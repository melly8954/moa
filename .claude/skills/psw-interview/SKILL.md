# psw-interview

요구사항의 뼈대를 모은다. 답은 인터뷰 기록으로 따로 남기지 않고 `docs/req/`의 제자리에 바로 적는다. 수용 기준·정책·권한 같은 상세는 `psw-req`가 채운다.

## 입력과 출력

| 입력 | 출력 |
|---|---|
| 프로젝트 주제 (사용자) | `docs/req/README.md` (개요, 범위, 제약, 코드표, 해당 없음) |
| 기존 REQ, `docs/open-question.md` (다시 묻는 경우) | `docs/req/actors.md` (역할 목록) |
| | `docs/req/functional/<domain>/README.md` (기능 목록) |
| | `docs/req/functional/<domain>/<feature>.md` (흐름 초안) |
| | 영역 파일 (`non-functional/` 등, 항목 초안) |
| | 미결 (`psw-change` 절차 A) |

## 규칙

- 질문 목록과 순서, 답을 적을 위치: `references/checklist.md`
- 템플릿: `psw-req`의 `references/*.md`. 파일이 없으면 그 템플릿으로 만든다
- 한 번에 3~5개씩 묻는다
  → 한꺼번에 많이 물으면 답이 얕아진다
- 질문마다 선택지와 추천안을 함께 제시한다
- 모르는 답은 추측하지 않는다. `psw-change` 절차 A로 `docs/open-question.md`에 등록하고 다음 질문으로 넘어간다
  - 항목의 `체크리스트:` 줄에 체크리스트 ID를 적는다
- 해당 없는 항목은 `req/README.md`의 해당 없음 표에 체크리스트 ID와 사유를 적는다
- 답을 반영한 자리에는 체크리스트 ID를 주석으로 남긴다 (예: `<!-- ck-dir-1 -->`)
  → `checklist-coverage.sh`가 이 ID로 누락을 찾는다
- 답은 뜻이 바뀌지 않게 옮긴다. 선택지 중에서 고른 값이나 추천안과 다르게 정한 값에는 결정 기록을 붙인다: `<값> 〔YYYY-MM-DD〕 <이유>` (harness-psw 8.1)
- 요구사항 ID는 `.claude/scripts/psw/next-id.sh <접두사>`로 발급한다 (예: `next-id.sh FR-ORD`, `next-id.sh CON`)
- 도메인·영역 코드는 `req/README.md` 코드표에만 정의한다
- 기능을 나눌 때 기능 크기 기준을 적용한다 (harness-psw 3.4)
  - 기능 1개 = 사용자가 독립적으로 시작하고 끝내는 행위 1개
  - 규칙·수치나 여러 기능이 함께 쓰는 것은 기능으로 만들지 않고 정책 후보로 적어 둔다 (`psw-req`가 `_policy.md`에 쓴다)
- 수용 기준, 정책 수치, 권한 매트릭스는 쓰지 않는다. `psw-req`가 쓴다
- `approved` 문서는 고치지 않는다. 다시 묻는 경우 답이 승인된 내용을 바꾸면 `psw-change` 절차 D로 보낸다

## 절차

### 1. 시작

- 새 프로젝트면 주제를 확인한다. 사용자가 주제를 말하지 않았으면 묻는다
- 다시 묻는 경우(누락 보완, 미결 해결)면 `checklist-coverage.sh` 결과나 해당 미결 항목부터 확인하고 3단계로 간다

### 2. 레퍼런스 조사

1. 주제와 비슷한 서비스·사례를 1~2개 고른다
   - 웹 검색을 쓸 수 있으면 출처를 확인한다. 확인하지 못한 내용은 확인하지 못했다고 밝힌다
   - 원문을 옮기지 않고 요약한다
2. 레퍼런스의 기능을 후보로 제시하고, 사용자가 채택·제외·보류를 고르게 한다
   - 채택: 해당 도메인 기능 목록에 넣는다
   - 제외: `req/README.md` 범위 밖에 사유와 함께 적는다
   - 보류: 미결로 등록한다
3. `req/README.md` 레퍼런스 표에 이름, 출처, 다르게 가져갈 점을 적는다

### 3. 인터뷰

1. 체크리스트 순서대로 묻는다: 방향성 → 행위자 → 기능 → 비기능·보안·연동·데이터 → 제약
   → 기능이 나와야 비기능의 적용 범위가 정해진다
2. 기능(ck-fun-2, ck-fun-3)은 도메인마다 반복해서 묻는다
   - 핵심 행위마다 기능 목록에 한 줄(ID, 한 줄 요구, 우선순위)을 넣고 FR 파일을 만든다
   - FR 파일에는 행위자, 주 흐름, 예외 흐름까지만 적는다
3. 묶음마다 답을 해당 파일에 바로 적는다

### 4. 마무리

1. `.claude/scripts/psw/checklist-coverage.sh`를 실행한다
2. 누락된 `[필수]` 항목이 있으면 이어서 묻는다
3. 결과를 보고한다
   - 모은 답의 요약 (영역별), 만든 파일
   - 등록한 미결
   - 다음 단계: `psw-req`로 REQ 상세를 채운다

## 커밋

- 최초 작성: `Refs:`에 새로 만든 도메인·영역 접두사 (예: `Refs: FR-ORD, NFR-PERF`)
- 메시지 예: `docs: 기획 인터뷰 반영 (방향성, 행위자)`

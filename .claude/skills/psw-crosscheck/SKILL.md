# psw-crosscheck

설계 문서끼리, 그리고 요구사항과 어긋난 곳을 찾는다. 이 스킬은 고치지 않고 찾기만 한다.
테이블·API는 문서가 아니라 코드가 정본이므로 여기서 보지 않는다. 코드와 요구사항의 정합은 구현 단계의 코드 검토가 본다.

## 검증 항목

| # | 항목 | 방식 |
|---|---|---|
| 1 | 승인된 FR 중 화면에서 참조되지 않는 것 (경고. 서버 전용 기능이면 무시) | 스크립트 |
| 2 | NFR·SEC·INT가 설계 문서에서 참조된다 | 스크립트 |
| 3 | IA 접근 역할이 `docs/req/actors.md`와 일치한다 | 검토자 |
| 4 | 목업의 `data-component` 값이 `components.md`에 있다 | 스크립트 |
| 5 | 목업마다 IA 화면 목록에 행이 있다 (IA 행에 목업이 없으면 경고) | 스크립트 |
| 6 | 화면의 refs가 비어 있지 않다 | 스크립트 |
| 7 | 참조한 ID가 정의돼 있다 | 스크립트 |

## 절차

### 1. 스크립트 항목

- `.claude/scripts/psw/crosscheck.sh [도메인 코드]`를 실행한다
  - 도메인 코드를 주면 항목 1, 5, 6, 7을 그 도메인으로 좁힌다. 나머지는 전역으로 본다
  - 스크립트 항목은 싸므로 매번 전체를 실행한다

### 2. 검토자 항목 (3)

- 검토자 에이전트(`reviewer`)가 설치돼 있으면 맡긴다. 없으면 메인 세션이 확인하고, 그 사실을 결과에 적는다
- 검토자에게 넘기는 것: 대상 도메인의 `ui/ia/<domain>.md`, `docs/req/actors.md`, 관련 FR 파일 경로
  - 설계 작성자의 설명은 넘기지 않는다
- 반복 실행이면 영향받은 문서만 다시 본다 (`psw-change` 절차 E의 영향 경로)
- 지적마다 근거 ID와 위치(파일, 제목)를 단다. 근거가 없으면 "제안"으로 분류한다

### 3. 결과 정리

| 결과 | 처리 |
|---|---|
| 설계 문제 | `psw-design`으로 `draft`에서 고친다 |
| 요구사항 문제 | `psw-change`로 기획 루프를 호출한다 |
| 근거가 빈 설계 요소 | 범위 밖 작업을 의심하고 사용자에게 확인한다 |
| 경고 (항목 1, 5) | 의도한 것이면 무시한다 (예: 서버 전용 기능, 아직 그리지 않은 시안) |

- 같은 불일치가 2회 이상 다시 나오면 요구사항 문제로 보고 사용자에게 보고한다
- 결과 보고: 항목별 오류·경고 수, 지적 목록, 처리 방향

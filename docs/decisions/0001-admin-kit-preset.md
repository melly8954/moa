# 관리자 백오피스는 키트 admin 프리셋 전체로 세운다

- 상태: 확정 (2026-11-07)
- 바꾸는 결정: 예전 기획의 "관리자 등급을 나누지 않는다" (예전 REQ 관리 정책, `archive/pre-reset` 이전 이력)

## 배경

관리자 백오피스의 기반(사용자, 메뉴, 권한)을 먼저 세워야 이후 관리 기능(신고, 제재, 게임 목록 등)을 얹을 수 있다.
psw-dev-kit springboot에는 이 기반을 묶은 admin 프리셋이 있다.

예전 기획은 운영자가 한 명이라 관리자 등급을 나누지 않기로 했다. admin 프리셋에는 업무 역할을 만드는 rbac 헬퍼가 들어 있다.

## 선택지

1. admin 프리셋 전체 (code, login-history, menu, rbac, user-admin)
2. rbac를 뺀 4개. 예전 결정대로 ADMIN 하나만 둔다
3. 프리셋 없이 필요한 헬퍼만 골라 쓴다

## 결정

1번. admin 프리셋 전체를 쓴다.

- rbac를 넣어 운영자가 늘어날 때 업무 역할(예: 신고 담당)로 권한을 나눌 수 있게 한다
- 키트 기본 동작대로 시스템 역할 ADMIN은 모든 권한을 갖는다
- 프리셋 밖의 헬퍼(redis, excel, mail 등)는 백오피스 기반에 넣지 않는다. 필요한 기능의 스펙에서 정한다
- 키트 버전 태그는 키트를 적용할 때 원칙 문서의 기술 제약에 적는다

## 결과

- 관리 메뉴 5개(사용자, 메뉴, 코드, 접속 이력, 역할)와 권한 키 5개가 키트에서 온다
- 이 기능들의 동작은 키트 문서와 수용 테스트가 기준이다. moa가 어떻게 쓰는지는 `specs/001-admin-foundation`에 적는다
- 프론트 관리자 화면은 프론트 키트(web-next)가 만드는 중이다. 키트를 적용할 때 태그가 나왔는지 확인한다

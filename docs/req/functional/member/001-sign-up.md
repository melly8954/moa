# FR-MEM-001 회원가입

<!-- refs: 이 기능에만 적용되는 NFR·SEC·INT·DAT ID. 전체 적용 항목은 적지 않는다 -->

## 행위자

비회원

## 선행조건

- 로그인하지 않은 상태다

## 주 흐름

<!-- ck-fun-3 -->

1. 비회원이 가입 수단(이메일, 구글, 카카오)을 고른다
2. 이메일이면 이메일과 비밀번호를 입력하고, 시스템이 보낸 인증 메일로 이메일을 인증한다
3. 구글·카카오면 해당 서비스에서 인증하고 돌아온다. 제공자가 이메일을 주지 않거나 인증되지 않은 이메일을 주면 2단계(이메일 가입 단계)로 이어 간다 〔2026-10-04〕 사용자 결정(인증되지 않은 이메일 추가)
4. 비회원이 생년월일을 입력하고 휴대폰 번호를 문자로 인증한다
5. 비회원이 닉네임을 입력하고 필수 약관·개인정보 수집에 동의한다
6. 시스템이 ACTIVE 회원을 만들고 로그인 상태로 홈으로 보낸다

## 예외 흐름

- E1. 이메일 가입인데 이미 가입된 이메일이면 → 이메일 인증 연결 규칙대로 처리한다. 기존 계정에 비밀번호가 없으면 인증 후 비밀번호를 추가하고 그 계정으로 로그인시킨다. 있으면 막고 로그인·비밀번호 찾기로 안내한다
- E2. 구글·카카오 가입인데 같은 이메일의 계정이 있으면 → 계정 합치기 규칙에 맞으면 기존 계정에 합치고 로그인시킨다. 맞지 않으면(인증되지 않은 이메일, ACTIVE가 아닌 계정, 같은 제공자의 다른 계정이 이미 연결된 계정 〔2026-10-04〕 사용자 결정) 가입을 막고 그 계정으로 로그인한 뒤 로그인 수단 관리에서 연결하라고 안내한다
- E3. 제공자가 이메일을 주지 않았거나 인증되지 않은 이메일을 줬고, 인증한 이메일이 기존 계정 이메일이면 → 이메일 인증 연결 규칙대로 기존 계정에 그 제공자를 연결하고 로그인시킨다. 기존 계정이 ACTIVE가 아니거나 같은 제공자의 다른 계정이 이미 연결돼 있으면 연결하지 않고 안내한다 〔2026-10-04〕 사용자 결정
- E1-1. 이메일 가입인데 비밀번호가 없는 기존 계정이 ACTIVE가 아니면 → 인증 후 연결하지 않고 상태별 안내(정지: 정지가 끝난 뒤 로그인, 탈퇴 유예: 고객 문의로 복구·정해진 기간 뒤 재가입)를 보인다 〔2026-10-04〕 사용자 결정
- E4. 이메일 인증 링크가 만료됐으면 → 인증 메일을 다시 받게 한다
- E5. 구글·카카오 인증에 실패하거나 취소하면 → 가입 화면으로 돌아간다
- E6. 가입 나이에 미달하면 → 가입을 막는다
- E7. 휴대폰 번호가 다른 계정에 이미 인증됐으면 → 휴대폰 번호 중복 안내 규칙대로 막고 안내한다. 탈퇴 유예 중 계정의 번호면 가입을 막고, 고객 문의로 복구할 수 있고 정해진 기간 뒤 다시 가입할 수 있다고 안내한다 〔2026-10-02〕 사용자 결정
- E8. 휴대폰 번호가 재가입 제한 중이면 → 가입을 막는다
- E9. 문자 인증 번호가 틀리거나 만료되면 → 다시 입력하거나 다시 받게 한다
- E10. 닉네임 규칙에 맞지 않거나 이미 쓰이면 → 다른 닉네임을 입력하게 한다
- E11. 필수 동의를 하지 않으면 → 가입을 진행하지 않는다
- E12. 가입 중에 취소하면 → 회원을 만들지 않는다

## 수용 기준

- AC-1 [MUST] API: 이메일, 비밀번호, 생년월일, 인증된 휴대폰 번호, 닉네임, 필수 동의가 모두 있으면 ACTIVE 회원이 생기고 로그인 세션이 발급된다
- AC-2 [MUST] API: 이메일 인증을 마치지 않은 이메일 가입 요청은 회원을 만들지 않는다
- AC-3 [MUST] API: 가입 나이에 미달하는 생년월일로 가입하면 거부된다
- AC-4 [MUST] API: 이미 다른 계정에 인증된 휴대폰 번호로 가입하면 거부된다
- AC-5 [MUST] API: 대소문자만 다른 기존 닉네임으로 가입하면 거부된다
- AC-6 [MUST] API: 제공자가 인증된 이메일로 알려 준 구글·카카오 계정의 이메일이 기존 계정과 같으면 새 회원을 만들지 않고 기존 계정으로 로그인된다
- AC-7 [MUST] API: 제공자가 인증되지 않은 이메일로 알려 준 경우에는 기존 계정에 합치지 않는다
- AC-8 [MUST] API: 비밀번호가 없는 기존 계정의 이메일로 이메일 가입을 하면, 이메일 인증 뒤 새 회원이 생기지 않고 기존 계정에 비밀번호가 추가되어 그 이메일·비밀번호로 로그인된다
- AC-9 [MUST] API: 비밀번호가 있는 기존 계정의 이메일로 이메일 가입을 하면 거부된다
- AC-10 [MUST] API: 카카오가 이메일을 주지 않으면 이메일 인증을 마치기 전에는 회원이 생기지 않고, 인증한 이메일이 기존 계정 이메일이면 그 계정에 카카오가 연결된다
- AC-11 [MUST] 화면: 휴대폰 번호가 활동 중인 기존 계정과 겹치면 가려진 기존 계정 이메일과 연결 방법 안내가 보인다. 정지된 계정이면 가려진 이메일과 정지가 끝난 뒤 로그인하라는 안내가 보인다 〔2026-10-02〕 사용자 결정. 탈퇴 유예 중 계정이면 이메일 없이 복구·재가입 안내가 보인다 〔2026-10-02〕 사용자 결정
- AC-12 [MUST] 화면: 가입 화면에 수집 항목(이메일, 생년월일, 휴대폰 번호)과 목적이 적힌 필수 동의가 있다
- AC-13 [MUST] API: 구글·카카오 계정을 기존 계정에 합치면 그 계정의 알림 목록에 로그인 수단 연결 알림이 생긴다 〔2026-10-04〕 사용자 결정
- AC-14 [MUST] API: 같은 이메일의 기존 계정이 ACTIVE가 아니거나 같은 제공자의 다른 계정이 이미 연결돼 있으면 합치지 않고 새 회원도 만들지 않는다 〔2026-10-04〕 사용자 결정
- AC-15 [MUST] API: 구글·카카오가 인증되지 않은 이메일을 주면 그 이메일로 회원이 생기지 않고, 이메일 인증을 마친 이메일이 계정 이메일이 된다 〔2026-10-04〕 사용자 결정
- AC-16 [MUST] API: 이메일 인증 연결의 대상인 비밀번호 없는 기존 계정이 ACTIVE가 아니면 연결하지 않고 새 회원도 만들지 않는다 〔2026-10-04〕 사용자 결정

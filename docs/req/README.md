## 개요

### 배경과 문제

<!-- ck-dir-1 -->
유명 게임들의 소셜 활동은 게임 밖의 다른 소셜 서비스를 거쳐서만 전달된다. 그래서 게임 전용 SNS는 크게 뒤처져 있다.
moa는 게임 커뮤니티, SNS, 메시지, 스트리밍을 하나로 묶는다.

- 커뮤니티·SNS: 인벤·디시 같은 게임 커뮤니티 성격을 가지되, 인스타그램처럼 피드 중심의 SNS로 쓴다
- 메시지: 1차는 카카오톡처럼 친구 관계를 기반으로 한 메신저다. 이후 디스코드처럼 음성·비디오 메신저로 확장한다
- 스트리밍: 트위치·SOOP 같은 방송 기능이다. 고도화 단계에서 추가한다
- AI: 친구 매칭 등 AI 기능을 섞을 수 있게 한다
- 게임: 처음에는 리그 오브 레전드, 오버워치, 배틀그라운드 3종을 다룬다. 이후 분류별로 나눠 여러 게임으로 넓힌다

## 범위

### 범위 안

<!-- ck-fun-1 -->

| 도메인 | 요약 |
|---|---|
| 회원 (MEM) | 가입, 로그인, 프로필, 플레이하는 게임과 게임 계정(직접 입력), 회원 검색 |
| 관계 (REL) | 팔로우, 팔로우 요청 승인(비공개 계정), 차단. 맞팔이면 친구 |
| 피드 (FEED) | 글·이미지·클립 게시, 게임별 피드, 좋아요, 댓글, 해시태그 검색 |
| 메신저 (MSG) | 친구끼리 1:1·그룹 텍스트 채팅 |
| 파티 (PTY) | 파티 모집 글, 게임·모드·티어 필터, 참여, 채팅방 연결 |
| 평판 (REP) | 같이 플레이한 사람 평가, 레벨 |
| 매칭 (MAT) | AI 친구·파티 추천. MVP 이후 |
| 알림 (NTF) | 서비스 내 알림 목록과 배지 |
| 관리 (ADM) | 신고 처리, 게시물 숨김, 회원 제재, 게임 목록 관리 |

<!-- ck-fun-4 --> 알림은 서비스 내 알림(목록, 배지)만 둔다. 웹 푸시와 활동 알림 이메일은 두지 않는다
<!-- ck-fun-5 --> 검색은 닉네임으로 회원 찾기, 해시태그로 게시물 찾기, 파티 모집 필터(게임·모드·티어)만 둔다. 본문 전체 검색은 두지 않는다

### 범위 밖

| 항목 | 사유 |
|---|---|
| 음성·비디오 통화 | 후속 단계. 1차 메신저는 텍스트다 |
| 라이브 스트리밍 | 후속 단계(고도화) |
| 리그 오브 레전드·오버워치·배틀그라운드 외 게임, 게임 분류 체계 | 후속 단계. 이번에는 3종만 다룬다 |
| 게임 관련 직업인 전용 기능 (인증 배지, 구인 등) | 후속 단계 |
| 게임사 API로 게임 계정·티어·전적 가져오기 | 후속 단계. MVP는 회원이 직접 입력한다 |
| 웹 푸시, 활동 알림 이메일 | 서비스 내 알림만 둔다 |
| 게시물 본문 전체 검색 | 회원·해시태그 검색만 둔다 |

### 첫 출시(MVP)

<!-- ck-dir-4 -->
<!-- 기능 ID는 도메인별 기능 목록을 만든 뒤 채운다 -->

- 게임별 피드: 글·이미지·클립 게시, 팔로우
- 친구 + 텍스트 메신저 (1:1, 그룹)
- 파티 모집
- 평판·레벨 〔2026-09-25〕 MVP 이후를 추천했으나 사용자가 MVP에 포함하기로 결정

관계 모델: 팔로우만 둔다. 서로 팔로우하면(맞팔) 친구로 보고, 친구끼리 메시지와 파티 초대가 열린다. 별도 친구 요청은 없다 〔2026-09-25〕 팔로우·친구를 둘 다 두는 안을 추천했으나 사용자가 인스타그램형으로 결정

AI 매칭은 범위 안이지만 MVP 이후에 구현한다.

# Contract: 공지 화면

API는 [notices-api.md](./notices-api.md)를 쓴다. 사용자 화면의 위치·모양은 FR-010을 따른다 (research R7, R11, R12).

## 관리자 (로그인, `NOTICE_MANAGE`)

| 경로 | 내용 |
|---|---|
| `/admin/notices` | 키트 목록 화면 모양. 머리("공지 관리", "공지 쓰기" 버튼), 검색(제목, 상태), 표(제목, 상태, 고정, 게시 시각, 고친 시각), 페이지. 행을 누르면 고치기 화면 |
| `/admin/notices/new` | 제목, 본문(`RichTextEditor`), 고정 여부. 버튼 "임시 저장", "게시" |
| `/admin/notices/[id]` | 같은 폼. 임시 저장 공지는 "저장"·"게시", 게시한 공지는 "저장"만. 고정 켜고 끄기, "지우기"(되묻기) |

- 사이드바: 서버 메뉴의 "공지 관리" (최상위 6번째, `001-admin-menus`)
- 권한이 없으면 키트 화면처럼 목록 자리에 권한 없음 안내 (`A005`)
- 저장하지 않고 떠나면 되묻는다. 본문 이미지 오류 문구는 키트 rich-text 동작

## 사용자 (로그인 없이)

사용자 셸(`(user)` 경로 묶음, `001-admin-menus` FR-005). 로그인하지 않았으면 계정 줄에 로그인 단추가 보인다.

| 경로 | 내용 |
|---|---|
| `/notices` | 공지 목록 표: 번호(게시 순번 `number`, 고정 공지는 고정 표시), 제목, 게시일. 제목을 누르면 상세. 비었으면 빈 결과 안내. 페이지 |
| `/notices/[id]` | 제목, 게시 날짜, 본문(`RichTextView`). 없는 공지면 "없는 공지예요" 안내와 목록 링크 |

- 로그인 상태면 `/notices`를 열 때 `PUT /api/v1/notices/seen`을 부르고 새 공지 상태를 다시 읽는다

## 새 공지 표시 (로그인 뒤 사용자 셸)

- 사용자 셸 메뉴(코드 메뉴 `menu.ts`)에 "공지"(`/notices`)를 보인다. 관리 셸에는 없다
- `GET /api/v1/notices/new`가 `hasNew`면 "공지" 메뉴 옆에 점을 보인다. 화면 낭독기에는 "새 공지"로 읽힌다. 사이드바를 접으면 아이콘 위에 점
- 첫 화면 안내문은 두지 않는다

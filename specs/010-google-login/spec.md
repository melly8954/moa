# Feature Specification: 구글 소셜 로그인 (google-login)

**Feature Branch**: `feat/010-google-login`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "구글 소셜 로그인"

**출처**: moa. 잠정으로 키트 oauth 헬퍼를 기본 방향으로 한다 [NEEDS CLARIFICATION: 키트에 oauth 헬퍼가 있는가, 연결·해제(FR-006)까지 지원하는가? 팀 확인 필요 (담당: 키트 담당/팀 리더). 팀이 다른 방식을 제안하면 그때 바꾼다]. 이 스펙은 구현 방식과 상관없이 동작(FR·AC)만 적고, 헬퍼에 맞춘 세부는 plan에서 정한다

**배경** (기존 스펙에서 따름):

- 이 기능이 moa의 첫 회원 가입 경로다. 지금까지 회원은 시드 계정뿐이었다(`008-party` 가정). `002-admin-users` 가정의 "회원 가입·로그인 방식과 회원 정보 모델은 사용자 쪽 기능이 정한다"의 그 기능이 이 스펙이다
- 구글로 가입한 회원은 비밀번호 없는 계정이다. 비밀번호 없는 계정의 기존 규칙(`002-admin-users` FR-007, 사용자 관리에서 비밀번호 초기화를 막음)을 그대로 따른다
- 구글 로그인의 성공과 실패도 접속 이력에 남긴다(`005-admin-login-history` FR-001)
- 로그인한 뒤 첫 화면은 아이디·비밀번호 로그인과 같은 규칙이다(`001-admin-menus` FR-006)
- 정해지지 않은 것(회원 정보 모델, 키트 헬퍼, 관리자·운영자 허용 등)은 추측하지 않고 [NEEDS CLARIFICATION]으로 둔다 (원칙 I)

## Clarifications

### Session 2026-11-16

- Q: 구글 계정과 moa 회원을 어떤 구조로 이어 두는가? → A: 잠정 B(회원 계정은 키트 `users` 그대로, 외부 계정 연결을 따로 두어 한 회원이 여러 소셜 계정을 가질 수 있음). 팀 확인 필요 (담당: 팀 회의 — 002 사용자 관리 목록에 영향). 키트 oauth 헬퍼가 기본 방향이므로 plan에서 그 구조와 맞는지 다시 본다
- Q: 아이디·비밀번호 계정이 이미 있는 사람이 구글 로그인을 하면 그 계정과 잇는가? → A: C. 이메일로 자동 연결하지 않는다. 로그인한 회원이 계정 설정 화면에서 자기 계정에 구글 계정을 직접 연결·해제한다. 로그인 수단이 구글 하나뿐인 회원(비밀번호 없음)은 해제할 수 없고, 다른 회원에 이미 연결된 구글 계정은 연결을 막고 안내한다. 관리자·운영자 계정의 연결은 FR-007과 함께 팀 확인 필요 (처음 답 A를 C로 정정)
- Q: 연결 조건에 "구글이 인증한 이메일일 때만"을 넣는가? → A: 넣지 않는다. 연결은 로그인한 본인이 구글 인증을 거쳐 직접 한다
- Q: 이번 범위에 앱 클라이언트가 들어가는가? → A: 아니다. 이번 범위는 웹 로그인만, 앱 클라이언트는 나중이다
- Q: 회원의 표시 이름은 어디서 가져오는가? → A: B. 처음 구글 로그인 때 닉네임 입력 화면을 거치고, 그 닉네임이 표시 이름이다
- Q: 구글 로그인을 키트 oauth 헬퍼로 만드는가, moa가 직접 만드는가? → A: 잠정 A(키트 oauth 헬퍼가 기본 방향). 헬퍼 유무와 연결·해제(FR-006) 지원은 팀 확인 필요 (담당: 키트 담당/팀 리더). 팀이 다른 방식을 제안하면 바꾼다. 스펙은 동작(FR·AC)만 적고 헬퍼에 맞춘 세부는 plan에서 정한다
- Q: 처음 구글 로그인을 한 사람이 닉네임을 넣지 않고 떠나면 어떻게 하는가? → A: A. 닉네임을 넣기 전에는 회원을 만들지 않는다. 떠나면 가입이 안 된 것이고 다음 구글 로그인 때 닉네임 입력부터 다시 한다

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 처음 온 사람이 구글 계정으로 가입한다 (Priority: P1)

moa에 계정이 없는 사람이 로그인 화면에서 "구글로 계속하기"를 눌러 구글 계정을 고르고 허락한다. moa는 그 구글 계정으로 회원을 만들고 로그인시킨다.

**Why this priority**: 회원 가입 경로가 없으면 시드 계정 밖의 사람이 회원 활동(파티 등)을 할 수 없다. 이 기능의 목적 자체다.

**Independent Test**: moa에 가입한 적 없는 구글 계정으로 로그인 화면에서 구글 로그인을 끝까지 하고, 회원이 생겨 로그인 상태로 첫 화면에 들어가는지 본다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** moa에 가입한 적 없는 구글 계정이다, **When** 로그인 화면에서 구글 로그인을 하고 구글에서 허락한다, **Then** 새 회원이 만들어지고 로그인 상태로 사용자 셸의 첫 화면(`/`)에 들어간다
2. **US1-AC2** **Given** US1-AC1로 가입했다, **When** 관리자가 사용자 관리 목록을 연다, **Then** 그 회원이 시스템 역할 `USER`인 비밀번호 없는 계정으로 보이고, 드로어에서 비밀번호 초기화를 할 수 없다
3. **US1-AC3** **Given** 처음 구글 로그인을 한다, **When** 가입이 끝난다, **Then** 닉네임 입력 화면이 보이고, 닉네임을 넣어 마치면 첫 화면(또는 돌아갈 주소)으로 가며 그 닉네임이 표시 이름으로 보인다 (FR-005) [NEEDS CLARIFICATION: 닉네임 말고 가입 때 함께 받는 것(약관·개인정보 동의 등)이 있는가?]
4. **US1-AC4** **Given** 로그인이 필요한 화면 주소로 들어와 로그인 화면으로 넘어왔다, **When** 구글로 처음 가입한다, **Then** 첫 화면이 아니라 처음 들어오려던 주소로 돌아간다 (`001-admin-menus` FR-006)
5. **US1-AC5** **Given** 처음 구글 로그인을 해 닉네임 입력 화면이 보인다, **When** 닉네임을 넣지 않고 떠난 뒤 다시 구글 로그인을 한다, **Then** 그 사이 회원은 만들어지지 않았고 닉네임 입력 화면부터 다시 시작한다

---

### User Story 2 - 구글 회원이 다시 로그인한다 (Priority: P1)

구글로 가입한 회원이 다음에 로그인 화면에서 구글 로그인을 하면 새 회원이 생기지 않고 같은 회원으로 로그인한다.

**Why this priority**: 가입만 되고 다시 들어올 수 없으면 쓸 수 없다. US1과 함께 최소 기능이다.

**Independent Test**: US1로 가입한 구글 계정으로 로그아웃 뒤 다시 구글 로그인을 하고, 같은 회원(같은 파티·알림 등)으로 들어가는지와 회원 수가 늘지 않는지 본다.

**Acceptance Scenarios**:

1. **US2-AC1** **Given** 구글로 가입한 회원이 로그아웃했다, **When** 같은 구글 계정으로 구글 로그인을 한다, **Then** 새 회원이 생기지 않고 같은 회원으로 로그인해 사용자 셸의 첫 화면에 들어간다
2. **US2-AC2** **Given** 관리자가 구글 회원을 잠갔다, **When** 그 회원이 구글 로그인을 한다, **Then** 로그인되지 않고 잠긴 계정이라는 안내가 보인다
3. **US2-AC3** **Given** 구글 회원이 로그인했다, **When** 계정 메뉴를 연다, **Then** 비밀번호 변경은 할 수 없다 [NEEDS CLARIFICATION: 비밀번호 없는 계정에서 계정 메뉴의 "비밀번호 변경"(`001-admin-menus` FR-005)을 숨기는가, 누르면 안내하는가?]

### User Story 3 - 구글 로그인이 안 될 때 안내를 받는다 (Priority: P2)

구글 화면에서 취소하거나, 구글 확인이 실패하거나, 구글 로그인을 쓸 수 없는 상태면 로그인 화면에 머물며 무엇이 잘못됐는지 안내를 받는다.

**Why this priority**: 실패해도 로그인 화면으로 돌아와 다시 할 수 있으면 핵심 흐름은 쓸 수 있다. 다만 원인 모를 빈 화면은 막아야 한다.

**Independent Test**: 구글 화면에서 취소, 확인할 수 없는 구글 응답, 구글 로그인 설정이 없는 환경 각각에서 로그인 화면의 안내와 접속 이력을 본다.

**Acceptance Scenarios**:

1. **US3-AC1** **Given** 로그인 화면이다, **When** 구글 화면에서 취소하거나 창을 닫는다, **Then** 로그인 화면에 그대로 있고 회원이 만들어지지 않는다
2. **US3-AC2** **Given** 구글 로그인을 했다, **When** moa가 구글 응답을 확인하지 못한다(위조, 만료, 다른 서비스용 응답), **Then** 로그인되지 않고 구글 로그인에 실패했다는 안내가 보이며, 접속 이력에 실패로 남는다
3. **US3-AC3** **Given** 구글 로그인 설정이 없는 환경이다, **When** 로그인 화면을 연다, **Then** [NEEDS CLARIFICATION: 구글 로그인 단추를 숨기는가, 보이되 누르면 지금 쓸 수 없다는 안내를 하는가?] 아이디·비밀번호 로그인은 그대로 쓸 수 있다

---

### User Story 4 - 관리자가 구글 로그인 기록을 본다 (Priority: P3)

관리자는 접속 이력에서 구글 로그인의 성공과 실패를 아이디·비밀번호 로그인과 함께 본다.

**Why this priority**: 접속 이력은 이미 있는 기능(005)이라 구글 로그인이 빠지지 않게만 하면 된다.

**Independent Test**: 구글 로그인 성공 한 번, 실패 한 번 뒤 관리자로 접속 이력을 연다.

**Acceptance Scenarios**:

1. **US4-AC1** **Given** 구글 로그인 성공과 실패가 한 번씩 있었다, **When** 관리자가 접속 이력을 연다, **Then** 두 건이 성공·실패로 보인다 [NEEDS CLARIFICATION: 구글 로그인 건을 접속 이력에서 무엇으로 보이는가? (회원 식별 칸에 무엇을 적는지, 로그인 방식(구글/아이디)을 구분해 보이는지). 회원 정보 모델(FR-004)이 정해져야 정할 수 있다]

---

### User Story 5 - 내 계정에 구글 계정을 연결하고 해제한다 (Priority: P2)

아이디·비밀번호 계정으로 로그인한 회원이 계정 설정 화면에서 구글 계정을 연결한다. 그 뒤로는 구글 로그인으로도 같은 계정에 들어간다. 필요 없어지면 연결을 해제한다.

**Why this priority**: 이미 계정이 있는 사람이 구글로 들어오면서 회원이 둘로 나뉘지 않게 한다. 새 가입(US1)과 다시 로그인(US2)만으로도 기능은 쓸 수 있어 P2다.

**Independent Test**: 아이디·비밀번호 계정으로 로그인해 구글 계정을 연결하고, 로그아웃 뒤 구글 로그인으로 같은 계정에 들어가는지 본다. 이어서 연결을 해제하고, 구글로 가입한 회원은 해제가 막히는지 본다.

**Acceptance Scenarios**:

1. **US5-AC1** **Given** 아이디·비밀번호 계정으로 로그인했고 연결된 구글 계정이 없다, **When** 계정 설정 화면에서 구글 계정을 연결한다, **Then** 계정 설정 화면에 구글이 연결됨으로 보인다
2. **US5-AC2** **Given** US5-AC1로 구글 계정을 연결했다, **When** 로그아웃 뒤 로그인 화면에서 그 구글 계정으로 구글 로그인을 한다, **Then** 새 회원이 생기지 않고 연결한 그 계정으로 로그인한다
3. **US5-AC3** **Given** 그 구글 계정이 이미 다른 회원에 연결되어 있다(구글로 가입한 회원 포함), **When** 계정 설정 화면에서 그 구글 계정을 연결하려 한다, **Then** 연결되지 않고 이미 다른 계정에 연결된 구글 계정이라는 안내가 보인다
4. **US5-AC4** **Given** 기존 계정과 이메일이 같은 구글 계정이다, **When** 연결하지 않은 채 로그인 화면에서 구글 로그인을 한다, **Then** 기존 계정에 자동으로 잇지 않고 따로 된 새 회원으로 가입한다
5. **US5-AC5** **Given** 비밀번호가 있는 계정에 구글 계정이 연결되어 있다, **When** 계정 설정 화면에서 연결을 해제한다, **Then** 구글이 연결되지 않음으로 보이고, 그 구글 계정으로 로그인 화면에서 구글 로그인을 하면 이 계정이 아니라 따로 된 새 회원이 된다
6. **US5-AC6** **Given** 구글로 가입해 비밀번호가 없는 회원이다, **When** 계정 설정 화면에서 구글 연결을 해제하려 한다, **Then** 해제되지 않고 유일한 로그인 수단이라 해제할 수 없다는 안내가 보인다

### Edge Cases

- 구글 계정에서 이름이나 이메일을 바꾼 뒤 다시 로그인할 때: 같은 구글 계정이면 같은 회원으로 로그인하고, 표시 이름(닉네임)은 바뀌지 않는다 (FR-005) [NEEDS CLARIFICATION: moa에 저장한 구글 이메일·이름이 있다면 따라 바꾸는가, 가입 때 값을 그대로 두는가? 회원 정보 모델(FR-004)과 함께 정한다]
- 같은 사람이 moa에 아이디·비밀번호 계정을 이미 가지고 있을 때 (같은 이메일 등): 자동으로 잇지 않는다. 기존 계정에 연결하지 않고 로그인 화면에서 구글 로그인을 하면 따로 된 새 회원이 된다. 이렇게 이미 회원이 된 구글 계정은 다른 계정에 연결할 수 없다 (FR-006)
- 구글 회원이 아이디·비밀번호 로그인 폼으로 로그인하려 할 때: 비밀번호가 없으므로 로그인되지 않는다 (비밀번호 없는 계정 규칙)
- 관리자가 구글 회원을 사용자 관리에서 삭제한 뒤 같은 구글 계정으로 다시 로그인할 때 [NEEDS CLARIFICATION: 새 회원으로 다시 가입되는가, 막는가? 탈퇴 상태·유예 기간(`specs/README.md` 맞춰야 할 경계)과 함께 정한다]
- 관리자·운영자 계정이 구글 로그인을 쓰려 할 때 [NEEDS CLARIFICATION: FR-007]
- 두 창에서 같은 구글 계정으로 동시에 처음 가입할 때: 회원은 하나만 만들어진다
- 처음 구글 로그인 뒤 닉네임 입력 화면에서 떠날 때: 회원이 만들어지지 않는다. 다음 구글 로그인 때 닉네임 입력 화면부터 다시 시작한다 (FR-005)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 로그인 화면에 구글 로그인 단추를 두어야 한다(MUST). 지금의 아이디·비밀번호 로그인 폼은 그대로 둔다. 관리자·운영자는 키트 기본 계정(아이디·비밀번호)으로 로그인한다(`002-admin-users` 가정)
- **FR-002**: moa에 연결된 회원이 없는 구글 계정으로 구글 로그인을 하면 회원을 새로 만들고 로그인시켜야 한다(MUST). 새 회원의 시스템 역할은 `USER`다. 같은 구글 계정으로는 회원이 하나만 생긴다
- **FR-003**: 이미 연결된 구글 계정으로 구글 로그인을 하면 그 회원으로 로그인시켜야 한다(MUST). 잠긴 회원은 아이디·비밀번호 로그인과 똑같이 막는다
- **FR-004**: 구글 회원의 정보 모델 [NEEDS CLARIFICATION: 회원 정보 모델 — (a) 구글 계정을 moa 회원과 어떻게 이어 두는가: 잠정으로 회원 계정(키트 `users`)은 그대로 두고 외부 계정 연결을 따로 두어 한 회원이 여러 소셜 계정을 가질 수 있게 한다. 팀 확인 필요 (담당: 팀 회의 — 002 사용자 관리 목록에 영향). 키트 oauth 헬퍼가 기본 방향이므로(출처) plan에서 헬퍼 구조와 맞는지 다시 본다, (b) 구글 이메일을 저장하는가, 저장하면 로그인 아이디로도 쓰는가, (c) 키트 `users`의 아이디·이름 칸에 무엇을 넣는가. `specs/README.md` "회원 정보 모델" 경계와 `002-admin-users` FR-004(사용자 관리 목록 항목)가 이 결정을 기다린다]
- **FR-005**: 구글로 처음 가입하는 회원은 닉네임 입력 화면을 거쳐야 한다(MUST). 그 닉네임이 회원의 표시 이름이다. 구글 계정 이름은 표시 이름으로 쓰지 않는다
  - 닉네임 입력 화면은 메뉴로 여는 화면이 아니므로 프로그램으로 등록하지 않는다 (`001-admin-menus` FR-008, FR-009)
  - 닉네임 규칙 [NEEDS CLARIFICATION: 닉네임 중복을 허용하는가? 길이·쓸 수 있는 글자는? 가입 뒤 바꿀 수 있는가?]
  - 닉네임을 넣어야 가입이 끝난다(MUST). 닉네임을 넣기 전에는 회원을 만들지 않는다. 닉네임 입력 화면에서 떠나면 가입이 안 된 것이고, 다음 구글 로그인 때 닉네임 입력 화면부터 다시 시작한다
  - 기존 회원의 표시 이름 [NEEDS CLARIFICATION: 닉네임이 없는 기존 아이디·비밀번호 회원(시드, 관리자·운영자 등)의 표시 이름은 무엇인가?]
- **FR-006**: 로그인한 회원은 계정 설정 화면에서 자기 계정에 구글 계정을 직접 연결하고 해제할 수 있어야 한다(MUST). 연결한 뒤에는 그 구글 계정으로 구글 로그인을 하면 그 회원으로 로그인한다
  - 구글 로그인은 이메일이 같다는 이유로 기존 계정과 자동으로 잇지 않는다(MUST). 연결되지 않은 구글 계정으로 로그인 화면에서 구글 로그인을 하면 따로 된 새 회원이 된다 (FR-002)
  - 다른 회원에 이미 연결된 구글 계정은 연결을 막고 안내한다(MUST)
  - 로그인 수단이 구글 하나뿐인 회원(비밀번호 없음)은 해제할 수 없다(MUST)
  - 연결 이메일 인증 조건은 두지 않는다. 연결은 로그인한 본인이 구글 인증을 거쳐 직접 한다
  - 연결·해제는 기존 계정 설정 화면 안에 둔다. 새 메뉴가 아니므로 프로그램으로 등록하지 않는다 (`001-admin-menus` FR-008)
  - 관리자·운영자 계정에 구글을 연결할 수 있는지는 FR-007에서 함께 정한다
- **FR-007**: 관리자·운영자 계정의 구글 로그인 [NEEDS CLARIFICATION: 관리자·운영자 계정이 구글 로그인을 쓸 수 있는가? `specs/README.md` "관리자·운영자 계정의 회원 활동 금지" 경계와 함께 정한다. 구글로 가입한 회원에게 관리자가 시스템 역할 `ADMIN`이나 업무 역할을 줄 수 있는지, 관리자·운영자 계정에 구글 계정을 연결할 수 있는지(FR-006)도 여기서 정한다. 팀 확인 필요 (담당: 팀 회의)]
- **FR-008**: 구글 로그인의 성공과 실패를 접속 이력으로 남겨야 한다(MUST). 보관 기간과 동작은 `005-admin-login-history`(FR-001·FR-002)를 따른다. 접속 이력에서 어떻게 보이는지는 US4-AC1의 질문으로 정한다
- **FR-009**: 구글 로그인 뒤 가는 화면은 `001-admin-menus` FR-006을 그대로 따른다(MUST). 처음 가입이면 닉네임 입력 화면을 거친 뒤 이 규칙대로 간다. 이 기능이 만드는 새 화면(닉네임 입력, 계정 설정 안의 구글 연결)은 메뉴로 열지 않으므로 프로그램이 아니다 (`001-admin-menus` FR-008)
- **FR-010**: 구글 회원은 비밀번호 없는 계정이어야 한다(MUST). 비밀번호 없는 계정에는 아이디·비밀번호 로그인과 비밀번호 초기화를 할 수 없다(`002-admin-users` FR-007)
- **FR-011**: 구글 로그인이 실패하면(취소, 확인 실패, 설정 없음) 로그인되지 않고 회원도 만들어지지 않아야 한다(MUST). 취소가 아닌 실패는 로그인 화면에 원인을 알 수 있는 안내를 보인다
- **FR-012**: 구글 로그인으로 들어온 회원의 로그인 유지·로그아웃은 아이디·비밀번호 로그인과 같아야 한다(MUST). 구글 로그인만을 위한 따로 된 로그인 유지 규칙은 두지 않는다

### Key Entities *(include if feature involves data)*

- **회원**: moa의 계정. 키트 `users`를 쓴다. 구글 회원은 비밀번호가 없다. 어떤 정보를 갖는지는 FR-004·FR-005
- **외부 계정 연결** (잠정, FR-004): 회원과 소셜 계정(이번에는 구글)을 잇는 정보. 회원 계정과 따로 두며 한 회원이 여러 개를 가질 수 있다. 제공자와 그 제공자가 주는 바뀌지 않는 계정 식별자로 같은 사람을 알아보고, 같은 제공자·식별자는 한 회원에만 이어진다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: moa에 처음 온 사람이 로그인 화면에서 구글 로그인을 시작해 로그인 상태로 첫 화면에 들어가기까지 1분 안에 마친다 (닉네임 입력 포함)
- **SC-002**: 이미 가입한 구글 회원은 로그인 화면에서 단추 한 번과 구글 계정 고르기만으로 다시 로그인한다
- **SC-003**: 같은 구글 계정으로 몇 번 로그인해도 회원은 하나다
- **SC-004**: 구글 로그인 시도(성공·실패)는 빠짐없이 접속 이력에 보인다
- **SC-005**: 수용 시나리오(US1~US5) 전부가 자동 테스트로 확인된다 (원칙 II)

## Assumptions

- 구글 로그인은 사용자 쪽 회원을 위한 것이다. 관리자·운영자의 로그인 방식(키트 기본 계정)은 바꾸지 않는다. 관리자·운영자가 구글 로그인을 함께 쓸 수 있는지는 FR-007로 묻는다
- 로그인 화면은 지금의 `/sign-in` 화면 하나다. 구글로 처음 가입할 때만 닉네임 입력 화면이 더해진다 (FR-005)
- 이번 범위는 웹 로그인만이다. 앱 클라이언트의 구글 로그인은 나중에 정한다
- 구글 말고 다른 소셜 로그인(카카오, 네이버 등)은 이 스펙의 범위가 아니다. 다만 FR-004의 답에 따라 나중에 더하기 쉬운지가 달라진다
- 회원 탈퇴는 이 스펙의 범위가 아니다(`specs/README.md` 탈퇴 상태·유예 기간 경계)
- 구글 로그인에 쓰는 설정 값(클라이언트 ID 등)은 환경마다 따로 주고 레포에 넣지 않는다 (원칙 VI)
- 나중에 고칠 곳: 이번 단계에서는 다른 스펙을 고치지 않는다. [NEEDS CLARIFICATION]이 풀리면 아래를 함께 고친다
  - `002-admin-users` FR-004: 사용자 관리 목록에 보일 회원 항목 (FR-004의 답)
  - `002-admin-users` 가정 "회원 가입·로그인 방식과 회원 정보 모델은 사용자 쪽 기능이 정한다": 이 스펙(010)을 가리키게 고친다
  - `008-party` 가정 "회원 가입은 아직 없으므로 시드 계정으로 시험한다", "닉네임은 회원 가입·프로필에서 정한다"와 FR-027의 표시 이름: 표시 이름을 닉네임으로 바꾼다 (FR-005). 팀 공유 필요 (담당: 008-party 담당)
  - `001-admin-menus` FR-008 프로그램 표: 고칠 것 없음. 이 기능의 새 화면은 프로그램이 아니다 (FR-009)
  - `005-admin-login-history`: 접속 이력에 로그인 방식을 보이기로 하면 (US4-AC1의 답)
  - `specs/README.md` 맞춰야 할 경계: "회원 정보 모델" 줄(FR-004·FR-005가 정해지면 지움), "관리자·운영자 계정의 회원 활동 금지" 줄(FR-007), "추가로 쓸 키트 헬퍼" 줄(헬퍼 유무가 팀 확인되면 oauth를 더함. 표의 출처 칸도 함께)

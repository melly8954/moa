# 화면 계약: 기본 회원가입·로그인 (019)

모두 `(public)` 그룹이다. 로그인한 사람이 열면 로그인 뒤 첫 화면(`001-admin-menus` FR-006)으로 보낸다 (FR-011). 메뉴로 열지 않아 프로그램이 아니다 (`001-admin-menus` FR-008).
문구는 `messages/ko.json`의 새 묶음 `emailAuth`에 둔다.

| 경로 | 내용 | AC |
|---|---|---|
| `/sign-in` (기존, [공용]) | 아이디·비밀번호 폼 아래에 "회원가입"(→ `/sign-up`)과 "아이디·비밀번호 찾기"(→ `/sign-in/find`) 링크. `A501`이면 폼 위에 "로그인을 5번 실패해 {시각}까지 로그인할 수 없어요. 비밀번호를 잊었다면 찾기를 이용해 주세요" | US1-AC1, US4-AC2·AC3 |
| `/sign-up` (새) | 1단계 이메일 인증. 이메일 칸 → "코드 받기" → 코드 6칸 입력, 남은 시간(10:00부터), "다시 받기"(60초 동안 꺼짐, 남은 초 표시), 늘 보이는 "메일이 안 보이면 스팸함을 확인해 주세요". `B501`(남은 횟수)·`B502`(다시 받기 단추)·`B503`·`B504`·`B505` 안내. 맞으면 `/sign-up/account`로 간다. `B506`·`B507`이면 안내와 "아이디·비밀번호 찾기"·로그인 길 | US1-AC2·AC3, US2, US5-AC5 |
| `/sign-up/account` (새) | 2단계 계정 정보. 인증한 이메일(읽기만), 아이디(규칙 안내), 비밀번호·비밀번호 확인(규칙 안내), 닉네임(010 닉네임 칸과 같은 부품), 약관 동의(`012-terms-privacy` FR-005 부품). 칸 오류는 칸 아래. `A502`면 "인증 시간이 지났어요. 이메일 인증부터 다시 해 주세요"와 함께 `/sign-up`으로 | US1-AC3~AC10 |
| `/sign-in/find` (새) | 1단계 이메일 → 코드(가입 1단계와 같은 부품. 안내는 "가입된 이메일이면 코드를 보냈어요"), 늘 보이는 "소셜 계정으로 가입했다면 그 계정으로 로그인해 주세요". 2단계 "아이디는 {loginId}예요" + 새 비밀번호·확인. 저장하면 `/sign-in?reset=done`("비밀번호를 바꿨어요. 새 비밀번호로 로그인해 주세요"). `A503`이면 처음부터 | US3 |
| 메일 꺼짐 | `availability.emailSignupEnabled = false`면 `/sign-up`·`/sign-in/find`에 "지금은 이메일 가입을 쓸 수 없어요"만 보이고, 로그인 화면의 두 링크는 그대로 둔다 | FR-018 |

- 상태: 보내는 중·확인 중에는 단추를 끄고, 서버 오류는 폼 위에 "잠시 뒤 다시 해 주세요"
- 이 화면들의 주소에는 이메일·코드를 넣지 않는다 (주소 기록에 남지 않게)

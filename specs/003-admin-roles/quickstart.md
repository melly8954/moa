# Quickstart: 운영자 역할 (admin-roles)

기대 결과의 기준은 [contracts/admin-roles.md](./contracts/admin-roles.md)다.

## 자동 검증

Docker가 떠 있어야 한다. `backend/`에서 실행한다 (Windows는 `.\gradlew.bat`).

```bash
./gradlew dbTest --tests "*AdminRolesAcceptanceTest" --tests "*AdminMenusAcceptanceTest"
```

기대: 003의 `US1-AC1`~`US4-AC3`과 001 AC가 통과한다.

## 화면 확인

2026-11-21에 두 칸 화면과 최고 관리자 역할로 바꿨다(FR-005·FR-010·FR-011). 운영자는 계정 종류 "관리자"인 계정이다.

1. `backend/`에서 `./gradlew bootRun`, `frontend/`에서 `npm run dev`
2. 시험 계정 `admin`으로 사이드바 "설정 > 권한 관리"를 연다: 머리 제목이 "권한 관리"이고, 왼쪽에 검색 칸·일괄 줄·역할 목록(체크박스·이름·구성원 수), 오른쪽에 역할을 고르라는 안내가 있다. 탭과 행 단추가 없다. 목록 맨 위에 자물쇠가 붙은 "최고 관리자"가 있고 체크 칸이 꺼져 있다
3. "최고 관리자"를 누른다: 오른쪽 칸에 쓸 메뉴가 모두 체크된 채 꺼져 있고, 이름·설명은 바꿀 수 없으며 저장 단추가 없다. 구성원에 `admin`이 있다
4. "역할 추가"로 "보안 담당"을 만든다: 오른쪽 칸에 쓸 메뉴 트리(운영·설정)와 "저장하면 구성원을 더할 수 있어요."가 나란히 보인다. "접속 이력"만 체크해 저장하면 같은 칸에서 구성원을 더할 수 있다
5. 사용자 관리에서 계정 종류 "관리자"로 계정 `op1`을 만든다. 권한 관리로 돌아와 "보안 담당"의 구성원에서 `op1`을 검색해 체크하고 "더하기": 검색하지 않으면 구성원만 보이고, 검색하면 구성원 여부가 보인다. `admin` 행은 "모든 권한"이고 체크할 수 없다. 회원 `user`는 검색에 나오지 않는다
6. `op1`로 로그인한다: 관리 메뉴는 "운영" 아래 접속 이력만 보이고 목록이 열린다. `/admin/users`로 직접 들어가면 목록 자리에 "이 화면을 볼 권한이 없어요."가 보인다
7. `admin`으로 목록에서 "보안 담당"을 체크해 삭제하면 사용자 수를 알리고 되묻는다. 지우면 `op1`은 다음 요청부터 접속 이력도 쓰지 못한다
8. 창을 1024px보다 좁힌다: 목록만 보이고, 역할을 누르면 드로어가 열린다

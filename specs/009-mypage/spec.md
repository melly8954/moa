# Feature Specification: 마이페이지 (mypage)

**Feature Branch**: `feat/009-mypage`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "마이페이지: 로그인한 회원이 자기 프로필을 보고 고친다. 닉네임, 자기소개, 나이·성별(공개 선택), 디스코드 태그(공개 범위 선택), 기본 아바타, 게임 정보 최대 3개(게임·티어·포지션 공통코드, 게임 아이디와 전적 사이트 링크), 주로 플레이하는 시간대. 로그인 방식·소셜 연결은 010의 계정 설정 화면. 계정 메뉴에 loginId 대신 닉네임."

**출처**: moa가 만드는 기능.

**배경** (기존 스펙에서 따름):

- 회원의 표시 이름은 닉네임이다. 소셜 회원은 가입 때 닉네임을 정한다(`010-social-login` FR-005, PR #54 병합 전). 다른 기능은 표시 이름을 보이고 로그인 아이디는 보이지 않는다(`008-party` FR-027)
- 화면은 관리 셸과 사용자 셸로 나뉘고, 계정 화면(알림, 설정, 비밀번호 변경)은 사용자에 맞는 셸 안에서 열린다. 메뉴로 열지 않는 계정 화면은 프로그램으로 등록하지 않는다(`001-admin-menus` FR-005, FR-008)
- 게임·티어·포지션은 파티와 같은 공통코드를 쓴다: 게임 그룹 `GAME`, 게임마다 `<게임 코드>_TIER`, `<게임 코드>_POSITION` (`008-party` FR-002, FR-022)
- 로그인 방식(비밀번호)과 소셜 계정 연결·해제는 `010-social-login`의 계정 설정 화면이 맡는다(FR-006). 마이페이지는 프로필만 다룬다
- 정해지지 않은 것은 추측하지 않고 [NEEDS CLARIFICATION]으로 둔다 (원칙 I)

**배경** (2026-11-17 결정):

- 프로필 사진은 moa가 제공하는 기본 아바타 중에서만 고른다. 직접 올리기는 선정적·폭력적 이미지 검열 문제로 보류한다
- 게임 정보는 회원이 적는 값이다. 게임 API로 계정·랭크를 확인하는 일은 나중 스펙("게임 계정 확인")에서 다룬다
- 회원 탈퇴(30일 유예·복구·완전 삭제)는 별도 스펙이다. 활동 기록(내 파티·글 등)은 이번 범위가 아니다

## Clarifications

### Session 2026-11-17

- Q: 닉네임 규칙(중복, 길이, 글자)은? → A: 잠정안 — 중복 불가(대소문자 무시), 2~12자, 한글·영문·숫자·`_`만, 예약어(admin, 운영자, moa 등) 금지. `010-social-login` FR-005의 같은 질문과 같은 답이다. 잠정, 팀 확인 필요 (담당: 팀 회의) (FR-003)
- Q: 닉네임 변경 제한 기간은? → A: 잠정안 — 가입 뒤 첫 변경은 바로 할 수 있고, 그 뒤로는 바꿀 때마다 30일 동안 다시 바꿀 수 없다. `010-social-login` FR-005와 같은 답이다. 잠정, 팀 확인 필요 (담당: 팀 회의) (FR-004)
- Q: 나이는 어떻게 받는가? → A: 출생 연도를 저장하고 화면에는 나이로 보인다. 만 14세 미만의 가입 처리(법정대리인 동의 또는 가입 제한)는 `010-social-login` 가입과 엮이므로 팀 확인으로 남긴다 (FR-007)
- Q: 다른 회원은 내 프로필을 어디까지 보는가? → A: 잠정안 — 로그인한 회원만 본다. 나이·성별은 공개로 켠 것만 보인다. 디스코드 태그 공개 범위는 비공개 / 파티원에게만 / 전체 회원 중 하나다. "파티원"은 `008-party`의 파티 멤버 정의를 따른다. 잠정, 팀 확인 필요 (담당: 팀 회의) (FR-013)
- Q: 관리자·운영자 계정도 마이페이지를 쓰는가? → A: 쓰지 않는다. 계정 메뉴에 "마이페이지"가 보이지 않고 주소로 들어와도 막는다. `002-admin-users`·`010-social-login`(FR-007)의 "관리자·운영자는 회원 활동을 하지 않는다"를 따른다 (처음 가정 "관리자·운영자도 쓴다"를 정정) (FR-016)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 프로필을 본다 (Priority: P1)

로그인한 회원이 계정 메뉴에서 "마이페이지"를 눌러 자기 프로필(아바타, 닉네임, 자기소개, 나이·성별과 공개 여부, 디스코드 태그와 공개 범위, 게임 정보, 주로 플레이하는 시간대)을 본다. 계정 메뉴에는 로그인 아이디 대신 닉네임이 보인다.

**Why this priority**: 고치기 전에 지금 상태를 보여야 나머지 스토리가 의미가 있다. 계정 메뉴의 닉네임 표시는 모든 회원이 매번 보는 곳이다.

**Independent Test**: 로그인 뒤 계정 메뉴를 열어 닉네임이 보이는지 보고, "마이페이지"로 들어가 프로필 항목이 보이는지 본다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 로그인한 회원이다, **When** 계정 메뉴에서 "마이페이지"를 누른다, **Then** 마이페이지가 열리고 아바타, 닉네임, 자기소개, 나이·성별, 디스코드 태그, 게임 정보, 주로 플레이하는 시간대가 보인다. 아직 적지 않은 항목은 비어 있음으로 보인다
2. **US1-AC2** **Given** 로그인하지 않았다, **When** 마이페이지 주소로 직접 들어간다, **Then** 로그인 화면으로 가고, 로그인하면 마이페이지로 돌아온다
3. **US1-AC3** **Given** 로그인한 회원이다, **When** 계정 메뉴를 연다, **Then** 계정 메뉴의 이름 자리에 닉네임이 보이고 로그인 아이디는 보이지 않는다
4. **US1-AC4** **Given** 아바타를 고른 적이 없는 회원이다, **When** 마이페이지를 연다, **Then** 기본 아바타가 보인다
5. **US1-AC5** **Given** 로그인한 회원이다, **When** 마이페이지를 연다, **Then** 로그인 방식과 소셜 계정 연결은 마이페이지에 없다 (계정 설정 화면, `010-social-login` FR-006)
6. **US1-AC6** **Given** 관리자 또는 운영자 계정으로 로그인했다, **When** 계정 메뉴를 연다, **Then** "마이페이지" 항목이 보이지 않는다 (FR-016)
7. **US1-AC7** **Given** 관리자 또는 운영자 계정으로 로그인했다, **When** 마이페이지 주소로 직접 들어간다, **Then** 마이페이지가 열리지 않고 권한이 없다는 안내가 보인다 (FR-016, `001-admin-menus` FR-003)

### User Story 2 - 닉네임을 바꾼다 (Priority: P1)

마이페이지에서 닉네임을 새 값으로 바꾼다. 저장하면 계정 메뉴와 다른 기능의 표시 이름이 새 닉네임으로 바뀐다.

**Why this priority**: 닉네임은 회원이 모든 기능에서 보이는 이름이다. 가입 때 정한 뒤 바꿀 길이 없으면 오타도 고칠 수 없다.

**Independent Test**: 마이페이지에서 닉네임을 바꾸고 저장한 뒤, 계정 메뉴와 파티 화면의 표시 이름이 바뀌었는지 본다.

**Acceptance Scenarios**:

1. **US2-AC1** **Given** 마이페이지다, **When** 닉네임을 규칙에 맞는 새 값으로 바꾸고 저장한다, **Then** 저장되었다는 안내가 보이고, 계정 메뉴의 닉네임이 새로고침 없이 바뀐다
2. **US2-AC2** **Given** US2-AC1로 닉네임을 바꿨다, **When** 그 회원이 들어간 파티의 멤버 목록을 본다, **Then** 새 닉네임이 보인다 (`008-party` FR-027의 표시 이름)
3. **US2-AC3** **Given** 마이페이지다, **When** 닉네임을 비우거나 공백만 넣거나 규칙(FR-003)에 맞지 않는 값(1자, 13자, 허용되지 않는 글자, 예약어)으로 저장한다, **Then** 저장되지 않고 닉네임 칸에 무엇이 잘못됐는지 보인다
4. **US2-AC4** **Given** 가입 뒤 닉네임을 이미 한 번 이상 바꿨고 마지막으로 바꾼 지 30일(FR-004)이 지나지 않았다, **When** 다시 바꾸려 한다, **Then** 저장되지 않고 언제부터 바꿀 수 있는지 보인다
5. **US2-AC5** **Given** 다른 회원이 쓰는 닉네임이 있다, **When** 그 닉네임이나 대소문자만 다른 닉네임으로 저장한다, **Then** 저장되지 않고 이미 쓰는 닉네임이라는 안내가 보인다 (FR-003)
6. **US2-AC6** **Given** 가입 뒤 닉네임을 한 번도 바꾸지 않았다, **When** 가입 직후 닉네임을 바꾼다, **Then** 기다리지 않고 바로 저장된다 (FR-004)

### User Story 3 - 자기소개, 나이·성별, 디스코드 태그를 적고 공개 범위를 정한다 (Priority: P2)

마이페이지에서 자기소개를 적고, 나이와 성별을 각각 공개·비공개로 정해 적고, 디스코드 태그를 적어 공개 범위를 고른다.

**Why this priority**: 파티를 같이 할 사람을 고를 때 쓰는 정보다. 닉네임(US2)만으로도 기능은 쓸 수 있어 P2다.

**Independent Test**: 각 항목을 적고 공개 여부를 바꿔 저장한 뒤, 마이페이지에서 값과 공개 여부가 그대로인지 본다.

**Acceptance Scenarios**:

1. **US3-AC1** **Given** 마이페이지다, **When** 자기소개를 적고 저장한다, **Then** 저장되고 마이페이지에 보인다. 글자 수 제한(FR-006)을 넘으면 저장되지 않고 칸 오류가 보인다
2. **US3-AC2** **Given** 마이페이지다, **When** 출생 연도와 성별을 적고 각각 공개 또는 비공개로 정해 저장한다, **Then** 값과 공개 여부가 저장되고 마이페이지에는 출생 연도로 계산한 나이와 성별이 보인다. 미래 연도는 저장되지 않는다 (FR-007)
3. **US3-AC3** **Given** 마이페이지다, **When** 디스코드 태그를 디스코드 사용자명 형식에 맞게 적고 공개 범위를 골라 저장한다, **Then** 저장되고 마이페이지에 보인다
4. **US3-AC4** **Given** 마이페이지다, **When** 디스코드 태그를 형식에 맞지 않게(예: 예전 `이름#1234` 형식, 대문자, 허용되지 않는 글자) 적어 저장한다, **Then** 저장되지 않고 형식 안내가 보인다
5. **US3-AC5** **Given** 자기소개·나이·성별·디스코드 태그를 적어 두었다, **When** 값을 지우고 저장한다, **Then** 그 항목이 비어 있음으로 저장된다 (모두 적지 않아도 된다)

### User Story 4 - 기본 아바타를 고른다 (Priority: P2)

마이페이지에서 moa가 제공하는 기본 아바타 목록을 보고 하나를 골라 프로필 사진으로 정한다.

**Why this priority**: 회원을 알아보기 쉽게 한다. 없어도 기본 아바타가 보이므로 P2다.

**Independent Test**: 다른 아바타를 고르고 저장한 뒤, 마이페이지와 계정 메뉴에 새 아바타가 보이는지 본다.

**Acceptance Scenarios**:

1. **US4-AC1** **Given** 마이페이지다, **When** 기본 아바타 목록에서 지금과 다른 아바타를 고르고 저장한다, **Then** 저장되고 마이페이지와 계정 메뉴에 새 아바타가 보인다
2. **US4-AC2** **Given** 마이페이지다, **When** 아바타를 고른다, **Then** moa가 제공하는 목록 밖의 이미지를 고르거나 올릴 방법이 없고, 목록 밖의 값을 보내면 저장되지 않는다

---

### User Story 5 - 게임 정보를 적는다 (Priority: P2)

마이페이지에서 하는 게임을 최대 3개까지 적는다. 게임마다 티어, 포지션, 게임 아이디를 적고, 게임 아이디로 전적 사이트 링크를 본다.

**Why this priority**: 파티 상대를 고를 때 가장 많이 보는 정보다. 다만 파티는 이미 참가 때 티어를 따로 받으므로(`008-party`) P2다.

**Independent Test**: 게임 셋을 적고 넷째를 더하려 해 보고, 적은 게임 아이디로 전적 사이트 링크가 열리는지 본다.

**Acceptance Scenarios**:

1. **US5-AC1** **Given** 마이페이지다, **When** 게임 목록(공통코드 `GAME`)에서 게임을 고르고 그 게임의 티어(`<게임>_TIER`)와 포지션(`<게임>_POSITION`)을 고르고 게임 아이디를 적어 저장한다, **Then** 저장되고 마이페이지에 게임·티어·포지션·게임 아이디가 보인다
2. **US5-AC2** **Given** 게임 정보가 3개 있다, **When** 넷째 게임을 더하려 한다, **Then** 더할 수 없다
3. **US5-AC3** **Given** 이미 적은 게임이다, **When** 같은 게임을 한 번 더 더하려 한다, **Then** 더할 수 없다 (게임마다 하나)
4. **US5-AC4** **Given** 포지션 목록이 없는 게임(예: 배틀그라운드)이다, **When** 그 게임을 고른다, **Then** 포지션 칸이 없다
5. **US5-AC5** **Given** 그 게임의 목록에 없는 티어나 포지션 값이다, **When** 저장하려 한다, **Then** 저장되지 않는다
6. **US5-AC6** **Given** 전적 사이트가 정해진 게임에 게임 아이디를 적었다, **When** 마이페이지를 본다, **Then** 그 게임 아이디로 만든 전적 사이트 링크가 보이고, 누르면 새 창에서 열린다. 전적 사이트가 정해지지 않은 게임은 링크가 없다
7. **US5-AC7** **Given** 게임 정보가 있다, **When** 그 게임 정보를 지운다, **Then** 목록에서 빠지고 다른 게임을 더할 수 있다

### User Story 6 - 주로 플레이하는 시간대를 정한다 (Priority: P3)

마이페이지에서 주로 게임을 하는 시간대를 고른다.

**Why this priority**: 파티 상대를 고를 때 도움이 되지만 없어도 다른 기능은 쓸 수 있다.

**Independent Test**: 시간대를 둘 고르고 저장한 뒤 마이페이지에 그대로 보이는지 본다.

**Acceptance Scenarios**:

1. **US6-AC1** **Given** 마이페이지다, **When** 정해 둔 시간대 목록(FR-012)에서 하나 이상을 고르고 저장한다, **Then** 고른 시간대가 저장되고 마이페이지에 보인다
2. **US6-AC2** **Given** 시간대를 골라 두었다, **When** 모두 풀고 저장한다, **Then** 시간대가 비어 있음으로 저장된다

---

### Edge Cases

- 닉네임 앞뒤 공백: 지우고 저장한다. 지운 뒤 비면 빈 값으로 본다 (US2-AC3)
- 다른 회원이 이미 쓰는 닉네임으로 바꾸려 할 때: 막는다. 대소문자만 다른 것도 같은 닉네임으로 본다 (FR-003 잠정, US2-AC5)
- 규칙이 생기기 전부터 있던 이름(시드 계정 등)이 규칙(FR-003)에 맞지 않을 때: 그대로 보인다. 바꿀 때만 규칙을 적용한다
- 닉네임을 지금과 같은 값으로 저장할 때: 바뀐 것이 없으므로 변경 제한 기간(FR-004)을 새로 시작하지 않는다
- 두 창에서 닉네임을 동시에 바꿀 때: 나중 저장이 이긴다. 변경 제한 기간은 마지막으로 바뀐 때부터다
- 기본 아바타 목록에서 어떤 아바타를 빼면: 그 아바타를 쓰던 회원에게는 기본 아바타가 보인다
- 공통코드에서 어떤 게임·티어·포지션을 쓰지 않게 되면: 이미 적은 게임 정보는 그대로 보이고, 새로 고를 때는 목록에 없다 (`008-party` Edge Cases와 같은 규칙). 그 게임 정보를 고쳐 저장하려면 쓰는 값으로 바꿔야 한다
- 게임 아이디에 전적 사이트 주소에 쓸 수 없는 글자(공백, `#` 등)가 있을 때: 링크는 그 글자를 주소에 맞게 바꿔 만든다. 게임 아이디 자체는 적은 그대로 보인다
- 디스코드 태그와 010에서 연결한 디스코드 계정: 서로 따로다. 연결한 디스코드 계정으로 태그를 채우거나 확인하지 않는다 (가정)
- 저장 중 로그인이 만료될 때: 저장되지 않고 로그인 화면으로 간다. 로그인하면 마이페이지로 돌아온다
- 관리자·운영자 계정: 마이페이지를 쓰지 않는다(FR-016). 그 계정의 이름은 사용자 관리 드로어의 "이름 바꾸기"(`002-admin-users` FR-007)로 바꾼다
- 회원이 나중에 관리자·운영자가 될 때(업무 역할을 받음): 그때부터 마이페이지를 열 수 없다. 적어 둔 프로필은 지우지 않는다
- 나이 계산: 해가 바뀌면 보이는 나이가 저절로 한 살 늘어난다 (출생 연도 저장)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 로그인한 회원은 마이페이지에서 자기 프로필(아바타, 닉네임, 자기소개, 나이·성별과 각 공개 여부, 디스코드 태그와 공개 범위, 게임 정보, 주로 플레이하는 시간대)을 보고 고칠 수 있어야 한다(MUST). 로그인하지 않았으면 로그인 화면으로 보내고, 로그인 뒤 마이페이지로 돌아온다
- **FR-002**: 마이페이지는 프로필만 다룬다(MUST). 로그인 방식(비밀번호 변경)과 소셜 계정 연결·해제는 마이페이지에 두지 않고 계정 설정 화면(`010-social-login` FR-006)과 비밀번호 변경 화면에 둔다
- **FR-003**: 회원은 마이페이지에서 닉네임을 바꿀 수 있어야 한다(MUST). 닉네임은 회원의 표시 이름이다(`010-social-login` FR-005)
  - 앞뒤 공백을 지우고, 지운 뒤 비어 있으면 저장하지 않는다(MUST)
  - 잠정 규칙: 다른 회원과 겹칠 수 없다(대소문자 무시). 2~12자. 한글·영문·숫자·`_`만 쓴다. 예약어(admin, 운영자, moa 등)는 쓸 수 없다. 예약어 목록은 plan에서 정한다
  - 가입(`010-social-login` FR-005)과 변경(이 스펙)이 같은 규칙을 쓴다
  - [NEEDS CLARIFICATION: 위 잠정 규칙을 팀이 확인한다. `010-social-login` FR-005와 같은 답으로 맞춘다 (담당: 팀 회의)]
- **FR-004**: 가입 뒤 첫 닉네임 변경은 바로 할 수 있고, 그 뒤로는 바꿀 때마다 30일 동안 다시 바꿀 수 없다(잠정). 기간 안에 바꾸려 하면 저장하지 않고 다시 바꿀 수 있는 날을 보인다
  - [NEEDS CLARIFICATION: 위 잠정 변경 제한(첫 변경 바로, 그 뒤 30일)을 팀이 확인한다. `010-social-login` FR-005와 같은 답으로 맞춘다 (담당: 팀 회의)]
- **FR-005**: 닉네임이 바뀌면 그 회원의 표시 이름을 보이는 모든 곳(계정 메뉴, 파티 등)이 새 닉네임을 보여야 한다(MUST). 같은 브라우저의 계정 메뉴는 새로고침 없이 바뀐다
- **FR-006**: 회원은 자기소개를 적을 수 있다(MAY). 500자 이내다. 비워 둘 수 있다
- **FR-007**: 회원은 나이와 성별을 적고 각각 공개 또는 비공개를 정할 수 있다(MAY). 비워 둘 수 있다. 처음 공개 여부는 비공개다
  - 성별은 정해 둔 목록(남성, 여성, 밝히지 않음)에서 고른다
  - 나이는 출생 연도로 받아 저장하고, 화면에는 나이로 보인다(MUST). 미래 연도는 받지 않는다
  - [NEEDS CLARIFICATION: 만 14세 미만 회원은 어떻게 하는가(법정대리인 동의를 받는가, 가입을 막는가)? 가입(`010-social-login`)과 엮이므로 함께 정한다. 팀 확인 필요 (담당: 팀 회의)]
- **FR-008**: 회원은 디스코드 태그를 적고 공개 범위를 고를 수 있다(MAY). 비워 둘 수 있다
  - 디스코드의 새 사용자명 형식이어야 한다(MUST): 2~32자, 영문 소문자·숫자·밑줄(`_`)·마침표(`.`)만, 마침표 두 개를 잇달아 쓸 수 없다. 예전 `이름#1234` 형식은 받지 않는다
  - 공개 범위는 비공개, 파티원에게만, 전체 회원 중 하나다(FR-013, 잠정). 처음 값은 비공개다
  - 010에서 연결한 디스코드 계정과 잇지 않는다. 회원이 적은 값이며 moa가 확인하지 않는다
- **FR-009**: 회원은 moa가 제공하는 기본 아바타 중 하나를 프로필 사진으로 고를 수 있어야 한다(MUST). 목록 밖의 값은 거부한다. 이미지를 올리는 기능은 두지 않는다(MUST NOT). 고른 적이 없거나 고른 아바타가 목록에서 빠지면 기본 아바타를 보인다
- **FR-010**: 회원은 게임 정보를 최대 3개까지 적을 수 있다(MAY). 게임 정보는 게임마다 하나다
  - 게임은 공통코드 `GAME` 그룹에서, 티어는 `<게임 코드>_TIER`, 포지션은 `<게임 코드>_POSITION` 그룹에서 고른다(MUST). `008-party` FR-002·FR-022와 같은 코드다. 그 게임의 목록에 없는 값은 거부한다
  - 티어와 포지션은 고르지 않아도 된다. 포지션 그룹이 없는 게임은 포지션 칸이 없다
  - 게임 아이디는 적지 않아도 된다. 50자 이내다
  - 게임 정보는 회원이 적는 값이며 게임 API로 확인하지 않는다(범위 밖, 나중 스펙 "게임 계정 확인")
- **FR-011**: 게임 아이디가 있고 그 게임에 전적 사이트가 정해져 있으면 그 게임 아이디로 만든 전적 사이트 링크를 보여야 한다(MUST). 링크는 새 창에서 열린다. 게임마다 어떤 전적 사이트를 쓰는지는 moa가 정해 두고(예: 리그 오브 레전드는 op.gg) 회원이 바꾸지 않는다
- **FR-012**: 회원은 주로 플레이하는 시간대를 정해 둔 목록에서 여러 개 고를 수 있다(MAY). 목록은 새벽(0~6시), 오전(6~12시), 오후(12~18시), 저녁(18~24시)이다. 비워 둘 수 있다
- **FR-013**: 다른 회원이 내 프로필을 보는 범위 (잠정)
  - 로그인한 회원만 다른 회원의 프로필을 본다. 로그인하지 않은 사람에게는 보이지 않는다
  - 나이·성별은 공개로 켠 것만 보인다
  - 디스코드 태그는 공개 범위대로 보인다: 비공개는 아무에게도, 파티원에게만은 지금 같은 파티의 멤버(방장 포함)에게만, 전체 회원은 로그인한 회원 모두에게. "파티원"은 `008-party`의 파티 멤버(파티와 회원의 관계, 방장·멤버) 정의를 따른다
  - 닉네임, 아바타, 자기소개, 게임 정보, 시간대는 로그인한 회원 모두에게 보인다
  - 다른 회원 프로필을 어느 화면(파티 멤버 목록 등)에서 여는지는 이 스펙 범위 밖이다. 이 스펙은 보이는 규칙만 정하고, 그 화면을 만드는 기능이 이 규칙을 따른다
  - [NEEDS CLARIFICATION: 위 잠정 범위(로그인한 회원만, 나이·성별 공개 선택, 디스코드 태그 3단계, 파티원 정의)를 팀이 확인한다 (담당: 팀 회의)]
- **FR-014**: 계정 메뉴는 이름 자리에 닉네임을 보이고 로그인 아이디를 보이지 않아야 한다(MUST). 아바타를 고른 회원은 계정 메뉴에도 그 아바타를 보인다. 계정 메뉴에 "마이페이지" 항목을 더한다(MUST). 관리자·운영자 계정에는 "마이페이지" 항목을 보이지 않는다(FR-016). 닉네임 표시는 모든 계정에 같다
  - 계정 메뉴는 관리 셸과 사용자 셸이 함께 쓰는 키트 셸 파일이다. 구현 때 바꿀 내용을 먼저 보고하고 승인받는다
- **FR-015**: 마이페이지는 계정 메뉴로 여는 계정 화면이다(MUST). 사이드바 메뉴로 열지 않으므로 프로그램으로 등록하지 않는다(`001-admin-menus` FR-008 "메뉴로 열지 않는 화면(공지 상세, 계정 화면 등)은 프로그램으로 등록하지 않는다"). 다른 계정 화면처럼 관리 메뉴가 있는 사용자에게는 관리 셸, 없는 사용자에게는 사용자 셸 안에서 열린다(`001-admin-menus` FR-005). 관리자·운영자는 마이페이지를 쓰지 않으므로(FR-016) 실제로는 사용자 셸에서만 열린다
- **FR-016**: 관리자·운영자 계정(시스템 역할 `ADMIN`이거나 업무 역할을 가진 계정, `010-social-login` FR-007과 같은 정의)은 마이페이지를 쓰지 않는다(MUST)
  - 계정 메뉴에 "마이페이지"가 보이지 않는다
  - 마이페이지 주소로 들어오거나 프로필을 고치려 하면 막고 권한이 없다는 안내를 보인다(`001-admin-menus` FR-003)
  - 근거: `002-admin-users`와 `010-social-login` FR-007의 "관리자·운영자는 회원 활동을 하지 않는다"

### Key Entities *(include if feature involves data)*

- **회원**: 키트 `users`. 닉네임은 표시 이름이다(`010-social-login` FR-005). 가입 뒤 닉네임을 바꾼 적이 있는지와 마지막으로 바꾼 시각을 안다(FR-004)
- **프로필**: 회원 하나에 하나. 아바타(기본 아바타 목록의 키), 자기소개, 출생 연도와 나이 공개 여부, 성별과 공개 여부, 디스코드 태그와 공개 범위, 주로 플레이하는 시간대(여러 개)
- **게임 정보**: 회원 하나에 최대 3개, 게임마다 하나. 게임 코드, 티어 코드, 포지션 코드, 게임 아이디
- **기본 아바타 목록**: moa가 정해 둔 이미지 묶음. 회원이 더하거나 올릴 수 없다
- **전적 사이트**: 게임마다 moa가 정해 둔 링크 규칙. 회원이 바꿀 수 없다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원이 계정 메뉴에서 마이페이지로 들어가 닉네임을 바꾸고 저장을 마치기까지 30초 안에 끝난다
- **SC-002**: 닉네임이나 아바타를 저장하면 같은 브라우저의 계정 메뉴에 새로고침 없이 바로 보인다
- **SC-003**: 규칙에 맞지 않는 값(빈 닉네임, 글자 수 초과, 예약어·이미 쓰는 닉네임, 미래 출생 연도, 디스코드 형식 오류, 목록 밖의 게임·티어·포지션·아바타, 넷째 게임)을 저장하려는 시도는 하나도 저장되지 않고 어느 칸이 잘못됐는지 보인다
- **SC-004**: 계정 메뉴와 마이페이지 어디에도 로그인 아이디가 보이지 않는다
- **SC-005**: 수용 시나리오(US1~US6) 전부가 자동 테스트로 확인된다 (원칙 II)
- **SC-006**: 관리자·운영자 계정은 어떤 경로로도 마이페이지를 열거나 프로필을 고칠 수 없다

## Assumptions

- 마이페이지는 관리자·운영자가 아닌 로그인한 회원이 쓴다 (FR-016)
- 아이디·비밀번호 회원(시드 등)의 닉네임은 지금 이름(`name`)이다. 관리자·운영자가 아니면 마이페이지에서 바꿀 수 있다. 그 사람들의 처음 표시 이름은 `010-social-login` FR-005의 질문을 따른다
- 기본 아바타의 그림과 개수는 이 스펙이 정하지 않는다. 구현 전에 정한다
- 게임마다 쓸 전적 사이트와 링크 규칙(예: 리그 오브 레전드 op.gg)은 plan에서 정한다. 정해지지 않은 게임은 링크를 보이지 않는다
- 보이는 나이는 "올해 − 출생 연도"로 계산한다(생일을 받지 않으므로 연 나이)
- 자기소개 500자, 게임 아이디 50자, 성별 목록, 시간대 목록 4개는 이 스펙의 기본값이다. 바꾸면 이 스펙을 고친다
- 게임 정보의 티어는 회원이 적는 값이다. 파티 참가 때 적는 티어(`008-party`)와 이어지지 않는다. 잇는 일은 나중 스펙("게임 계정 확인" 또는 파티 스펙)이 정한다
- 회원 탈퇴(30일 유예·복구·완전 삭제)와 활동 기록은 이 스펙의 범위가 아니다. 탈퇴할 때 프로필·게임 정보를 어떻게 지울지는 회원 탈퇴 스펙이 정한다
- 프로필 이미지 올리기와 게임 API 계정·랭크 확인은 범위 밖이다
- 나중에 고칠 곳: 이번 단계에서는 다른 스펙을 고치지 않는다. [NEEDS CLARIFICATION]이 풀리거나 이 기능을 구현할 때 아래를 함께 고친다
  - `001-admin-menus` FR-005: 계정 화면 목록(알림, 설정, 비밀번호 변경)에 마이페이지를 더하고, "두 셸의 계정 메뉴는 설정, 비밀번호 변경, 로그아웃 순서다"에 마이페이지 항목의 자리를 더한다. 계정 메뉴의 이름·아이디 표시를 닉네임 표시로 바꾼다 (FR-014). FR-008 프로그램 표는 고칠 것 없음 (FR-015)
  - `002-admin-users` FR-004·FR-007: 사용자 관리 목록·드로어에 닉네임·아바타를 보일지, 드로어의 "이름 바꾸기"를 닉네임 바꾸기로 볼지와 같은 닉네임 규칙(FR-003)·변경 제한(FR-004)을 적용할지. 관리자·운영자는 마이페이지를 쓰지 않으므로(FR-016) 그 계정의 이름은 드로어로만 바뀐다
  - `008-party` FR-027과 가정 "닉네임은 회원 가입·프로필에서 정한다", "나중에 프로필에 게임 계정을 연동해 티어를 가져오면": 표시 이름은 닉네임이고 마이페이지에서 바뀐다(FR-005). 프로필의 게임 티어는 회원이 적는 값이며 연동은 나중 스펙이다. 디스코드 태그 공개 범위 "파티원에게만"(FR-013)이 008의 파티 멤버 정의를 쓴다. 다른 회원 프로필을 파티 화면에서 보일지는 008이 정하고 FR-013의 보이는 규칙을 따른다. 팀 공유 필요 (담당: 008-party 담당)
  - `010-social-login` FR-005 닉네임 규칙: 가입 뒤 바꾸기는 `009-mypage`가 맡는다고 적고, 같은 잠정 답(FR-003 중복 불가·2~12자·한글·영문·숫자·`_`·예약어 금지, FR-004 첫 변경 바로·그 뒤 30일)으로 맞춘다. 만 14세 미만 가입 처리(법정대리인 동의 또는 가입 제한, FR-007) 질문을 010에 더한다. 출생 연도를 가입 때 받을지도 함께 정한다 (PR #54와 맞춘다)
  - `specs/README.md` 맞춰야 할 경계: "회원 정보 모델" 줄(프로필 항목: 닉네임, 아바타, 자기소개, 나이·성별, 디스코드 태그, 게임 정보, 시간대), "관리자·운영자 계정의 회원 활동 금지" 줄(009는 FR-016으로 관리자·운영자의 마이페이지를 막았다), "사용자 셸의 메뉴와 모양" 줄(마이페이지는 계정 메뉴로 열고 사용자 메뉴가 아님)

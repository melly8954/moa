# Feature Specification: 마이페이지 (mypage)

**Feature Branch**: `feat/009-mypage`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "마이페이지: 로그인한 회원이 자기 프로필을 보고 고친다. 닉네임, 자기소개, 나이·성별(공개 선택), 디스코드 태그(공개 범위 선택), 기본 아바타, 게임 정보 최대 3개(게임·티어·포지션 공통코드, 게임 아이디와 전적 사이트 링크), 주로 플레이하는 시간대. 로그인 방식·소셜 연결은 010의 계정 설정 화면. 계정 바에 loginId 대신 닉네임."

**출처**: moa. 팀 기획안(2차 작업 요약 마이페이지 & 운영 정책 결정안)의 프로필 편집 화면·게임정보 추가 모달을 따른다

**배경** (기존 스펙에서 따름):

- 회원의 표시 이름은 닉네임이다. 소셜 회원은 가입 때 닉네임을 정한다(`010-social-login` FR-005, 2026-11-22 dev에 구현됨). 다른 기능은 표시 이름을 보이고 로그인 아이디는 보이지 않는다(`008-party` FR-027)
- 화면은 관리 셸과 사용자 셸로 나뉘고, 계정 화면(알림, 설정, 비밀번호 변경)은 사용자에 맞는 셸 안에서 열린다. 메뉴로 열지 않는 계정 화면은 프로그램으로 등록하지 않는다(`001-admin-menus` FR-005, FR-008)
- 게임·티어·포지션은 파티와 같은 공통코드를 쓴다: 게임 그룹 `GAME`, 게임마다 `<게임 코드>_TIER`, `<게임 코드>_POSITION` (`008-party` FR-002, FR-022)
- 로그인 방식(비밀번호)과 소셜 계정 연결·해제는 `010-social-login`의 계정 설정 화면이 맡는다(FR-006). 마이페이지는 프로필과 계정 관리(회원 탈퇴, `018-member-withdrawal`)를 다룬다
- 정해지지 않은 것은 추측하지 않고 [NEEDS CLARIFICATION]으로 둔다 (원칙 I)

**배경** (2026-11-17 결정):

- 프로필 사진은 moa가 제공하는 기본 아바타 중에서만 고른다. 직접 올리기는 선정적·폭력적 이미지 검열 문제로 보류한다
- 게임 정보는 회원이 적는 값이다. 게임 API로 계정·랭크를 확인하는 일은 나중 스펙("게임 계정 확인")에서 다룬다
- 회원 탈퇴(30일 유예·복구·완전 삭제)는 별도 스펙이다. 활동 기록(내 파티·글 등)은 이번 범위가 아니다

## Clarifications

### Session 2026-11-17

- Q: 닉네임 규칙(중복, 길이, 글자)은? → A: 잠정안 — 중복 불가(대소문자 무시), 2~12자, 한글·영문·숫자·`_`만, 예약어(admin, 운영자, moa 등) 금지. `010-social-login` FR-005의 같은 질문과 같은 답이다. 잠정, 팀 확인 필요 (담당: 팀 회의) (FR-003). **2026-11-19 정정: "중복 불가"를 "닉네임 중복 허용 + 고유 태그"로 바꿨다 (아래 Session 2026-11-19)**
- Q: 닉네임 변경 제한 기간은? → A: 잠정안 — 가입 뒤 첫 변경은 바로 할 수 있고, 그 뒤로는 바꿀 때마다 30일 동안 다시 바꿀 수 없다. `010-social-login` FR-005와 같은 답이다. 잠정, 팀 확인 필요 (담당: 팀 회의) (FR-004)
- Q: 나이는 어떻게 받는가? → A: 출생 연도를 저장하고 화면에는 나이로 보인다. 만 14세 미만의 가입 처리(법정대리인 동의 또는 가입 제한)는 `010-social-login` 가입과 엮이므로 팀 확인으로 남긴다 (FR-007)
- Q: 다른 회원은 내 프로필을 어디까지 보는가? → A: 잠정안 — 로그인한 회원만 본다. 나이·성별은 공개로 켠 것만 보인다. 디스코드 태그 공개 범위는 비공개 / 친구만 / 전체 회원 중 하나다(팀 기획안에 따라 처음 답 "파티원에게만"을 정정. 2026-11-25 "친구·팔로워만"을 "친구만"으로 정정). 잠정, 팀 확인 필요 (담당: 팀 회의) (FR-013)
- Q: 관리자·운영자 계정도 마이페이지를 쓰는가? → A: 쓰지 않는다. 계정 바 톱니 메뉴에 "마이페이지"가 보이지 않고 주소로 들어와도 막는다. `002-admin-users`·`010-social-login`(FR-007)의 "관리자·운영자는 회원 활동을 하지 않는다"를 따른다 (처음 가정 "관리자·운영자도 쓴다"를 정정) (FR-016)
- Q: 플레이 시간대 선택지는? → A: 팀 기획안대로 "플레이 가능 시간대"로 부르고 평일 오전, 평일 저녁, 주말 종일, 새벽 중 여러 개를 고른다. 선택지는 공통코드로 두어 나중에 바꿀 수 있게 한다 (처음 기본값 새벽·오전·오후·저녁을 정정) (FR-012)
- Q: 디스코드 태그의 "친구만"에서 친구는 누구인가? → A: 친구의 정의는 `014-friends-follow` FR-004를 따른다. 2026-11-25에 014 FR-015의 제안을 받아 "친구·팔로워만"을 "친구만"으로 바꿨다(팔로우는 수락 없이 누구나 걸 수 있어 공개 범위로서 뜻이 약하다). 처음 답의 "파티원에게만"과 `008-party` 파티 멤버 정의 연결은 지운다 (FR-013)
- Q: 나이·성별 공개 여부는 따로 정하는가? → A: 잠정안 — 팀 기획안대로 "공개 여부" 토글 하나로 나이와 성별을 함께 공개·비공개한다. 각각 따로 둘지(기획안 "공개범위 개별 관리" 항목)는 팀 확인 (처음 답 "각각 공개 여부"를 정정) (FR-007)
- Q: 게임 정보는 어떻게 더하는가? → A: 팀 기획안의 게임정보 추가 모달에서 게임, 랭크, 포지션을 고른다. 랭크는 본인이 적는 값(직접 입력)이라는 뜻이고 고르는 목록은 공통코드 `<게임 코드>_TIER`다(`008-party`와 같은 코드). 모달에 "랭크는 직접 입력한 값이라 확인되지 않은 값" 안내와 현재 개수(예: 1/3)를 보인다. 게임 아이디와 전적 사이트 링크는 그대로 둔다 (FR-010)
- Q: 프로필 편집 화면에서 무엇이 필수인가? → A: 팀 기획안대로 닉네임만 필수다. 자기소개, 나이, 성별, 디스코드 태그, 플레이 가능 시간대는 선택으로 표시한다 (FR-017)

### Session 2026-11-19

- Q: 다른 회원과 같은 닉네임을 쓸 수 있는가? 회원은 무엇으로 구별하는가? → A: 쓸 수 있다(대소문자만 다른 것도). 회원마다 서버가 숫자 4자리 태그(`0001`~`9999`)를 정해 `닉네임#0421`로 구별한다. 태그는 가입(또는 프로필이 처음 생길) 때 그 닉네임에서 쓰이지 않은 번호 중 무작위로 정하고 회원이 고르지 않는다. 닉네임을 바꾸면 새 닉네임에서 지금 태그가 비어 있으면 그대로, 쓰이고 있으면 새로 정한다. 같은 닉네임의 태그가 모두 쓰이면 그 닉네임은 더 쓸 수 없다. 처음 잠정안 "중복 불가(대소문자 무시)"를 정정한다. `010-social-login` FR-005와 같은 답이다 (FR-003, FR-004)
- Q: 태그는 어디에 어떻게 보이는가? → A: 잠정안 — 기본은 닉네임만 보이고, 사람을 골라야 하는 자리(마이페이지·프로필 머리, 회원 검색 결과, 멘션 후보, 사용자 관리)에는 `닉네임#0421`로 보인다. 검색은 닉네임 일부로 찾고 결과에 태그를 함께 보이며, `닉네임#0421`을 넣으면 그 회원 하나를 찾는다. 멘션은 `@닉네임#0421`이다. 팀 기획안 화면의 `@my_handle` 표기와 다르므로 팀 확인 필요 (담당: 팀 회의) (FR-003)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 프로필을 본다 (Priority: P1)

로그인한 회원이 계정 바 톱니 메뉴에서 "마이페이지"를 눌러 자기 프로필(아바타, 닉네임, 자기소개, 나이·성별과 공개 여부, 디스코드 태그와 공개 범위, 게임 정보, 플레이 가능 시간대)을 본다. 계정 바에는 로그인 아이디 대신 닉네임이 보인다.

**Why this priority**: 고치기 전에 지금 상태를 보여야 나머지 스토리가 의미가 있다. 계정 바의 닉네임 표시는 모든 회원이 매번 보는 곳이다.

**Independent Test**: 로그인 뒤 계정 바를 열어 닉네임이 보이는지 보고, "마이페이지"로 들어가 프로필 항목이 보이는지 본다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 로그인한 회원이다, **When** 계정 바 톱니 메뉴에서 "마이페이지"를 누른다, **Then** 마이페이지가 열리고 아바타, 닉네임과 태그(`닉네임#0421`), 자기소개, 나이·성별, 디스코드 태그, 게임 정보, 플레이 가능 시간대가 보인다. 아직 적지 않은 항목은 비어 있음으로 보인다
2. **US1-AC2** **Given** 로그인하지 않았다, **When** 마이페이지 주소로 직접 들어간다, **Then** 로그인 화면으로 가고, 로그인하면 마이페이지로 돌아온다
3. **US1-AC3** **Given** 로그인한 회원이다, **When** 계정 바와 톱니 메뉴를 본다, **Then** 계정 바의 이름 자리에 닉네임이 보이고 로그인 아이디는 보이지 않는다
4. **US1-AC4** **Given** 아바타를 고른 적이 없는 회원이다, **When** 마이페이지를 연다, **Then** 기본 아바타가 보인다
5. **US1-AC5** **Given** 로그인한 회원이다, **When** 마이페이지를 연다, **Then** 로그인 방식과 소셜 계정 연결은 마이페이지에 없다 (계정 설정 화면, `010-social-login` FR-006)
6. **US1-AC6** **Given** 관리자 또는 운영자 계정으로 로그인했다, **When** 계정 바와 톱니 메뉴를 본다, **Then** "마이페이지" 항목이 보이지 않는다 (FR-016)
7. **US1-AC7** **Given** 관리자 또는 운영자 계정으로 로그인했다, **When** 마이페이지 주소로 직접 들어간다, **Then** 마이페이지가 열리지 않고 권한이 없다는 안내가 보인다 (FR-016, `001-admin-menus` FR-003)
8. **US1-AC8** **Given** 마이페이지의 프로필 편집 화면이다, **When** 항목을 본다, **Then** 닉네임은 필수로, 자기소개·나이·성별·디스코드 태그·플레이 가능 시간대는 선택으로 표시된다 (FR-017)

### User Story 2 - 닉네임을 바꾼다 (Priority: P1)

마이페이지에서 닉네임을 새 값으로 바꾼다. 저장하면 계정 바와 다른 기능의 표시 이름이 새 닉네임으로 바뀐다.

**Why this priority**: 닉네임은 회원이 모든 기능에서 보이는 이름이다. 가입 때 정한 뒤 바꿀 길이 없으면 오타도 고칠 수 없다.

**Independent Test**: 마이페이지에서 닉네임을 바꾸고 저장한 뒤, 계정 바와 파티 화면의 표시 이름이 바뀌었는지 본다.

**Acceptance Scenarios**:

1. **US2-AC1** **Given** 마이페이지다, **When** 닉네임을 규칙에 맞는 새 값으로 바꾸고 저장한다, **Then** 저장되었다는 안내가 보이고, 계정 바의 닉네임이 새로고침 없이 바뀐다
2. **US2-AC2** **Given** US2-AC1로 닉네임을 바꿨다, **When** 그 회원이 들어간 파티의 멤버 목록을 본다, **Then** 새 닉네임이 보인다 (`008-party` FR-027의 표시 이름)
3. **US2-AC3** **Given** 마이페이지다, **When** 닉네임을 비우거나 공백만 넣거나 규칙(FR-003)에 맞지 않는 값(1자, 13자, 허용되지 않는 글자, 예약어)으로 저장한다, **Then** 저장되지 않고 닉네임 칸에 무엇이 잘못됐는지 보인다
4. **US2-AC4** **Given** 가입 뒤 닉네임을 이미 한 번 이상 바꿨고 마지막으로 바꾼 지 30일(FR-004)이 지나지 않았다, **When** 다시 바꾸려 한다, **Then** 저장되지 않고 언제부터 바꿀 수 있는지 보인다
5. **US2-AC5** **Given** 다른 회원이 쓰는 닉네임이 있다, **When** 그 닉네임이나 대소문자만 다른 닉네임으로 저장한다, **Then** 저장되고, 그 회원과 다른 태그를 갖는다 (FR-003. 2026-11-19 "막힘"에서 정정)
6. **US2-AC6** **Given** 가입 뒤 닉네임을 한 번도 바꾸지 않았다, **When** 가입 직후 닉네임을 바꾼다, **Then** 기다리지 않고 바로 저장된다 (FR-004)
7. **US2-AC7** **Given** 태그가 `0421`인 회원이고 새 닉네임에서 `0421`을 쓰는 회원이 없다, **When** 닉네임을 바꾼다, **Then** 태그는 `0421` 그대로다. 새 닉네임에서 `0421`을 이미 다른 회원이 쓰면 새 태그를 받는다 (FR-003)
8. **US2-AC8** **Given** 어떤 닉네임(대소문자 무시)의 태그 9999개가 모두 쓰이고 있다, **When** 그 닉네임으로 바꾼다, **Then** 저장되지 않고 그 닉네임은 더 쓸 수 없으니 다른 닉네임을 고르라는 안내가 보인다 (FR-003)

### User Story 3 - 자기소개, 나이·성별, 디스코드 태그를 적고 공개 범위를 정한다 (Priority: P2)

마이페이지에서 자기소개를 적고, 나이와 성별을 적어 공개 여부 토글 하나로 함께 공개·비공개를 정하고, 디스코드 태그를 적어 공개 범위를 고른다.

**Why this priority**: 파티를 같이 할 사람을 고를 때 쓰는 정보다. 닉네임(US2)만으로도 기능은 쓸 수 있어 P2다.

**Independent Test**: 각 항목을 적고 공개 여부를 바꿔 저장한 뒤, 마이페이지에서 값과 공개 여부가 그대로인지 본다.

**Acceptance Scenarios**:

1. **US3-AC1** **Given** 마이페이지다, **When** 자기소개를 적고 저장한다, **Then** 저장되고 마이페이지에 보인다. 글자 수 제한(FR-006)을 넘으면 저장되지 않고 칸 오류가 보인다
2. **US3-AC2** **Given** 마이페이지다, **When** 출생 연도와 성별을 적고 공개 여부 토글 하나를 켜거나 꺼서 저장한다, **Then** 값과 공개 여부가 저장되고 나이와 성별이 같은 공개 여부를 가진다. 마이페이지에는 출생 연도로 계산한 나이와 성별이 보인다. 미래 연도는 저장되지 않는다 (FR-007)
3. **US3-AC3** **Given** 마이페이지다, **When** 디스코드 태그를 디스코드 사용자명 형식에 맞게 적고 공개 범위(비공개, 친구만, 전체 회원)를 골라 저장한다, **Then** 저장되고 마이페이지에 태그와 공개 범위가 보인다. 공개 범위를 고르지 않았으면 비공개다 (FR-008)
4. **US3-AC4** **Given** 마이페이지다, **When** 디스코드 태그를 형식에 맞지 않게(예: 예전 `이름#1234` 형식, 대문자, 허용되지 않는 글자) 적어 저장한다, **Then** 저장되지 않고 형식 안내가 보인다
5. **US3-AC5** **Given** 자기소개·나이·성별·디스코드 태그를 적어 두었다, **When** 값을 지우고 저장한다, **Then** 그 항목이 비어 있음으로 저장된다 (모두 적지 않아도 된다)

### User Story 4 - 기본 아바타를 고른다 (Priority: P2)

마이페이지에서 moa가 제공하는 기본 아바타 목록을 보고 하나를 골라 프로필 사진으로 정한다.

**Why this priority**: 회원을 알아보기 쉽게 한다. 없어도 기본 아바타가 보이므로 P2다.

**Independent Test**: 다른 아바타를 고르고 저장한 뒤, 마이페이지와 계정 바에 새 아바타가 보이는지 본다.

**Acceptance Scenarios**:

1. **US4-AC1** **Given** 마이페이지다, **When** 기본 아바타 목록에서 지금과 다른 아바타를 고르고 저장한다, **Then** 저장되고 마이페이지와 계정 바에 새 아바타가 보인다
2. **US4-AC2** **Given** 마이페이지다, **When** 아바타를 고른다, **Then** moa가 제공하는 목록 밖의 이미지를 고르거나 올릴 방법이 없고, 목록 밖의 값을 보내면 저장되지 않는다

### User Story 5 - 게임 정보를 적는다 (Priority: P2)

마이페이지에서 게임정보 추가 화면(모달)을 열어 하는 게임을 최대 3개까지 더한다. 게임마다 랭크(티어), 포지션, 게임 아이디를 적고, 게임 아이디로 전적 사이트 링크를 본다.

**Why this priority**: 파티 상대를 고를 때 가장 많이 보는 정보다. 다만 파티는 이미 참가 때 티어를 따로 받으므로(`008-party`) P2다.

**Independent Test**: 게임 셋을 적고 넷째를 더하려 해 보고, 적은 게임 아이디로 전적 사이트 링크가 열리는지 본다.

**Acceptance Scenarios**:

1. **US5-AC1** **Given** 마이페이지다, **When** 게임정보 추가 화면을 열어 게임 목록(공통코드 `GAME`)에서 게임을 고르고 그 게임의 랭크(`<게임>_TIER`)와 포지션(`<게임>_POSITION`)을 고르고 게임 아이디를 적어 저장한다, **Then** 저장되고 마이페이지에 게임·랭크·포지션·게임 아이디가 보인다
2. **US5-AC2** **Given** 게임 정보가 3개 있다, **When** 넷째 게임을 더하려 한다, **Then** 더할 수 없다
3. **US5-AC3** **Given** 이미 적은 게임이다, **When** 같은 게임을 한 번 더 더하려 한다, **Then** 더할 수 없다 (게임마다 하나)
4. **US5-AC4** **Given** 포지션 목록이 없는 게임(예: 배틀그라운드)이다, **When** 그 게임을 고른다, **Then** 포지션 칸이 없다
5. **US5-AC5** **Given** 그 게임의 목록에 없는 랭크나 포지션 값이다, **When** 저장하려 한다, **Then** 저장되지 않는다
6. **US5-AC6** **Given** 전적 사이트가 정해진 게임에 게임 아이디를 적었다, **When** 마이페이지를 본다, **Then** 그 게임 아이디로 만든 전적 사이트 링크가 보이고, 누르면 새 창에서 열린다. 전적 사이트가 정해지지 않은 게임은 링크가 없다
7. **US5-AC7** **Given** 게임 정보가 있다, **When** 그 게임 정보를 지운다, **Then** 목록에서 빠지고 다른 게임을 더할 수 있다
8. **US5-AC8** **Given** 게임정보 추가 화면이다, **When** 화면을 본다, **Then** "랭크는 직접 입력한 값이라 확인되지 않은 값"이라는 안내가 보인다 (FR-010)
9. **US5-AC9** **Given** 게임 정보가 1개 있다, **When** 마이페이지의 게임 정보 영역을 본다, **Then** 현재 개수와 최대 개수가 "1/3"으로 보인다. 3개가 되면 "3/3"으로 보이고 게임정보 추가 단추를 쓸 수 없다 (FR-010)

### User Story 6 - 플레이 가능 시간대를 정한다 (Priority: P3)

마이페이지에서 게임을 할 수 있는 시간대를 고른다 (팀 기획안 "플레이 가능 시간대").

**Why this priority**: 파티 상대를 고를 때 도움이 되지만 없어도 다른 기능은 쓸 수 있다.

**Independent Test**: 시간대를 둘 고르고 저장한 뒤 마이페이지에 그대로 보이는지 본다.

**Acceptance Scenarios**:

1. **US6-AC1** **Given** 마이페이지다, **When** 시간대 목록(평일 오전, 평일 저녁, 주말 종일, 새벽, FR-012)에서 하나 이상을 고르고 저장한다, **Then** 고른 시간대가 저장되고 마이페이지에 보인다
2. **US6-AC2** **Given** 시간대를 골라 두었다, **When** 모두 풀고 저장한다, **Then** 시간대가 비어 있음으로 저장된다

---

### Edge Cases

- 닉네임 앞뒤 공백: 지우고 저장한다. 지운 뒤 비면 빈 값으로 본다 (US2-AC3)
- 다른 회원이 이미 쓰는 닉네임으로 바꾸려 할 때: 바뀐다. 대소문자만 다른 것도 같은 닉네임으로 보아 서로 다른 태그를 갖는다 (FR-003, US2-AC5)
- 대소문자만 바꿀 때(예: `moa_kim` → `Moa_Kim`): 같은 닉네임으로 보므로 태그가 그대로다 (FR-003)
- 두 회원이 같은 닉네임으로 동시에 바꿀 때: 둘 다 바뀌고 서로 다른 태그를 갖는다
- 규칙(FR-003)이 생기기 전부터 있던 회원: 태그를 갖는다(010 마이그레이션이 채움, `010-social-login` data-model). 키트 경로로 만든 계정(첫 관리자, 관리자가 만든 계정)은 프로필이 생길 때까지 태그가 없고 닉네임만 보인다
- 규칙이 생기기 전부터 있던 이름(시드 계정 등)이 규칙(FR-003)에 맞지 않을 때: 그대로 보인다. 바꿀 때만 규칙을 적용한다
- 닉네임을 지금과 같은 값으로 저장할 때: 바뀐 것이 없으므로 변경 제한 기간(FR-004)을 새로 시작하지 않는다
- 두 창에서 닉네임을 동시에 바꿀 때: 먼저 저장된 쪽이 30일 제한(FR-004)을 시작하고, 나중 저장은 B202로 막힌다
- 기본 아바타 목록에서 어떤 아바타를 빼면: 그 아바타를 쓰던 회원에게는 기본 아바타가 보인다
- 공통코드에서 어떤 플레이 가능 시간대를 쓰지 않게 되면: 이미 고른 값은 그대로 보이고, 새로 고를 때는 목록에 없다 (게임 코드와 같은 규칙)
- 디스코드 태그 공개 범위를 "친구만"으로 골랐는데 친구 기능(`014-friends-follow`)이 아직 없을 때: 해당하는 회원이 없으므로 아무에게도 보이지 않는다 (FR-013 [NEEDS CLARIFICATION])
- 공통코드에서 어떤 게임·랭크·포지션을 쓰지 않게 되면: 이미 적은 게임 정보는 그대로 보이고, 새로 고를 때는 목록에 없다 (`008-party` Edge Cases와 같은 규칙). 그 게임 정보를 고쳐 저장하려면 쓰는 값으로 바꿔야 한다
- 게임 아이디에 전적 사이트 주소에 쓸 수 없는 글자(공백, `#` 등)가 있을 때: 링크는 그 글자를 주소에 맞게 바꿔 만든다. 게임 아이디 자체는 적은 그대로 보인다
- 디스코드 태그와 010에서 연결한 디스코드 계정: 서로 따로다. 연결한 디스코드 계정으로 태그를 채우거나 확인하지 않는다 (가정)
- 저장 중 로그인이 만료될 때: 저장되지 않고 로그인 화면으로 간다. 로그인하면 마이페이지로 돌아온다
- 관리자·운영자 계정: 마이페이지를 쓰지 않는다(FR-016). 그 계정의 이름은 사용자 관리 드로어의 "이름 바꾸기"(`002-admin-users` FR-007)로 바꾼다
- 회원이 나중에 관리자·운영자가 될 때(사용자 관리에서 계정 종류가 관리자 계정 `ADMIN`으로 바뀜): 그때부터 마이페이지를 열 수 없다. 적어 둔 프로필은 지우지 않는다
- 나이 계산: 해가 바뀌면 보이는 나이가 저절로 한 살 늘어난다 (출생 연도 저장)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 로그인한 회원은 마이페이지에서 자기 프로필(아바타, 닉네임, 자기소개, 나이·성별과 공개 여부, 디스코드 태그와 공개 범위, 게임 정보, 플레이 가능 시간대)을 보고 고칠 수 있어야 한다(MUST). 로그인하지 않았으면 로그인 화면으로 보내고, 로그인 뒤 마이페이지로 돌아온다
- **FR-002**: 마이페이지는 "프로필"과 "계정 관리" 두 탭을 다룬다(MUST). 이 스펙은 프로필 탭을 맡고, 계정 관리 탭(회원 탈퇴)은 `018-member-withdrawal` FR-001·FR-016이 맡는다. 로그인 방식(비밀번호 변경)과 소셜 계정 연결·해제는 마이페이지에 두지 않고 계정 설정 화면(`010-social-login` FR-006)과 비밀번호 변경 화면에 둔다
- **FR-003**: 회원은 마이페이지에서 닉네임을 바꿀 수 있어야 한다(MUST). 닉네임은 회원의 표시 이름이다(`010-social-login` FR-005)
  - 앞뒤 공백을 지우고, 지운 뒤 비어 있으면 저장하지 않는다(MUST)
  - 잠정 규칙: 2~12자. 한글·영문·숫자·`_`만 쓴다. 예약어(admin, 운영자, moa 등)는 쓸 수 없다. 예약어 목록은 plan에서 정한다
  - 다른 회원과 겹쳐도 된다(MUST). 대소문자만 다른 닉네임은 같은 닉네임으로 본다 (2026-11-19, 처음 잠정 "겹칠 수 없음"을 정정)
  - 고유 태그(MUST): 회원마다 숫자 4자리 태그(`0001`~`9999`)를 두어 `닉네임#태그`로 구별한다. 같은 닉네임 안에서 태그는 겹치지 않는다
    - 태그는 서버가 정한다: 가입(`010-social-login` FR-005) 또는 프로필이 처음 생길 때, 그 닉네임에서 쓰이지 않은 번호 중 무작위
    - 닉네임을 바꾸면(이 스펙, 관리자의 이름 바꾸기 `002-admin-users` FR-007): 새 닉네임에서 지금 태그가 비어 있으면 그대로, 쓰이고 있으면 새로 정한다. 대소문자만 바꾸면 그대로다
    - 같은 닉네임의 태그가 모두 쓰이면 그 닉네임으로 가입하거나 바꿀 수 없고, 다른 닉네임을 고르라는 안내를 보인다
    - [NEEDS CLARIFICATION: 회원이 태그를 직접 고르거나 태그만 바꿀 수 있는가? 잠정으로 할 수 없다. 팀 확인 필요 (담당: 팀 회의)]
  - 표시·검색·멘션 형식 (잠정): 기본은 닉네임만 보인다. 사람을 골라야 하는 자리(마이페이지·프로필 머리, 회원 검색 결과, 멘션 후보, 사용자 관리)는 `닉네임#0421`로 보인다. 검색은 닉네임 일부(대소문자 무시)로 찾아 결과에 태그를 함께 보이고, `닉네임#0421`을 넣으면 그 회원 하나를 찾는다. 멘션은 `@닉네임#0421`이다. 이 스펙은 형식만 정하고 검색·멘션 기능은 그 기능의 스펙이 만든다
    - [NEEDS CLARIFICATION: 팀 기획안 화면은 `@my_handle`(회원이 정하는 핸들)로 그렸다. 태그 방식(`닉네임#0421`)으로 갈지 팀 확인 필요 (담당: 팀 회의)]
  - 가입(`010-social-login` FR-005)과 변경(이 스펙)이 같은 규칙을 쓴다
  - [NEEDS CLARIFICATION: 위 잠정 규칙(길이·글자·예약어)을 팀이 확인한다. `010-social-login` FR-005와 같은 답으로 맞춘다 (담당: 팀 회의)]
- **FR-004**: 가입 뒤 첫 닉네임 변경은 바로 할 수 있고, 그 뒤로는 바꿀 때마다 30일 동안 다시 바꿀 수 없다(잠정). 기간 안에 바꾸려 하면 저장하지 않고 다시 바꿀 수 있는 날을 보인다
  - 서버가 태그를 새로 정하는 일(FR-003)은 닉네임 변경에 따른 것이라 따로 제한하지 않는다. 대소문자만 바꾸는 것도 닉네임 변경으로 보아 이 제한을 받는다
  - [NEEDS CLARIFICATION: 위 잠정 변경 제한(첫 변경 바로, 그 뒤 30일)을 팀이 확인한다. `010-social-login` FR-005와 같은 답으로 맞춘다 (담당: 팀 회의)]
- **FR-005**: 닉네임이 바뀌면 그 회원의 표시 이름을 보이는 모든 곳(계정 바, 파티 등)이 새 닉네임을 보여야 한다(MUST). 같은 브라우저의 계정 바는 새로고침 없이 바뀐다
- **FR-006**: 회원은 자기소개를 적을 수 있다(MAY). 500자 이내다. 비워 둘 수 있다
- **FR-007**: 회원은 나이와 성별을 적고 공개 또는 비공개를 정할 수 있다(MAY). 비워 둘 수 있다. 처음 공개 여부는 비공개다
  - 잠정: 팀 기획안대로 "공개 여부" 토글 하나로 나이와 성별을 함께 공개·비공개한다
  - [NEEDS CLARIFICATION: 나이와 성별의 공개 여부를 각각 따로 정하게 할 것인가(팀 기획안 "공개범위 개별 관리" 항목)? 팀 확인 필요 (담당: 팀 회의)]
  - 성별은 정해 둔 목록(남성, 여성, 밝히지 않음)에서 고른다
  - 나이는 출생 연도로 받아 저장하고, 화면에는 나이로 보인다(MUST). 미래 연도는 받지 않는다
  - [NEEDS CLARIFICATION: 만 14세 미만 회원은 어떻게 하는가(법정대리인 동의를 받는가, 가입을 막는가)? 가입(`010-social-login`)과 엮이므로 함께 정한다. 팀 확인 필요 (담당: 팀 회의)]
- **FR-008**: 회원은 디스코드 태그를 적고 공개 범위를 고를 수 있다(MAY). 비워 둘 수 있다
  - 디스코드의 새 사용자명 형식이어야 한다(MUST): 2~32자, 영문 소문자·숫자·밑줄(`_`)·마침표(`.`)만, 마침표 두 개를 잇달아 쓸 수 없다. 예전 `이름#1234` 형식은 받지 않는다
  - 공개 범위는 비공개, 친구만, 전체 회원 중 하나다(FR-013, 잠정). 친구의 정의는 `014-friends-follow` FR-004를 따른다. 처음 값은 비공개다
  - 010에서 연결한 디스코드 계정과 잇지 않는다. 회원이 적은 값이며 moa가 확인하지 않는다
- **FR-009**: 회원은 moa가 제공하는 기본 아바타 중 하나를 프로필 사진으로 고를 수 있어야 한다(MUST). 목록 밖의 값은 거부한다. 이미지를 올리는 기능은 두지 않는다(MUST NOT). 고른 적이 없거나 고른 아바타가 목록에서 빠지면 기본 아바타를 보인다
- **FR-010**: 회원은 게임 정보를 최대 3개까지 적을 수 있다(MAY). 게임 정보는 게임마다 하나다. 게임 정보는 게임정보 추가 화면(모달)에서 더한다
  - 게임은 공통코드 `GAME` 그룹에서, 랭크(티어)는 `<게임 코드>_TIER`, 포지션은 `<게임 코드>_POSITION` 그룹에서 고른다(MUST). `008-party` FR-002·FR-022와 같은 코드다. 그 게임의 목록에 없는 값은 거부한다
  - 랭크와 포지션은 고르지 않아도 된다. 포지션 그룹이 없는 게임은 포지션 칸이 없다
  - 게임정보 추가 화면에 "랭크는 직접 입력한 값이라 확인되지 않은 값"이라는 안내를 보인다(MUST). 팀 기획안의 "직접 입력"은 회원이 스스로 적는 값이라는 뜻이고 고르는 목록은 위 공통코드다
  - 마이페이지의 게임 정보 영역에 현재 개수와 최대 개수(예: 1/3)를 보인다(MUST). 3개면 추가 단추를 쓸 수 없다
  - 게임 아이디는 적지 않아도 된다. 50자 이내다
  - 게임 정보는 회원이 적는 값이며 게임 API로 확인하지 않는다(범위 밖, 나중 스펙 "게임 계정 확인")
- **FR-011**: 게임 아이디가 있고 그 게임에 전적 사이트가 정해져 있으면 그 게임 아이디로 만든 전적 사이트 링크를 보여야 한다(MUST). 링크는 새 창에서 열린다. 게임마다 어떤 전적 사이트를 쓰는지는 moa가 정해 두고(예: 리그 오브 레전드는 op.gg) 회원이 바꾸지 않는다
- **FR-012**: 회원은 플레이 가능 시간대를 목록에서 여러 개 고를 수 있다(MAY). 비워 둘 수 있다
  - 처음 목록은 평일 오전, 평일 저녁, 주말 종일, 새벽이다 (팀 기획안)
  - 목록은 공통코드 그룹으로 둔다(MUST). 관리자가 공통코드 화면(`004-admin-codes`)에서 바꿀 수 있다. 그룹 이름은 잠정 `PLAY_TIME`, 코드는 잠정 `WEEKDAY_MORNING` 평일 오전, `WEEKDAY_EVENING` 평일 저녁, `WEEKEND_ALL_DAY` 주말 종일, `DAWN` 새벽이고 plan에서 확정한다
  - 시간대마다 몇 시부터 몇 시까지인지는 정하지 않는다 (팀 기획안에 없음)
- **FR-013**: 다른 회원이 내 프로필을 보는 범위 (잠정)
  - 로그인한 회원만 다른 회원의 프로필을 본다. 로그인하지 않은 사람에게는 보이지 않는다
  - 나이·성별은 공개로 켠 경우에만 보인다 (FR-007)
  - 디스코드 태그는 공개 범위대로 보인다: 비공개는 아무에게도, 친구만은 그 회원의 친구에게만, 전체 회원은 로그인한 회원 모두에게
  - 친구의 정의는 `014-friends-follow` FR-004(요청과 수락으로 맺는 양방향 관계)를 따른다. 팔로워에게는 보이지 않는다 (014 FR-015)
  - [NEEDS CLARIFICATION: 친구 기능(`014-friends-follow`)이 생기기 전에도 "친구만" 단계를 고를 수 있게 할 것인가(지금 고르면 아무에게도 보이지 않는다)? 팀 확인 필요 (담당: 팀 회의)]
  - 닉네임, 아바타, 자기소개, 게임 정보, 시간대는 로그인한 회원 모두에게 보인다
  - 다른 회원 프로필을 어느 화면(파티 멤버 목록 등)에서 여는지는 이 스펙 범위 밖이다. 이 스펙은 보이는 규칙만 정하고, 그 화면을 만드는 기능이 이 규칙을 따른다
  - [NEEDS CLARIFICATION: 위 잠정 범위(로그인한 회원만, 나이·성별 공개 선택, 디스코드 태그 3단계)를 팀이 확인한다 (담당: 팀 회의)]
- **FR-014**: 계정 바(사이드바 바닥의 계정 줄과 톱니 메뉴, `001-admin-menus` FR-005)는 이름 자리에 닉네임을 보여야 한다(MUST). 회원에게는 로그인 아이디를 보이지 않는다(MUST). 아바타를 고른 회원은 계정 바에도 그 아바타를 보인다. 톱니 메뉴에 "마이페이지" 항목을 더한다(MUST). 관리자·운영자 계정에는 "마이페이지" 항목을 보이지 않는다(FR-016). 닉네임 표시는 모든 계정에 같다
  - 관리자·운영자 계정의 아이디 줄은 `001-admin-menus` FR-005(2026-11-22)대로 둔다. 소셜 회원(비밀번호 없는 계정)의 아이디 줄과 "비밀번호 변경"은 `010-social-login` US2-AC3이 이미 숨긴다 (2026-11-22, 계정 메뉴가 계정 바로 바뀌어 고침)
  - 계정 바(`account-bar.tsx`)는 관리 셸과 사용자 셸이 함께 쓰는 셸 파일이다. 구현 때 바꿀 내용을 먼저 보고하고 승인받는다
- **FR-015**: 마이페이지는 계정 바 톱니 메뉴로 여는 계정 화면이다(MUST). 사이드바 메뉴로 열지 않으므로 프로그램으로 등록하지 않는다(`001-admin-menus` FR-008 "메뉴로 열지 않는 화면(공지 상세, 계정 화면 등)은 프로그램으로 등록하지 않는다"). 다른 계정 화면처럼 관리 메뉴가 있는 사용자에게는 관리 셸, 없는 사용자에게는 사용자 셸 안에서 열린다(`001-admin-menus` FR-005). 관리자·운영자는 마이페이지를 쓰지 않으므로(FR-016) 실제로는 사용자 셸에서만 열린다
- **FR-016**: 관리자·운영자 계정(`ADMIN` 계정. 회원(`USER`)은 업무 역할을 받지 않으므로 업무 역할을 가진 계정도 `ADMIN` 계정이다, `003-admin-roles` FR-002·`specs/README.md`, 2026-11-22. `010-social-login` FR-007과 같은 정의)은 마이페이지를 쓰지 않는다(MUST)
  - 계정 바 톱니 메뉴에 "마이페이지"가 보이지 않는다
  - 마이페이지 주소로 들어오거나 프로필을 고치려 하면 막고 권한이 없다는 안내를 보인다(`001-admin-menus` FR-003)
  - 근거: `002-admin-users`와 `010-social-login` FR-007의 "관리자·운영자는 회원 활동을 하지 않는다"
- **FR-017**: 프로필 편집 화면은 닉네임을 필수로, 자기소개·나이·성별·디스코드 태그·플레이 가능 시간대를 선택으로 표시해야 한다(MUST) (팀 기획안). 아바타와 게임 정보는 각자 고르는 곳(FR-009, FR-010)에서 다룬다

### Key Entities *(include if feature involves data)*

- **회원**: 키트 `tb_user`. 닉네임은 표시 이름이다(`010-social-login` FR-005). 닉네임은 겹칠 수 있고 회원은 `닉네임#태그`로 구별한다(FR-003). 가입 뒤 닉네임을 바꾼 적이 있는지와 마지막으로 바꾼 시각을 안다(FR-004)
- **프로필**: 회원 하나에 하나. 아바타(기본 아바타 목록의 키), 자기소개, 출생 연도, 성별, 나이·성별 공개 여부(하나, 잠정), 디스코드 태그와 공개 범위, 플레이 가능 시간대(공통코드, 여러 개)
- **게임 정보**: 회원 하나에 최대 3개, 게임마다 하나. 게임 코드, 랭크(티어) 코드, 포지션 코드, 게임 아이디
- **기본 아바타 목록**: moa가 정해 둔 이미지 묶음. 회원이 더하거나 올릴 수 없다
- **전적 사이트**: 게임마다 moa가 정해 둔 링크 규칙. 회원이 바꿀 수 없다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원이 계정 바에서 마이페이지로 들어가 닉네임을 바꾸고 저장을 마치기까지 30초 안에 끝난다
- **SC-002**: 닉네임이나 아바타를 저장하면 같은 브라우저의 계정 바에 새로고침 없이 바로 보인다
- **SC-003**: 규칙에 맞지 않는 값(빈 닉네임, 글자 수 초과, 예약어·태그가 다 찬 닉네임, 미래 출생 연도, 디스코드 형식 오류, 목록 밖의 게임·랭크·포지션·시간대·아바타, 넷째 게임)을 저장하려는 시도는 하나도 저장되지 않고 어느 칸이 잘못됐는지 보인다
- **SC-004**: 회원에게는 계정 바와 마이페이지 어디에도 로그인 아이디가 보이지 않는다
- **SC-005**: 수용 시나리오(US1~US6) 전부가 자동 테스트로 확인된다 (원칙 II)
- **SC-006**: 관리자·운영자 계정은 어떤 경로로도 마이페이지를 열거나 프로필을 고칠 수 없다

## Assumptions

- 마이페이지는 관리자·운영자가 아닌 로그인한 회원이 쓴다 (FR-016)
- 아이디·비밀번호 회원(시드 등)의 닉네임은 지금 이름(`name`)이다. 관리자·운영자가 아니면 마이페이지에서 바꿀 수 있다. 그 사람들의 처음 표시 이름은 `010-social-login` FR-005의 질문을 따른다
- 기본 아바타의 그림과 개수는 이 스펙이 정하지 않는다. 구현 전에 정한다
- 게임마다 쓸 전적 사이트와 링크 규칙(예: 리그 오브 레전드 op.gg)은 plan에서 정한다. 정해지지 않은 게임은 링크를 보이지 않는다
- 보이는 나이는 "올해 − 출생 연도"로 계산한다(생일을 받지 않으므로 연 나이)
- 자기소개 500자, 게임 아이디 50자, 성별 목록은 이 스펙의 기본값이다. 바꾸면 이 스펙을 고친다. 플레이 가능 시간대 목록은 공통코드라 스펙을 고치지 않고 바꿀 수 있다(FR-012)
- 게임 정보의 랭크는 회원이 적는 값이다. 파티 참가 때 적는 티어(`008-party`)와 이어지지 않는다. 잇는 일은 나중 스펙("게임 계정 확인" 또는 파티 스펙)이 정한다
- 회원 탈퇴(30일 유예·복구·완전 삭제)와 활동 기록은 이 스펙의 범위가 아니다. 탈퇴할 때 프로필·게임 정보를 어떻게 지울지는 회원 탈퇴 스펙이 정한다
- 프로필 이미지 올리기와 게임 API 계정·랭크 확인은 범위 밖이다
- 나중에 고칠 곳: 이번 단계에서는 다른 스펙을 고치지 않는다. [NEEDS CLARIFICATION]이 풀리거나 이 기능을 구현할 때 아래를 함께 고친다
  - `001-admin-menus` FR-005: 계정 화면 목록(알림, 설정, 비밀번호 변경)에 마이페이지를 더하고, 계정 바 톱니 메뉴(화면 모드, 언어, 설정, 비밀번호 변경)의 설정 앞에 마이페이지 항목의 자리를 더한다. 계정 바의 아바타 표시와 회원의 아이디 줄 숨김을 적는다 (FR-014). FR-008 프로그램 표는 고칠 것 없음 (FR-015)
  - `002-admin-users` FR-004·FR-007: 사용자 관리 목록·드로어에 닉네임·아바타를 보일지, 드로어의 "이름 바꾸기"를 닉네임 바꾸기로 볼지와 같은 닉네임 규칙(FR-003)·변경 제한(FR-004)을 적용할지. 관리자·운영자는 마이페이지를 쓰지 않으므로(FR-016) 그 계정의 이름은 드로어로만 바뀐다. 사용자 관리에서 이름을 바꿀 때 tb_user_profile의 `nickname_key`도 함께 바꾸고 태그를 FR-003대로 맞춘다(겹쳐도 막지 않음, research R14). 사용자 관리 목록·드로어는 `닉네임#태그`로 보인다(FR-003 표시 형식)
  - `008-party` FR-027과 가정 "닉네임은 회원 가입·프로필에서 정한다", "나중에 프로필에 게임 계정을 연동해 티어를 가져오면": 표시 이름은 닉네임이고 마이페이지에서 바뀐다(FR-005). 프로필의 게임 랭크는 회원이 적는 값이며 연동은 나중 스펙이다. 다른 회원 프로필을 파티 화면에서 보일지는 008이 정하고 FR-013의 보이는 규칙을 따른다. 팀 공유 필요 (담당: 008-party 담당)

# Quickstart: 소셜 로그인 (010) 확인 안내

구현 뒤 기능이 스펙대로 도는지 확인하는 순서다. 구현 코드는 tasks 단계에서 정한다.

## 준비

1. 구글 클라우드 콘솔에서 OAuth 클라이언트(웹 애플리케이션)를 만들고, 승인된 리디렉션 URI에 `http://localhost:3000/api/v1/auth/oauth/google/callback`을 넣는다
2. 디스코드 개발자 포털에서 애플리케이션을 만들고, OAuth2 Redirects에 `http://localhost:3000/api/v1/auth/oauth/discord/callback`을 넣는다
3. `backend/.env.local`에 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI`, `SOCIAL_REJOIN_HASH_SECRET`을 넣는다 (이름은 `backend/.env.example` 참고. 값은 레포에 넣지 않는다. 재가입 해시 비밀 값은 한번 정하면 바꾸지 않는다)
4. 백엔드 `backend/`에서 `.\gradlew.bat bootRun`, 프론트 `frontend/`에서 `npm run dev`
5. 칸 추가 뒤 프론트 타입: `npm run gen:api`

## 수동 확인 (스펙 AC와 대응)

| 순서 | 할 일 | 기대 결과 | AC |
|---|---|---|---|
| 1 | 디스코드 설정만 빼고 백엔드를 띄우고 `/sign-in` | 구글 단추만 있음, 아이디 로그인 됨 | US3-AC3 |
| 2 | 두 설정을 넣고 `/sign-in` → 구글로 계속하기 → 처음 쓰는 구글 계정 | 닉네임·약관 화면 → 넣고 둘 다 체크하면 `/`, 닉네임이 보임 | US1-AC1·AC3 |
| 3 | 2와 같이 하되 약관 하나를 체크하지 않음 | 제출할 수 없음. 약관 요약을 펼치면 전문 | US1-AC7 |
| 4 | 2에서 가입한 회원의 `tb_user_terms_agreement`를 DB에서 봄 | 두 행, 버전과 동의 시각 | US1-AC8 |
| 5 | 2를 닉네임 화면에서 닫고 다시 구글 로그인 | 닉네임 화면부터 다시, 사용자 관리에 회원 없음 | US1-AC5 |
| 6 | 처음 쓰는 디스코드 계정(이메일 인증됨, 2와 다른 이메일)으로 가입 | 2와 같이 가입됨 | US1-AC1 |
| 7 | 이메일 인증을 하지 않은 디스코드 계정으로 로그인 | "제공자에서 이메일 인증 후 다시 시도", 회원 없음 | US1-AC12 |
| 8 | 2의 구글과 같은 이메일을 쓰는 디스코드 계정으로 로그인 | "다른 방식으로 가입된 이메일", 회원 없음 | US1-AC9 |
| 9 | 2의 회원으로 설정 → 8의 디스코드 연결 | 연결됨 (본인 이메일) | US5-AC8 |
| 10 | 처음 쓰는 소셜 계정의 해시로 `tb_social_rejoin_block`에 미래 시각 행을 넣고 그 계정으로 로그인 | 재가입 제한 안내, 회원 없음. 행의 시각을 과거로 바꾸면 가입됨 | US1-AC10 |
| 11 | 10의 행 시각을 비우고(영구) 로그인 | 막힘 | US1-AC11 |
| 12 | 로그아웃 뒤 2의 구글 계정으로 다시 | 닉네임 없이 바로 로그인, 회원 수 그대로 | US2-AC1 |
| 13 | 소셜 회원으로 계정 바와 톱니 메뉴 | 아이디 줄과 "비밀번호 변경" 없음 | US2-AC3 |
| 14 | `admin`으로 사용자 관리 | 그 회원이 `USER`, 비밀번호 없음, `ADMIN` 주기 막힘 | US1-AC2·AC6 |
| 15 | `user`(비밀번호 있음)로 설정 → 구글 연결 → 로그아웃 → 구글 로그인 | `user` 계정으로 로그인 | US5-AC1·AC2 |
| 16 | 15에서 해제 | 연결 안 됨, 그 구글로 로그인하면 닉네임 화면(새 회원) | US5-AC5 |
| 17 | `user`로 설정 → 7의 미인증 디스코드 연결 | 연결 안 됨, 이메일 인증 안내 | US5-AC10 |
| 18 | `user`로 설정 → 10의 제한 계정 연결 | 연결 안 됨, 재가입 제한 안내 | US5-AC9 |
| 19 | 6의 디스코드 회원(비밀번호 없음, 연결 1개)으로 설정 → 해제 | 막힘 안내 | US5-AC6 |
| 20 | `admin`으로 설정 | 소셜 연결 줄 없음 | US5-AC7 |
| 21 | 제공자 화면에서 취소 | 로그인 화면, 안내 없음 | US3-AC1 |
| 22 | `admin`으로 접속 이력 | 소셜 로그인 성공·실패가 보임 (표시 방식은 미정) | US4-AC1 |

## 자동 검사

- 빠른 검사: 백엔드 `.\gradlew.bat build`, 프론트 `npm run check`
- 인수 테스트(`*SocialLoginAcceptanceTest`, 원칙 II: AC마다 하나, 이름에 AC 번호)는 제공자를 실제로 부르지 않도록 제공자 클라이언트(R2 경계)를 제공자마다 테스트용 가짜로 바꿔 돈다. 재가입 제한 행은 테스트가 직접 넣는다. 로컬에서는 돌리지 않고 PR CI로 본다 (CLAUDE.md)
- e2e는 핵심 흐름(US1 가입)만, 제공자 가짜를 쓴다

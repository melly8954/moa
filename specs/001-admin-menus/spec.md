# Feature Specification: 관리 메뉴와 접근 (admin-menus)

**Feature Branch**: `feat/001-admin-menus`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "백오피스의 관리 메뉴 구성과 순서를 정하고, 권한이 없는 사용자는 관리 메뉴를 보지 못하고 관리 화면에 들어오지 못하게 한다."

**출처**: psw-dev-kit springboot menu 헬퍼와 admin 프리셋의 메뉴 시드. 태그 `springboot/v0.3.1`, 화면은 `web-next/v0.3.0`.
키트 동작(메뉴 트리 관리, 내 메뉴, 권한 판정)은 키트 문서와 키트 수용 테스트가 기준이다 (원칙 III).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자가 관리 메뉴를 본다 (Priority: P1)

관리자가 백오피스에 들어가면 관리 메뉴 5개를 사이드바 최상위에서 정해진 순서로 보고, 각 화면을 열 수 있다.

**Why this priority**: 백오피스의 첫 화면이다. 다른 관리 기능을 얹을 자리다.

**Independent Test**: 관리자로 로그인해 백오피스에 들어가 메뉴와 각 화면을 확인한다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 관리자가 로그인했다, **When** 백오피스에 들어간다, **Then** 묶음 그룹 없이 사이드바 최상위에 사용자 관리, 메뉴 관리, 코드 관리, 접속 이력, 역할 관리가 이 순서로 보인다
2. **US1-AC2** **Given** 관리자가 로그인했다, **When** 관리 메뉴 5개를 하나씩 연다, **Then** 모든 화면의 목록이 보인다

---

### User Story 2 - 권한이 없는 사용자는 백오피스에 들어오지 못한다 (Priority: P1)

일반 회원과 로그인하지 않은 사용자는 관리 메뉴를 보지 못하고, 관리 화면 주소로 직접 들어와도 막힌다.

**Why this priority**: 백오피스를 여는 순간부터 지켜져야 하는 보안 경계다.

**Independent Test**: 일반 회원과 비로그인 상태로 메뉴와 관리 화면 주소를 확인한다.

**Acceptance Scenarios**:

1. **US2-AC1** **Given** 일반 회원이 로그인했다, **When** 메뉴를 본다, **Then** 관리 메뉴가 보이지 않는다
2. **US2-AC2** **Given** 일반 회원이 로그인했다, **When** 관리 화면 주소로 직접 들어가거나 관리 기능을 쓰려 한다, **Then** 권한이 없다는 안내와 함께 막힌다
3. **US2-AC3** **Given** 로그인하지 않았다, **When** 관리 화면 주소로 들어간다, **Then** 로그인하라는 안내와 함께 막힌다

---

### Edge Cases

- 관리 메뉴 중 일부 권한만 가진 사용자: 권한이 있는 메뉴만 최상위에 보인다. 하나도 없으면 관리 메뉴가 하나도 보이지 않는다 (키트 메뉴 동작)
- 관리자가 메뉴 관리에서 메뉴를 끄거나 순서를 바꾸면: 다음 조회부터 바뀐 대로 보인다 (키트 메뉴 동작). 이 스펙의 순서는 처음 배포할 때의 구성이다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 처음 배포할 때 관리 메뉴는 묶음 그룹 없이 사이드바 최상위에 아래 표의 순서와 권한으로 구성되어야 한다(MUST). 홈은 프론트 메뉴 정의에 있어 이 표보다 앞에 온다

  | 순서 | 메뉴 | 필요한 권한 | 스펙 |
  |---|---|---|---|
  | 1 | 사용자 관리 | 사용자 관리 | `002-admin-users` |
  | 2 | 메뉴 관리 | 메뉴 관리 | 이 스펙 |
  | 3 | 코드 관리 | 코드 관리 | `004-admin-codes` |
  | 4 | 접속 이력 | 접속 이력 조회 | `005-admin-login-history` |
  | 5 | 역할 관리 | 역할 관리 | `003-admin-roles` |

- **FR-002**: 관리 메뉴는 그 메뉴의 권한을 가진 사용자에게만 보여야 한다(MUST). 관리자는 모든 권한을 갖는다
- **FR-003**: 권한이 없는 사용자가 관리 화면이나 관리 기능에 접근하면 막아야 한다(MUST). 로그인하지 않았으면 로그인 안내, 로그인했으면 권한 없음 안내를 보인다
- **FR-004**: moa 관리 기능(신고, 제재, 게임, 복구)은 기능이 정해질 때까지 메뉴에 넣지 않는다. 넣을 때는 그 기능의 스펙에 메뉴 위치와 권한을 적고 FR-001 표에 더한다

### Key Entities *(include if feature involves data)*

- **관리 메뉴**: 백오피스 사이드바의 항목. 이름, 화면 경로, 순서, 보는 데 필요한 권한을 가진다. 그룹으로 묶지 않고 최상위에 둔다
- **권한**: 관리 기능 하나를 쓸 수 있는 자격. 관리 메뉴마다 하나씩 있다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 로그인 직후 추가 설정 없이 관리 메뉴 5개를 쓸 수 있다
- **SC-002**: 일반 회원과 로그인하지 않은 사용자의 관리 화면·관리 기능 접근은 100% 막힌다
- **SC-003**: 수용 시나리오(US1~US2) 전부가 자동 테스트로 확인된다 (원칙 II)

## Assumptions

- 관리자 화면(프론트)은 프론트 키트(web-next admin 프리셋)가 만드는 admin 화면을 쓴다
- 키트 admin 프리셋의 기본 시드는 관리 메뉴를 "관리" 그룹 아래에 둔다. moa는 그 그룹을 없애고 메뉴를 최상위로 옮긴다. 순서와 권한은 키트 시드와 같다
  - 배경 (2026-11-14): 백오피스 메뉴가 모두 관리 기능이라 "관리" 한 단계로 묶는 의미가 없다

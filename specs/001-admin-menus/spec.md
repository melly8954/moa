# Feature Specification: 관리 메뉴와 접근 (admin-menus)

**Feature Branch**: `feat/001-admin-menus`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "백오피스의 관리 메뉴 구성과 순서를 정하고, 권한이 없는 사용자는 관리 메뉴를 보지 못하고 관리 화면에 들어오지 못하게 한다."

**출처**: psw-dev-kit springboot menu 헬퍼와 admin 프리셋의 메뉴 시드. 태그 `springboot/v0.3.1`, 화면은 `web-next/v0.3.0`.
키트 동작(메뉴 트리 관리, 내 메뉴, 권한 판정)은 키트 문서와 키트 수용 테스트가 기준이다 (원칙 III).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자가 관리 메뉴를 본다 (Priority: P1)

관리자가 백오피스에 들어가면 관리 메뉴 7개를 사이드바의 "운영"·"설정" 상위 메뉴 아래에서 정해진 순서로 보고, 각 화면을 열 수 있다.

**Why this priority**: 백오피스의 첫 화면이다. 다른 관리 기능을 얹을 자리다.

**Independent Test**: 관리자로 로그인해 백오피스에 들어가 메뉴와 각 화면을 확인한다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 관리자가 로그인했다, **When** 백오피스에 들어간다, **Then** 첫 관리 메뉴(사용자 관리) 화면이 열리고, 사이드바에 "운영"·"설정" 상위 메뉴만 이 순서로 보인다(홈과 사용자 화면 메뉴는 없다). 지금 화면이 있는 "운영"은 펴져 사용자 관리, 공지 관리, 접속 이력, 파기 기록이 보이고, 접힌 "설정"을 펴면 역할 관리, 메뉴 관리, 코드 관리가 이 순서로 보인다
2. **US1-AC2** **Given** 관리자가 로그인했다, **When** 관리 메뉴 7개를 하나씩 연다, **Then** 모든 화면의 목록이 보인다
3. **US1-AC3** **Given** 관리자가 넓은 폭에서 관리 화면을 본다, **When** 사이드바 맨 위 로고 옆 접기 단추를 누르고 다시 로고 자리의 펼치기 단추를 누른다, **Then** 본문 위에 머리 줄이 없고, 사이드바가 아이콘만 남게 접혔다가 다시 펼쳐진다
4. **US1-AC4** **Given** 관리자가 사용자 관리 화면을 본다, **When** 접힌 "설정" 상위 메뉴를 눌러 펴고 새로 고친다, **Then** "설정"이 펴진 채다. 다시 눌러 접고 새로 고치면 접힌 채다
5. **US1-AC5** **Given** 상위 메뉴를 펴거나 접은 적이 없다, **When** 상위 메뉴 안의 화면 주소(메뉴 관리)로 바로 들어간다, **Then** 그 화면이 있는 "설정"만 펴져 메뉴 관리가 지금 화면으로 표시되고, "운영"은 접혀 있다
6. **US1-AC6** **Given** 관리자가 사용자 관리 화면에서 "운영" 상위 메뉴를 눌러 접었다, **When** 새로 고친다, **Then** 지금 화면이 그 안에 있어도 "운영"은 접힌 채다
7. **US1-AC7** **Given** 관리자가 넓은 폭에서 사이드바를 아이콘만 남게 접었다, **When** "설정" 상위 메뉴 아이콘을 누른다, **Then** 사이드바가 펼쳐지고 "설정"이 펴진다
8. **US1-AC8** **Given** 관리자가 사용자 관리 화면에서 "운영"을 펴거나 접은 적이 없다(지금 화면이라 펴져 있다), **When** "설정"을 펴고 메뉴 관리로 간다, **Then** "운영"도 펴진 채다(지나온 상위 메뉴가 저절로 접히지 않는다)

### User Story 2 - 권한이 없는 사용자는 백오피스에 들어오지 못한다 (Priority: P1)

일반 회원과 로그인하지 않은 사용자는 관리 메뉴를 보지 못하고, 관리 화면 주소로 직접 들어와도 막힌다.

**Why this priority**: 백오피스를 여는 순간부터 지켜져야 하는 보안 경계다.

**Independent Test**: 일반 회원과 비로그인 상태로 메뉴와 관리 화면 주소를 확인한다.

**Acceptance Scenarios**:

1. **US2-AC1** **Given** 일반 회원이 로그인했다, **When** 메뉴를 본다, **Then** 사용자 셸에 있고 관리 메뉴가 보이지 않는다
2. **US2-AC2** **Given** 일반 회원이 로그인했다, **When** 관리 화면 주소로 직접 들어가거나 관리 기능을 쓰려 한다, **Then** 권한이 없다는 안내와 함께 막힌다
3. **US2-AC3** **Given** 로그인하지 않았다, **When** 관리 화면 주소로 들어간다, **Then** 로그인하라는 안내와 함께 막힌다
4. **US2-AC4** **Given** 일반 회원이다, **When** 로그인한다, **Then** 사용자 셸의 첫 화면이 열리고 사이드바에 홈, 공지가 보인다

---

### User Story 3 - 관리자가 사용자 화면 메뉴도 메뉴 관리에서 다룬다 (Priority: P2)

관리자는 메뉴 관리에서 메뉴마다 대상(관리자, 사용자)을 정하고, 사용자 셸에 보일 메뉴를 코드 수정 없이 더하고 끄고 순서를 바꾼다.
사용자 메뉴는 공개 범위(누구나, 회원만)로 누구에게 보일지 정한다.

**Why this priority**: 사용자 화면 메뉴가 늘어날 때 배포 없이 다룰 수 있게 한다. 지금 사용자 메뉴는 홈·공지 둘이라 P1 셸 나누기보다 뒤다.

**Independent Test**: 메뉴 관리에서 사용자 메뉴를 하나 더하고 끈 뒤, 일반 회원과 로그인하지 않은 사람의 사용자 셸 사이드바를 본다.

**Acceptance Scenarios**:

1. **US3-AC1** **Given** 관리자가 메뉴 관리를 연다, **When** 메뉴 목록을 본다, **Then** 관리 메뉴와 사용자 메뉴(홈, 공지)가 대상으로 나뉘어 보인다
2. **US3-AC2** **Given** 관리자가 대상이 사용자인 메뉴를 공개 범위 "누구나"로 더했다, **When** 일반 회원이나 로그인하지 않은 사람이 사용자 셸을 연다, **Then** 사이드바에 그 메뉴가 보이고 관리 셸에는 보이지 않는다
3. **US3-AC3** **Given** 사용자 메뉴가 있다, **When** 관리자가 그 메뉴를 끈다, **Then** 사용자 셸 사이드바에서 빠진다
4. **US3-AC4** **Given** 관리자가 대상이 관리자인 메뉴를 더했다, **When** 일반 회원이 메뉴를 본다, **Then** 그 메뉴가 보이지 않는다
5. **US3-AC5** **Given** 관리자가 대상이 사용자인 메뉴를 공개 범위 "회원만"으로 더했다, **When** 로그인하지 않은 사람과 일반 회원이 사용자 셸을 연다, **Then** 로그인하지 않은 사람의 사이드바에는 없고 일반 회원의 사이드바에는 보인다

---

### User Story 4 - 관리자는 등록된 연결 화면을 골라 메뉴를 만든다 (Priority: P2)

관리자는 메뉴를 만들거나 고칠 때 코드에 등록된 연결 화면을 선택 상자에서 고른다. 연결 화면 목록을 따로 보여 주는 화면은 없다.
경로와 권한 키를 직접 입력하지 않는다. 관리 메뉴의 권한은 고른 연결 화면을 따른다.

**Why this priority**: 경로와 권한 키를 직접 입력하는 방식은 키 이름을 아는 사람만 쓸 수 있고, 잘못 넣기 쉽다. 메뉴를 다룰 일이 생기기 전에 바로잡는다.

**Independent Test**: 메뉴 관리에서 연결 화면을 골라 관리 메뉴와 사용자 메뉴를 하나씩 만든다.

**Acceptance Scenarios**:

1. **US4-AC1** **Given** 관리자가 메뉴 상세 칸에서 연결 화면 선택 상자를 연다, **When** 연결 화면을 본다, **Then** 등록된 연결 화면이 이름과 경로로 보이고, 고르면 필요한 권한(관리 연결 화면) 또는 로그인 필요 여부(사용자 연결 화면)가 함께 보인다. 연결 화면을 더하거나 고치는 곳은 없다
2. **US4-AC2** **Given** 관리자가 관리 메뉴를 만든다, **When** 연결 화면을 고른다, **Then** 대상이 관리자인 연결 화면만 고를 수 있고, 경로와 필요한 권한은 고른 연결 화면의 값으로 보이며 입력 칸이 없다
3. **US4-AC3** **Given** 관리자가 사용자 메뉴를 만든다, **When** 로그인이 필요한 연결 화면을 고른다, **Then** 공개 범위는 "회원만"만 고를 수 있다
4. **US4-AC4** **Given** 관리자가 연결 화면 "코드 관리"를 고른 관리 메뉴를 상위 메뉴 아래에 더했다, **When** 코드 관리 권한만 받은 운영자가 관리 셸을 연다, **Then** 상위 메뉴와 그 아래 메뉴가 보이고 누르면 코드 관리 화면이 열린다
5. **US4-AC5** **Given** 관리자가 연결 화면 없이 상위 메뉴를 만든다, **When** 저장한다, **Then** 저장되고, 보이는 하위 메뉴가 없으면 사이드바에 보이지 않는다

---

### User Story 5 - 관리자는 메뉴 트리를 두 칸 화면에서 고르고 끌어 정리한다 (Priority: P2)

관리자는 메뉴 관리에서 왼쪽에 대상별 메뉴 트리 전체를 보고, 끌어서 순서와 상위 메뉴를 바꾸고, 체크박스로 여러 메뉴를 한꺼번에 켜고 끄고 옮기고 지운다.
메뉴 하나를 고치려면 그 행을 눌러 오른쪽 상세 칸에서 고친다. 행마다 붙은 단추는 없다. 상세 칸은 늘 열려 있어, 다른 메뉴를 누르면 바로 그 메뉴로 바뀐다.

**Why this priority**: 메뉴가 상위 메뉴로 나뉘면 행마다 위·아래·수정·삭제 단추를 두는 방식으로는 상위 메뉴 사이를 옮기기 어렵고 표가 단추로 가득 찬다. 드로어는 트리를 가리고 메뉴마다 열고 닫아야 해, 여러 메뉴를 이어서 고치기 어렵다 (2026-11-20).

**Independent Test**: 메뉴 관리에서 메뉴 둘을 이어서 눌러 오른쪽 칸에서 고치고, 메뉴를 끌어 다른 상위 메뉴로 옮기고, 여러 메뉴를 골라 끈 뒤, 사이드바를 확인한다.

**Acceptance Scenarios**:

1. **US5-AC1** **Given** 관리자가 넓은 폭에서 메뉴 관리를 연다, **When** 관리자 메뉴 탭을 본다, **Then** 왼쪽에 상위 메뉴 아래 하위 메뉴가 들여쓰기된 트리가 쪽 나눔 없이 전체로 보이고, 행마다 체크박스·끌기 손잡이·메뉴명·사용 여부만 있고 단추는 없다. 사용 안 함은 회색이다. 오른쪽 칸에는 메뉴를 고르라는 안내가 보인다
2. **US5-AC2** **Given** 같은 화면이다, **When** 메뉴 행(체크박스·손잡이 밖)을 누른다, **Then** 오른쪽 칸에 메뉴명·아이콘·상위 메뉴·연결 화면·공개 범위·사용 여부가 보이고 그 행이 강조된다. "종류" 칸은 없다. 고쳐 저장하면 트리와 사이드바에 반영된다
3. **US5-AC3** **Given** 같은 화면이다, **When** "접속 이력"을 끌어 "설정" 상위 메뉴 안으로 옮긴다(또는 키보드로 같은 일을 한다), **Then** 저장되고 다음 조회부터 사이드바의 "설정" 아래에 보인다
4. **US5-AC4** **Given** 같은 화면이다, **When** 메뉴 둘을 체크하고 "사용 안 함"을 누른다, **Then** 두 메뉴가 모두 꺼지고 사이드바에서 빠진다. "상위 메뉴로 옮기기"는 고른 메뉴를 고른 상위 메뉴 아래로, "삭제"는 확인을 받은 뒤 지운다. 일괄 처리 줄은 고르기 전후에 같은 자리·높이다
5. **US5-AC5** **Given** 하위 메뉴가 있는 상위 메뉴와 다른 메뉴를 함께 체크했다, **When** "삭제"를 누른다, **Then** 아무것도 지워지지 않고 하위 메뉴가 있는 상위 메뉴 때문이라는 안내가 보인다
6. **US5-AC6** **Given** 같은 화면이다, **When** "메뉴 추가"를 누르고 상위 메뉴를 "없음(맨 위)"로 둔 채 연결 화면을 비우고 저장한다, **Then** 하위 메뉴를 담을 상위 메뉴가 맨 위에 생긴다. 상위 메뉴로 "운영"을 고르면 연결 화면을 골라야 저장된다
7. **US5-AC7** **Given** 오른쪽 칸에서 메뉴 이름을 고치고 저장하지 않았다, **When** 다른 메뉴를 누른다, **Then** 저장하지 않은 변경을 버릴지 묻고, 그만두면 고치던 메뉴가 그대로 남는다
8. **US5-AC8** **Given** 1024px보다 좁은 폭이다, **When** 메뉴 행을 누른다, **Then** 트리 하나만 보이던 화면에서 상세가 드로어로 열린다

### Edge Cases

- 관리 메뉴 중 일부 권한만 가진 사용자: 권한이 있는 메뉴만 최상위에 보인다. 하나도 없으면 관리 메뉴가 하나도 보이지 않는다 (키트 메뉴 동작)
- 관리자가 메뉴 관리에서 메뉴를 끄거나 순서를 바꾸면: 다음 조회부터 바뀐 대로 보인다 (키트 메뉴 동작). 이 스펙의 순서는 처음 배포할 때의 구성이다
- 관리자·운영자가 사용자 화면 주소(공지 등)로 들어가면: 사용자 셸로 보인다. 관리 셸에서 사용자 화면으로 가는 메뉴는 두지 않는다
- 운영자의 관리 권한을 모두 빼면: 다음 로그인부터 관리 메뉴가 없는 사용자로 사용자 셸 첫 화면에 간다
- 메뉴 관리에서 메뉴의 대상을 바꾸면: 다음 조회부터 다른 셸에 보인다. 하위 메뉴가 있는 메뉴는 대상을 바꿀 수 없다(하위 메뉴의 연결 화면이 원래 대상이다). 하위 메뉴를 먼저 옮기거나 지운다
- 사용자 메뉴를 모두 끄면: 사용자 셸 사이드바에 메뉴가 없다. 화면 주소로 직접 들어가는 것은 막지 않는다
- 메뉴의 공개 범위와 권한은 사이드바에 보일지만 정한다: 화면과 API에 들어올 수 있는지는 코드가 정한다(API의 권한·공개 표시, 로그인이 필요한 화면 묶음). 메뉴를 숨겨도 주소로 들어가는 것은 그대로다
- 같은 연결 화면을 여러 메뉴에 걸면: 모두 같은 화면으로 가고, 보이는 조건(권한, 공개 범위)도 같은 규칙을 따른다
- 코드에서 연결 화면이 빠지면: 그 연결 화면을 가리키던 메뉴는 사이드바에 보이지 않고, 메뉴 관리에는 "없는 화면"으로 표시되어 관리자가 다른 연결 화면으로 바꾸거나 지운다
- 메뉴의 대상을 바꾸면: 대상이 다른 연결 화면을 가리키는 메뉴는 바꿀 수 없다. 연결 화면을 먼저 바꾼다. 하위 메뉴를 대상이 다른 상위 메뉴 아래로 옮기는 것도 같은 이유로 막는다
- 브라우저 저장소를 쓸 수 없으면(사생활 보호 창 등): 상위 메뉴를 펴고 접을 수는 있고, 새로 고치면 처음 상태(지금 화면이 있는 상위 메뉴만 펴짐)로 돌아간다. 다른 상위 메뉴의 화면으로 옮기면 지나온 상위 메뉴가 접힐 수 있다
- 메뉴 관리에서 상위 메뉴 이름을 바꾸면: 펴고 접은 상태는 그대로다(메뉴별로 기억한다). 상위 메뉴를 지우면 그 기억은 쓰이지 않는다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 처음 배포할 때 관리 메뉴는 아래 표의 상위 메뉴·순서·연결 화면으로 구성되어야 한다(MUST). 관리 셸 사이드바에는 관리 메뉴만 둔다(홈과 사용자 화면 메뉴를 두지 않는다)
  - "운영"은 매일 쓰는 화면, "설정"은 가끔 정하는 화면이다

  | 상위 메뉴 | 순서 | 메뉴 | 연결 화면 (FR-008) | 스펙 |
  |---|---|---|---|---|
  | 운영 | 1 | 사용자 관리 | 사용자 관리 | `002-admin-users` |
  | 운영 | 2 | 공지 관리 | 공지 관리 | `006-notices` |
  | 운영 | 3 | 접속 이력 | 접속 이력 | `005-admin-login-history` |
  | 운영 | 4 | 파기 기록 | 파기 기록 | `013-purge-log` |
  | 설정 | 1 | 역할 관리 | 역할 관리 | `003-admin-roles` |
  | 설정 | 2 | 메뉴 관리 | 메뉴 관리 | 이 스펙 |
  | 설정 | 3 | 코드 관리 | 코드 관리 | `004-admin-codes` |

- **FR-002**: 관리 메뉴는 그 메뉴가 가리키는 연결 화면의 권한을 가진 사용자에게만 보여야 한다(MUST). 관리자는 모든 권한을 갖는다. 연결 화면이 없는 상위 메뉴는 보이는 하위 메뉴가 하나라도 있을 때만 보인다
- **FR-003**: 권한이 없는 사용자가 관리 화면이나 관리 기능에 접근하면 막아야 한다(MUST). 로그인하지 않았으면 로그인 안내, 로그인했으면 권한 없음 안내를 보인다
- **FR-004**: moa 관리 기능(신고, 제재, 게임, 복구)은 기능이 정해질 때까지 메뉴에 넣지 않는다. 넣을 때는 그 기능의 스펙에 연결 화면(FR-008)과 메뉴 위치(상위 메뉴와 순서)를 적고 FR-001·FR-008 표에 더한다
- **FR-005**: 화면은 관리 셸과 사용자 셸로 나뉘어야 한다(MUST). 두 셸은 같은 사이드바 모양(사이드바, 계정 줄, 좁은 폭의 서랍)을 쓰고 메뉴만 다르다
  - 관리 셸: 관리 화면(`/admin/...`). 사이드바에는 대상이 "관리자"인 메뉴(관리 메뉴, FR-001)만 있다. 관리 메뉴가 하나라도 있는 사용자(관리자, 권한을 받은 운영자)만 쓴다
  - 사용자 셸: 사용자 화면(첫 화면, 공지 목록·상세). 사이드바에는 대상이 "사용자"인 메뉴(사용자 메뉴, FR-007)만 있다. 로그인하지 않아도 열 수 있는 화면(공지)은 로그인하지 않은 채로도 이 셸에서 보이고, 계정 줄에는 로그인 단추가 보인다
  - 계정 화면(알림, 설정, 비밀번호 변경)은 관리 메뉴가 있는 사용자에게는 관리 셸, 없는 사용자에게는 사용자 셸 안에서 보인다
  - 두 셸의 계정 메뉴는 설정, 비밀번호 변경, 로그아웃 순서다
  - 넓은 폭에서는 본문 위에 머리 줄을 두지 않는다. 사이드바 접기 단추는 사이드바 맨 위 로고 옆에 둔다. 아이콘만 남게 접었을 때는 로고 자리가 펼치기 단추가 된다
  - 사이드바가 서랍이 되는 좁은 폭에서는 머리 줄에 서랍 단추, 사이트 이름, 벨(로그인했을 때) 또는 로그인 단추(로그인하지 않았을 때)를 둔다. 화면 이름은 머리 줄에 두지 않는다(화면 제목이 본문에 있다)
  - 하위 메뉴가 있는 상위 메뉴는 펴고 접는다. 상위 메뉴 행을 누르면 펴지거나 접힌다. 처음에는 접혀 있고, 지금 보는 화면이 그 상위 메뉴 안이면 펴져 있다. 넓은 폭·좁은 폭(서랍)이 같다
  - 펴고 접은 상태는 메뉴별로 브라우저에 기억해 새로 고쳐도 유지한다. 서버에는 저장하지 않는다. 사용자가 직접 펴거나 접은 상태가 지금 화면에 따른 자동 펴기보다 먼저다
  - 지금 화면이 있어 자동으로 펴진 상위 메뉴는 펴진 채로 기억한다. 다른 상위 메뉴의 화면으로 옮겨도 사용자가 접기 전까지 펴져 있다
  - 아이콘만 남게 접었을 때 상위 메뉴 아이콘을 누르면 사이드바를 펼치고 그 상위 메뉴를 편다
  - 메뉴에 아이콘이 있으면 상위 메뉴와 하위 메뉴 모두 이름 앞에 보인다 (2026-11-21)
  - 사이드바의 머리(로고 줄), 메뉴, 바닥(계정 줄)은 선으로 나눈다. 하위 메뉴 목록은 왼쪽 선으로 상위 메뉴 아래에 들여 보인다
- **FR-006**: 로그인한 뒤 첫 화면은 관리 메뉴가 있는 사용자는 볼 수 있는 첫 관리 메뉴의 화면(상위 메뉴 안이면 사이드바 위에서부터 첫 화면 메뉴, 처음 구성에서는 사용자 관리), 없는 사용자는 사용자 셸의 첫 화면(`/`)이어야 한다(MUST). 로그인 화면이 돌아갈 주소를 받았으면 그 주소가 먼저다. 브라우저를 다시 열어 첫 화면(`/`)에서 리프레시 토큰으로 로그인이 이어진 때도 같은 첫 화면으로 보낸다
- **FR-007**: 메뉴는 대상(관리자, 사용자)을 가져야 한다(MUST). 관리자는 메뉴 관리에서 관리 메뉴와 사용자 메뉴를 함께 만들고, 고치고, 끄고, 순서를 바꾼다. 하위 메뉴는 부모 메뉴의 대상을 따른다
  - 사용자 메뉴는 권한을 쓰지 않고 공개 범위를 가진다(MUST). "누구나"는 로그인하지 않은 사람을 포함한 모두에게, "회원만"은 로그인한 사용자에게만 보인다. 로그인이 필요한 연결 화면(FR-008)을 가리키는 메뉴는 "회원만"이어야 한다
  - 처음 배포할 때 사용자 메뉴는 상위 메뉴 없이 아래 표의 순서다

  | 순서 | 메뉴 | 연결 화면 (FR-008) | 공개 범위 | 스펙 |
  |---|---|---|---|---|
  | 1 | 홈 | 홈 | 누구나 | 이 스펙 |
  | 2 | 공지 | 공지 | 누구나 | `006-notices` |

  - 사용자 메뉴를 더하는 것은 사용자 쪽 기능의 스펙이 정한다 (`specs/README.md` 맞춰야 할 경계)
- **FR-008**: 메뉴에 걸 수 있는 화면은 연결 화면(코드 `ScreenDefinition`)으로 코드에 등록되어야 한다(MUST). 관리자는 메뉴 상세 칸의 "연결 화면" 선택 상자에서 연결 화면을 고르기만 하고 더하거나 고치지 않는다. 연결 화면 목록만 보여 주는 화면은 두지 않는다
  - 연결 화면은 이름, 경로, 대상(관리자·사용자)을 가진다. 관리 연결 화면은 필요한 권한을 하나 가진다(MUST). 사용자 연결 화면은 로그인 필요 여부를 가진다
  - 연결 화면의 권한과 로그인 필요 여부는 그 화면이 쓰는 API가 실제로 막는 조건과 같아야 한다. 새 화면을 만드는 기능은 그 스펙에 연결 화면(이름, 경로, 권한 또는 로그인 필요 여부)을 적는다
  - 메뉴로 열지 않는 화면(공지 상세, 계정 화면 등)은 연결 화면으로 등록하지 않는다
  - 처음 등록하는 연결 화면은 아래 표다

  | 연결 화면 | 경로 | 대상 | 필요한 권한 / 로그인 | 스펙 |
  |---|---|---|---|---|
  | 사용자 관리 | `/admin/users` | 관리자 | 사용자 관리 | `002-admin-users` |
  | 메뉴 관리 | `/admin/menus` | 관리자 | 메뉴 관리 | 이 스펙 |
  | 코드 관리 | `/admin/codes` | 관리자 | 코드 관리 | `004-admin-codes` |
  | 접속 이력 | `/admin/login-histories` | 관리자 | 접속 이력 조회 | `005-admin-login-history` |
  | 파기 기록 | `/admin/purge-logs` | 관리자 | 파기 기록 조회 | `013-purge-log` |
  | 역할 관리 | `/admin/roles` | 관리자 | 역할 관리 | `003-admin-roles` |
  | 공지 관리 | `/admin/notices` | 관리자 | 공지 관리 | `006-notices` |
  | 홈 | `/` | 사용자 | 로그인 필요 없음 | 이 스펙 |
  | 공지 | `/notices` | 사용자 | 로그인 필요 없음 | `006-notices` |

- **FR-009**: 메뉴는 연결 화면 하나를 가리키는 화면 메뉴이거나, 연결 화면 없이 하위 메뉴를 담는 상위 메뉴여야 한다(MUST). 메뉴 관리에서 경로와 권한 키를 직접 입력하지 않는다
  - 화면 메뉴는 메뉴의 대상과 같은 대상의 연결 화면만 가리킨다
  - 메뉴 관리 화면은 권한 키를 몰라도 쓸 수 있어야 한다. 메뉴 관리 권한만 받은 운영자도 선택 상자에서 연결 화면 이름·경로와 그 권한 이름을 본다
  - 화면 문구는 쉬운 말을 쓴다(MUST). 연결 화면 없는 메뉴는 "상위 메뉴", 상위 메뉴 아래 메뉴는 "하위 메뉴"라고 부른다. "묶음"과 "프로그램"은 화면에 쓰지 않는다. 역할 관리 등 다른 관리 화면의 같은 개념도 같은 말을 쓴다
  - 메뉴를 만들고 고치는 칸에 "종류"를 두지 않는다. 연결 화면을 고르면 화면 메뉴, 비우면 상위 메뉴다. 메뉴의 자리는 "상위 메뉴" 칸("없음(맨 위)" 또는 같은 대상의 상위 메뉴)으로 정한다
  - 메뉴는 2단계까지다. 상위 메뉴 아래에 둔 메뉴는 연결 화면을 골라야 한다. 하위 메뉴가 있는 메뉴는 연결 화면을 고를 수 없고 상위 메뉴 칸도 "없음(맨 위)"뿐이다
- **FR-010**: 메뉴 관리 화면은 넓은 폭에서 왼쪽 메뉴 트리와 오른쪽 상세 칸의 두 칸이다(MUST). 공통코드(`004-admin-codes` FR-005)와 같은 틀이다. 두 칸은 화면 남은 높이를 반씩 나눠 채우고, 각 칸 안에서 스크롤한다
  - 메뉴 트리는 구성 목록이다(원칙 "목록"). 대상 탭마다 트리 전체를 쪽 나눔 없이 보인다. 대상마다 메뉴는 200개를 넘지 않는다(MUST)
  - 순서와 부모는 끌기 손잡이로 바꾼다. 같은 일을 키보드로도 할 수 있어야 한다(MUST). 행마다 위·아래·수정·삭제 단추를 두지 않는다
  - 메뉴 하나는 행을 눌러 오른쪽 칸에서 고친다. 체크박스와 끌기 손잡이를 누를 때는 열지 않는다. 키보드로는 메뉴명 단추로 연다. 트리 열은 체크박스·손잡이·메뉴명·사용이다(사용 안 함은 회색). 오른쪽 칸에 열린 행은 강조한다. 아무것도 고르지 않으면 오른쪽 칸에 고르라는 안내를 보인다. 저장 줄은 오른쪽 칸 아래에 붙는다
  - 트리의 메뉴명 앞에는 그 메뉴의 아이콘을 보인다. 아이콘이 없으면 상위 메뉴는 폴더, 화면 메뉴는 문서 아이콘이다. 메뉴명에 마우스를 올려도 밑줄을 긋지 않는다(행 전체가 눌린다)
  - 상위 메뉴·연결 화면·아이콘 칸은 글자를 쳐서 찾는 선택 상자다 (2026-11-21)
    - 상위 메뉴: 메뉴명으로 찾고, 메뉴명 앞에 그 메뉴의 아이콘을 보인다
    - 연결 화면: 화면 이름이나 경로로 찾는다. 목록은 화면 이름 아래에 경로와 쓰는 사람(권한 이름, 로그인 필요 여부)을 작게 보인다. 다른 메뉴에 이미 건 화면에는 "{메뉴명}에 연결됨"을 붙인다. 같은 화면을 여러 메뉴에 걸 수 있으므로(엣지 케이스) 고르기를 막지 않는다
    - 아이콘: 영어 이름과 한글 이름·비슷한 말(예: 공지 → 공지·알림·확성기)로 찾는다. 목록은 아이콘과 한글 이름을 칸(격자)으로 보이고, 방향키로 위·아래·옆 칸으로 옮겨 고른다. 첫 칸은 "없음"이다
  - 사용자 메뉴의 공개 범위는 고르기 카드 두 장("누구나", "회원만")을 한 줄에 나란히 둔다. 카드마다 아이콘, 이름, 한 줄 설명("로그인 안 해도 보여요", "로그인하면 보여요")을 보인다. 로그인이 필요한 연결 화면이면 "누구나" 카드를 끄고 이유를 보인다 (2026-11-21)
  - "사용" 토글은 메뉴명 칸 바로 아래 오른쪽에 둔다 (2026-11-21. 공통코드 패널도 같다)
  - 새 메뉴는 트리 위 "메뉴 추가" 하나로 같은 칸에서 만든다. 상위 메뉴 칸의 처음 값은 지금 고른 메뉴가 있는 상위 메뉴(고른 것이 상위 메뉴면 그 메뉴), 없으면 "없음(맨 위)"다
  - 저장하지 않은 변경이 있는 채로 다른 행을 고르거나 다른 대상 탭으로 가려 하면 버릴지 묻는다
  - 일괄 처리 줄은 트리 위에 늘 같은 자리·높이로 둔다. 고른 것이 없으면 안내와 꺼진 단추를, 고르면 고른 수와 단추를 보인다
  - 1024px보다 좁으면 트리 하나만 보이고 상세는 FR-012의 드로어로 연다
  - 체크박스로 여러 메뉴를 골라 사용·사용 안 함, 상위 메뉴로 옮기기, 삭제를 한꺼번에 한다. 한꺼번에 하는 일은 하나라도 틀리면 아무것도 바꾸지 않고(MUST) 이유를 보인다. 삭제는 확인을 받는다
  - 끌기와 일괄 처리도 FR-009의 규칙(상위 메뉴는 1단계만, 대상이 다른 부모 아래로 옮기지 않음 등)을 그대로 따른다
- **FR-011**: 관리 화면은 머리 설명에 그 화면이 정하는 것과 앞뒤 화면(예: 메뉴 관리 → 역할 관리)을 한두 줄로 알려야 한다(MUST). 앞뒤 화면은 링크로 둔다. 문구는 각 화면의 스펙이 정한다
  - 메뉴 관리: "사이드바에 보일 메뉴와 상위 메뉴, 순서를 정해요. 누가 어떤 관리 메뉴를 쓰는지는 역할 관리에서 정해요."
- **FR-012**: 관리 화면의 드로어는 다음을 지킨다(MUST). 메뉴·역할·공통코드·사용자 관리 드로어 모두 같다. 공통코드와 메뉴 관리는 넓은 폭에서 드로어 대신 오른쪽 상세 패널을 쓰고 좁은 폭에서만 드로어를 쓴다 (`004-admin-codes` FR-005, 이 스펙 FR-010, 2026-11-20). 패널도 저장하지 않은 변경을 묻는 규칙은 같다
  - 좁은 폭(사이드바가 서랍이 되는 폭)에서는 드로어가 화면 전체를 덮는다. 끌기가 어려운 화면에서도 키보드·단추로 순서를 바꿀 수 있어야 한다
  - 저장하지 않은 변경이 있는 채로 닫으려 하면 닫을지 묻는다

### Key Entities *(include if feature involves data)*

- **셸**: 화면을 감싸는 틀(사이드바, 계정 줄, 머리). 관리 셸과 사용자 셸이 있다
- **연결 화면**: 메뉴에 걸 수 있는 화면. 코드에 등록한다. 이름, 경로, 대상, 필요한 권한(관리 연결 화면) 또는 로그인 필요 여부(사용자 연결 화면)를 가진다
- **메뉴**: 셸 사이드바의 항목. 이름, 아이콘, 순서, 대상(관리자·사용자), 켜짐, 연결 화면(화면 메뉴) 또는 하위 메뉴(상위 메뉴)를 가진다.
  - **관리 메뉴**: 대상이 관리자인 메뉴. 관리 셸에 보인다. 처음 배포할 때는 "운영"·"설정" 상위 메뉴 아래에 둔다(FR-001). 보이는 조건은 연결 화면의 권한이다
  - **사용자 메뉴**: 대상이 사용자인 메뉴. 사용자 셸에 보인다. 공개 범위(누구나, 회원만)를 가진다
- **권한**: 관리 기능 하나를 쓸 수 있는 자격. 관리 연결 화면마다 하나씩 있고 코드에 등록한다. 계정에는 시스템 역할(`USER`, `ADMIN`)로, 운영자에게는 역할 관리의 업무 역할(`003-admin-roles`)로 준다

## Assumptions

- 관리자 화면(프론트)은 프론트 키트(web-next admin 프리셋)가 만드는 admin 화면을 쓴다
- 키트 admin 프리셋의 기본 시드는 관리 메뉴를 "관리" 그룹 아래에 둔다. moa는 그 그룹을 없애고 메뉴를 최상위로 옮긴다. 순서와 권한은 키트 시드와 같다
  - 배경 (2026-11-14): 백오피스 메뉴가 모두 관리 기능이라 "관리" 한 단계로 묶는 의미가 없다
  - 2026-11-15에 "운영"·"설정" 두 묶음으로 바꿨다 (아래 "관리 화면 정리")
- 관리 셸과 사용자 셸을 나눈다 (2026-11-15 결정, FR-005·FR-006)
  - 배경: 한 사이드바에 홈·공지(사용자 화면)와 관리 메뉴가 섞여, 관리자 사이드바가 일반적인 관리 화면과 달랐다. 공지 화면은 셸 없이 머리만 있어 다른 화면과 구성이 달랐다
  - 두 셸은 같은 사이드바 모양을 쓰고 메뉴만 다르다. 사용자 셸의 메뉴와 모양은 사용자 쪽 담당이 더하거나 바꾼다 (`specs/README.md` 맞춰야 할 경계)
- 넓은 폭에서 머리 줄을 없앤다 (2026-11-15 결정, FR-005)
  - 배경: 머리 줄에는 접기 단추와 메뉴 이름만 있었고, 메뉴 이름은 바로 아래 화면 제목과 같았다. 상위 메뉴도 보이지 않아 위치 표시 구실도 하지 않았다
  - 알림은 메뉴로 따로 두지 않는다. 계정 줄 벨과 그 목록의 "전체 보기"가 알림 화면으로 가는 길이다 (`007-notifications` FR-005)
  - 키트 `SidebarShell`을 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 사이드바 묶음을 펴고 접는다 (2026-11-18 결정, FR-005, US1-AC4~AC8)
  - 배경: 묶음 메뉴가 늘 펼쳐져 사이드바가 길고, 머리·메뉴·계정 줄 사이 경계가 약했다. psw-gongbu `release/v0.11.0`의 사이드바 분류 아코디언에서 moa에 맞는 것만 가져왔다(⋯ 행 메뉴·개수 표시처럼 moa 메뉴에 없는 것은 뺐다)
  - 묶음은 링크가 아니라서 묶음 행 전체를 펴기·접기 단추로 쓴다
  - 자동으로 펴진 묶음을 기억한다: 기억하지 않으면 다른 묶음의 화면으로 옮길 때 위쪽 묶음이 접혀, 방금 누른 메뉴가 커서 밑에서 위로 움직인다. 관리 셸 묶음은 둘뿐이라 펴진 채 남아도 길어지지 않는다
  - 버린 안: 묶음 왼쪽에 화살표 단추를 따로 두기(행 나머지가 할 일이 없다), 아이콘만 남게 접었을 때 옆에 하위 메뉴 띄우기(부품과 테스트가 더 든다), 처음에 모두 펴 두기(사이드바가 길어지는 문제가 그대로다)
  - 키트 `SidebarShell`을 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 메뉴에 대상(관리자·사용자)을 둔다 (2026-11-15 결정, FR-007)
  - 배경: 사용자 셸 메뉴(홈·공지)가 코드에 고정돼 메뉴 관리에서 보이지 않았다. 권한은 계정의 시스템 역할(USER·ADMIN)로 나누는 느낌을 원했고, 대상이 그 구분을 맡는다. 세부 권한(운영자용)은 선택으로 남긴다
  - 버린 안: 세부 권한을 없애고 시스템 역할만 남기기. 003 역할 관리와 키트 rbac 헬퍼를 걷어내야 해 범위가 크다
  - 키트 menu 헬퍼를 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III, 사용자 결정)
- 메뉴는 등록된 프로그램을 골라 만들고, 사용자 메뉴는 권한 대신 공개 범위를 쓴다 (2026-11-15 결정, FR-002·FR-007~FR-009)
  - 배경: 메뉴 관리에서 경로와 권한 키를 직접 입력해야 해, 키 이름을 모르면 메뉴를 만들 수 없었다. 권한 칸을 비웠을 때의 뜻도 대상마다 달라(관리 메뉴는 `ADMIN`만, 사용자 메뉴는 모두) 알기 어려웠다. 사용자 쪽에서 필요한 구분은 비회원과 회원뿐이다
  - 흐름은 그룹웨어에서 흔한 "프로그램 등록 → 메뉴 등록 → 권한 그룹에 메뉴 체크 → 사용자에게 권한 그룹 주기"를 따른다. 권한 그룹에 메뉴를 체크하는 것은 `003-admin-roles`가 정한다
  - 프로그램은 화면에서 등록하지 않고 코드에 등록한다. 화면은 코드로 만들어 배포해야 생기므로 화면에서 경로만 등록해도 쓸 데가 없다
  - API를 막는 것은 지금처럼 코드의 권한 표시다. 메뉴나 프로그램 등록으로 API를 막지 않는다(등록을 빠뜨리면 API가 열리는 일을 막는다)
  - 버린 안: 권한 칸을 등록된 권한의 선택 상자로만 바꾸기(잘못 고를 여지가 남는다), 기능 메뉴의 경로·권한을 고정하기(관리자가 메뉴를 다시 짤 수 없다), 사용자 메뉴에 "모두 / 권한 선택"을 두기(사용자 쪽은 권한을 쓰지 않는다)
  - 키트 menu 헬퍼와 admin 프리셋 시드를 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III, 사용자 결정)
- 관리 화면 정리: 묶음, 메뉴 표 조작, 화면 안내 (2026-11-15 결정, FR-001·FR-008·FR-010·FR-011, US5)
  - 배경: 사용자 관리·메뉴 관리·코드 관리·접속 이력·역할 관리·공지 관리가 같은 무게로 섞여, 권한과 관계없는 코드 관리가 권한 화면 사이에 있었고 셋(코드·메뉴·역할)의 경계가 헷갈렸다. 메뉴 관리는 행마다 위·아래·수정·삭제 단추가 있어 묶음 사이를 옮기기 어려웠다. 프로그램 탭은 관리자가 할 일이 없는 개발자 개념을 보였다
  - 관리 화면은 같은 틀(목록 + 오른쪽 드로어 + 체크박스 일괄 처리)로 맞춘다. 역할 관리(`003-admin-roles`)·공통코드(`004-admin-codes`)도 같은 틀이다
  - 공통코드는 2026-11-20에 넓은 폭에서 좌 트리 · 우 상세 두 칸으로 바꿨다(`004-admin-codes` FR-005). 메뉴 관리도 같은 날 두 칸으로 바꿨다(아래). 역할·사용자 관리도 두 칸으로 맞출지는 나중에 따로 정한다
  - 버린 안: 코드 관리 메뉴 숨기기(공통코드를 지금 함께 다시 만들기로 함), 메뉴 표 쪽 나눔(구성 목록이라 전체를 보며 끌어야 한다)
  - 키트 menu 헬퍼 화면과 admin 프리셋 시드를 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 메뉴 관리를 두 칸 화면과 쉬운 말로 바꾼다 (2026-11-20 사용자 결정, FR-009·FR-010·FR-012, US5)
  - 배경: 메뉴 관리를 써 본 사용자가 "묶음 아래 하위 메뉴", "종류", "프로그램"이 무슨 뜻인지 알기 어렵다고 했다. 드로어는 메뉴마다 열고 닫아야 하고 트리를 가려, 여러 메뉴를 이어서 고치기 어렵다. 국내 백오피스의 메뉴 관리는 왼쪽 트리 · 오른쪽 상세가 흔하고, 공통코드도 같은 날 그렇게 바꿨다
  - 화면 문구만 바꾼다. 스펙 안의 개념 이름(프로그램, 화면 메뉴)과 API·데이터는 그대로다. 위 결정 기록의 "묶음"은 그때 쓰던 말이라 고치지 않는다
  - "종류" 칸을 없앤다. 연결 화면이 있고 없음이 곧 종류라 두 칸이 같은 것을 두 번 묻는다
  - 사용자 메뉴의 홈·공지는 상위 메뉴 없이 맨 위에 놓인 화면 메뉴라, 추가 단추를 "상위 메뉴 추가"·"하위 메뉴 추가"로 나누면 이 경우를 부를 말이 없다. 그래서 "메뉴 추가" 하나와 "상위 메뉴" 칸으로 정한다
  - 버린 안: 추가 단추를 상위·하위 둘로 나누기(위 이유), 드로어를 두고 넓게만 하기(트리를 가리는 문제가 그대로다), "프로그램"을 그대로 두고 도움말 붙이기(관리자가 모르는 개발자 말이 남는다)
  - 키트 menu 헬퍼 화면을 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 트리 행 전체를 눌러 상세를 열고, 메뉴 트리의 "보이는 사람" 열을 뺀다 (2026-11-21 사용자 결정, FR-010, US5-AC1·AC2·AC8)
  - 배경: 메뉴를 써 본 사용자가 이름만 눌리는 것이 불편하고, "이름"보다 "메뉴명"이 분명하며, "보이는 사람"이 무엇을 뜻하는지 알기 어렵다고 했다. 관리 메뉴는 그 칸에 연결 화면의 권한 이름이 나오는데 대개 메뉴명과 같아 같은 말이 두 번 보였다
  - 누가 보는지는 오른쪽 상세 칸의 연결 화면 안내(권한·로그인 필요)와 공개 범위에 그대로 있고, 관리 메뉴를 누가 쓰는지는 역할 관리에서 정한다

  - 버린 안: "보이는 사람"을 사용자 탭에서만 "공개 범위"로 남기기(두 탭의 열이 달라지고 상세 칸에 이미 있다)

# Quickstart: 관리자·운영자 계정 (admin-users)

기대 결과의 기준은 [contracts/admin-accounts.md](./contracts/admin-accounts.md)다.

## 자동 검증

Docker가 떠 있어야 한다. `backend/`에서 실행한다 (Windows는 `.\gradlew.bat`).

```bash
./gradlew dbTest --tests "*AdminUsersAcceptanceTest"
```

기대: `US1-AC1`, `US2-AC1`이 통과한다.

## 화면 확인

자동 테스트는 API까지 확인한다. 화면의 안내와 창은 아래로 직접 본다.

1. `backend/`에서 `./gradlew bootRun`, `frontend/`에서 `npm run dev`
2026-11-21에 계정 종류(회원·관리자)와 드로어 역할 주기, 다루기 범위를 더했다(FR-005~FR-008).

2. 시험 계정 `admin`으로 로그인해 사용자 관리에서 계정 종류 "관리자"로 사용자를 만든다: 계정 종류에 회원·관리자가 있고, 만들기 드로어 안에 임시 비밀번호가 보이며, 닫으면 다시 볼 수 없다
3. 로그아웃하고 새 계정과 임시 비밀번호로 로그인한다: 비밀번호 변경 화면에 안내가 보이고, 다른 화면으로 갈 수 없다
4. 비밀번호를 바꾸면 관리 셸에 "받은 권한이 없어요"가 보인다 (역할을 받지 않았다)
5. 다시 `admin`으로 로그인해 사용자 관리를 연다: "계정 종류" 열에 회원·관리자, "역할" 열에 `admin`은 "최고 관리자", 새 계정은 "역할 없음", 회원 `user`는 빈 칸이다. 줄에 "관리" 메뉴 단추는 없다
6. 새 계정의 아이디를 누르면 드로어 가운데 역할 칸이 있다: 역할마다 쓰는 메뉴가 작게 붙어 있다. 역할을 체크하고 "역할 저장"을 누르면 목록의 역할 열에 보인다. 내 줄은 계정 종류 바꾸기·잠그기·삭제가 꺼져 있다
7. `user`(회원)의 드로어에는 역할 칸 대신 "회원은 역할을 받지 않아요..." 안내가 있다
8. 새 계정에게 "사용자 관리" 권한만 묶은 역할을 주고 그 계정으로 로그인한다: `admin` 줄을 열면 단추가 모두 꺼지고 "최고 관리자 계정은 최고 관리자만 다룰 수 있어요."가 보인다. 접속 이력 권한을 가진 다른 운영자 줄은 "나보다 권한이 많은 관리자 계정이라..."가 보인다. 권한 관리 권한이 없으므로 역할 칸은 이름만 보인다
9. `admin`으로 역할이 있는 운영자의 계정 종류를 "회원"으로 바꾸려 하면 빠질 역할 이름이 확인 창에 보인다

첫 관리자는 빈 DB에 환경 변수 `BOOTSTRAP_ADMIN_LOGIN_ID`, `BOOTSTRAP_ADMIN_PASSWORD`를 주고 띄우면 생긴다. 만든 뒤에는 그 환경 변수를 지운다.

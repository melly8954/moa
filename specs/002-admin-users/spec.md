# Feature Specification: 관리자·운영자 계정 (admin-users)

**Feature Branch**: `feat/002-admin-users`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "운영 환경의 첫 관리자를 만들고, 이후 운영자 계정은 관리자가 사용자 관리에서 만든다. 관리자와 운영자는 회원 활동을 하지 않는다."

**출처**: psw-dev-kit springboot user-admin 헬퍼와 골격의 첫 관리자 부트스트랩. 태그 `springboot/v0.3.0`.
키트 동작(사용자 목록·만들기·잠금·비밀번호 초기화, 임시 비밀번호, ADMIN 보호, 부트스트랩 조건)은 키트 문서와 키트 수용 테스트가 기준이다 (원칙 III).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 첫 배포 때 관리자가 생긴다 (Priority: P1)

운영 환경에 처음 배포할 때 첫 관리자 설정을 넣으면 관리자 계정이 생기고, 그 관리자가 백오피스에 들어갈 수 있다.

**Why this priority**: 관리자가 없으면 백오피스의 어떤 기능도 쓸 수 없다.

**Independent Test**: 빈 운영 환경에 첫 관리자 설정을 넣어 배포하고 그 계정으로 로그인한다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 첫 배포에 첫 관리자 설정(아이디, 임시 비밀번호)을 넣었다, **When** 그 아이디와 임시 비밀번호로 로그인한다, **Then** 비밀번호를 바꾸라는 안내를 받고, 바꾼 뒤 백오피스에 들어간다

---

### User Story 2 - 관리자가 운영자 계정을 만든다 (Priority: P2)

관리자가 사용자 관리에서 운영자 계정을 만들어 임시 비밀번호를 운영자에게 전달한다. 운영자는 첫 로그인 때 비밀번호를 바꾼다.

**Why this priority**: 운영자가 늘어날 때를 위한 기능이다. 첫 출시에는 관리자 한 명으로도 운영할 수 있다.

**Independent Test**: 관리자로 운영자 계정을 만들고, 그 운영자로 로그인한다.

**Acceptance Scenarios**:

1. **US2-AC1** **Given** 관리자가 로그인했다, **When** 사용자 관리에서 운영자 계정을 만든다, **Then** 임시 비밀번호가 한 번 보이고, 그 운영자는 첫 로그인 때 비밀번호를 바꾸라는 안내를 받는다

---

### Edge Cases

- 첫 관리자 설정을 빠뜨리거나 잘못 넣은 경우: 키트 부트스트랩 동작을 따른다 (관리자가 없으면 경고, 같은 아이디의 일반 계정이 있거나 비밀번호가 짧으면 시작 실패)
- 운영자 계정에 역할을 주지 않은 경우: 운영자는 관리 메뉴를 보지 못한다 (`001-admin-menus` FR-002). 역할은 `003-admin-roles`에서 준다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 운영 환경의 첫 관리자는 키트의 첫 관리자 부트스트랩으로 만든다(MUST). 설정 이름, 생성 조건, 첫 로그인 비밀번호 변경, 실패 조건은 키트를 따른다
- **FR-002**: 첫 관리자를 만든 뒤 운영자 계정은 관리자가 사용자 관리에서 만든다(MUST). 운영자가 스스로 가입하는 경로는 두지 않는다
- **FR-003**: 관리자와 운영자 계정은 관리와 조회만 하고 회원 활동(게시물, 파티, 메시지)은 하지 않는다(MUST). [NEEDS CLARIFICATION: 회원 활동을 어떻게 막을지는 회원 기능(사용자 쪽)과 맞춘다. `specs/README.md` 맞춰야 할 경계]
- **FR-004**: 사용자 관리 목록에 보일 회원 항목은 키트 기본(아이디, 이름, 역할, 잠금)으로 시작한다. 회원 정보 모델이 정해지면 그 항목을 이 스펙에 더한다

### Key Entities *(include if feature involves data)*

- **관리자**: 모든 권한을 가진 계정. 첫 관리자는 배포 때 생기고, 이후 관리자가 다른 계정을 관리자로 바꿀 수 있다
- **운영자**: 관리자가 만든 계정. 역할로 일부 권한만 받는다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 새 운영 환경에 배포한 직후, DB 직접 입력 같은 수작업 없이 관리자가 로그인할 수 있다
- **SC-002**: 관리자가 운영자 계정을 만들어 전달하기까지 2분 안에 마칠 수 있다
- **SC-003**: 수용 시나리오(US1~US2) 전부가 자동 테스트로 확인된다 (원칙 II)

## Assumptions

- 관리자 화면(프론트)은 프론트 키트(web-next)가 만드는 admin 화면을 쓴다. 아직 태그가 없어 키트를 적용할 때 확인한다
- 회원 가입·로그인 방식과 회원 정보 모델은 사용자 쪽 기능이 정한다. 이 스펙은 키트 기본 계정(아이디·비밀번호)으로 관리자와 운영자를 다룬다
- 임시 비밀번호는 관리자가 운영자에게 직접 전달한다 (메일·문자 발송 없음, 프리셋 밖 헬퍼를 쓰지 않으므로)

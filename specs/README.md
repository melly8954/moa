# 기능 지도

moa의 도메인과 기능, 출처, 담당, 상태를 한 장에 둔다. 기능 스펙 자체는 `specs/<번호>-<이름>/`에 있다.

- 출처: `키트` = psw-dev-kit 헬퍼에서 온 기능, `moa` = moa가 만드는 기능
- 키트 기능은 동작을 다시 적지 않는다. moa가 어떻게 쓰는지는 `001-admin-foundation`에, 고칠 때는 그 기능의 스펙에 적는다

## 관리자 백오피스

| 도메인 | 기능 | 출처 | 스펙 | 상태 |
|---|---|---|---|---|
| 기반 | 관리자 영역 구성 (헬퍼, 메뉴 트리, 권한, 관리자 계정) | moa | `001-admin-foundation` | 기획 중 |
| 회원 | 사용자 목록·상세·잠금·비밀번호 초기화 | 키트 user-admin | `001-admin-foundation` | 기획 중 |
| 시스템 | 메뉴 관리 | 키트 menu | `001-admin-foundation` | 기획 중 |
| 시스템 | 공통코드 관리 | 키트 code | `001-admin-foundation` | 기획 중 |
| 시스템 | 접속 이력 조회 | 키트 login-history | `001-admin-foundation` | 기획 중 |
| 시스템 | 역할·권한 관리 | 키트 rbac | `001-admin-foundation` | 기획 중 |
| 회원 | 탈퇴 계정 복구 | moa | - | 보류: 탈퇴 상태·유예 기간이 정해진 뒤 |
| 회원 | 회원 제재·해제 | moa | - | 미정 |
| 신고 | 신고 처리 | moa | - | 미정 |
| 게임 | 게임·모드·티어 관리 | moa | - | 다른 담당, 추후 |

## 사용자 쪽

팀원 담당이다. 기능이 정해지면 이 표에 더한다.

| 도메인 | 기능 | 출처 | 스펙 | 상태 |
|---|---|---|---|---|

## 맞춰야 할 경계

관리자 백오피스와 사용자 쪽이 함께 정해야 하는 것이다. 정해지면 `docs/decisions/`에 남기고 이 목록에서 지운다.

| 항목 | 관련 기능 | 비고 |
|---|---|---|
| 회원 탈퇴 상태와 유예 기간 | 탈퇴 계정 복구 | 예전 정책: 유예 기간 안의 탈퇴 계정만 복구, 본인 확인은 관리자가 직접 |
| 관리자 계정의 회원 활동 금지 방법 | 회원 기능 전반 | `docs/decisions/0002-admin-account.md` |
| 회원 정보 모델 | 사용자 관리 | 키트 `users`는 아이디·이름 기준이다. 회원 가입 방식(이메일, 소셜, 닉네임)에 따라 관리자 목록에 보일 항목이 달라진다 |
| 추가로 쓸 키트 헬퍼 | 키트 적용 | 백오피스 기반은 admin 프리셋만 쓴다. 사용자 쪽에 필요한 헬퍼(oauth, websocket, file 등)는 키트 적용 전에 알려 준다 |

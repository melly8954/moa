# 기능 지도

moa의 도메인과 기능, 출처, 담당, 상태를 한 장에 둔다. 기능 스펙 자체는 `specs/<번호>-<이름>/`에 있다.

- 출처: `키트` = psw-dev-kit 헬퍼에서 온 기능, `moa` = moa가 만드는 기능
- 키트 기능도 도입할 때 스펙을 만든다. 스펙에는 키트 동작을 다시 적지 않고 moa가 어떻게 쓰는지만 적는다 (원칙 III)

## 관리자 백오피스

psw-dev-kit admin 프리셋 전체(code, login-history, menu, rbac, user-admin)로 세운다. 프리셋 밖 헬퍼는 넣지 않고 필요한 기능의 스펙에서 정한다.

| 도메인 | 기능 | 출처 | 스펙 | 상태 |
|---|---|---|---|---|
| 시스템 | 관리 메뉴 구성과 접근 제한 | 키트 menu | `001-admin-menus` | 구현됨 |
| 회원 | 첫 관리자, 운영자 계정 | 키트 user-admin, 골격 부트스트랩 | `002-admin-users` | 구현됨 |
| 시스템 | 운영자 역할 | 키트 rbac | `003-admin-roles` | 구현됨 |
| 시스템 | 공통코드 | 키트 code | `004-admin-codes` | 구현됨 |
| 시스템 | 접속 이력 | 키트 login-history | `005-admin-login-history` | 구현됨 |
| 공지 | 공지사항 (관리 화면과 사용자 목록·상세) | moa | `006-notices` | 구현됨 (실시간 알림 US4는 007 뒤) |
| 알림 | 알림 (실시간 전달, 개인 알림함, 브라우저 알림) | moa, 키트 websocket | `007-notifications` | 기획 중. 공지가 첫 사용처, 사용자 쪽 기능도 쓴다 |
| 회원 | 탈퇴 계정 복구 | moa | - | 보류: 탈퇴 상태·유예 기간이 정해진 뒤 |
| 회원 | 회원 제재·해제 | moa | - | 미정 |
| 신고 | 신고 처리 | moa | - | 미정 |
| 게임 | 게임·모드·티어 관리 | moa | - | 다른 담당, 추후 |

## 사용자 쪽

팀원 담당이다. 기능이 정해지면 이 표에 더한다.

| 도메인 | 기능 | 출처 | 스펙 | 상태 |
|---|---|---|---|---|

## 맞춰야 할 경계

관리자 백오피스와 사용자 쪽이 함께 정해야 하는 것이다. 정해지면 관련 기능의 스펙에 적고 이 목록에서 지운다.

| 항목 | 관련 기능 | 비고 |
|---|---|---|
| 회원 탈퇴 상태와 유예 기간 | 탈퇴 계정 복구 | 예전 정책: 유예 기간 안의 탈퇴 계정만 복구, 본인 확인은 관리자가 직접 |
| 관리자·운영자 계정의 회원 활동 금지 | 회원 활동 기능 (게시물, 파티, 메시지) | 관리자와 운영자 계정은 관리와 조회만 하고 회원 활동은 하지 않는다(MUST). 막는 방법은 회원 활동을 만드는 기능의 스펙이 정한다. 운영자는 시스템 역할이 `USER`라 일반 회원과 구분되지 않으므로 가려낼 방법도 함께 정한다 |
| 회원 정보 모델 | `002-admin-users` FR-004 | 키트 `users`는 아이디·이름 기준이다. 회원 가입 방식(이메일, 소셜, 닉네임)에 따라 관리자 목록에 보일 항목이 달라진다 |
| 추가로 쓸 키트 헬퍼 | 키트 적용 | 백오피스 기반은 admin 프리셋만 쓴다. 사용자 쪽에 필요한 헬퍼(oauth, websocket, file 등)는 키트 적용 전에 알려 준다. `006-notices`가 rich-text를, 알림(007)이 websocket을 적용한다 |

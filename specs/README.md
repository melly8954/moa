# 기능 지도

moa의 도메인과 기능, 출처, 담당, 상태를 한 장에 둔다. 기능 스펙 자체는 `specs/<번호>-<이름>/`에 있다.

- 출처: `키트` = psw-dev-kit 헬퍼에서 온 기능, `moa` = moa가 만드는 기능
- 키트 기능도 도입할 때 스펙을 만든다. 스펙에는 키트 동작을 다시 적지 않고 moa가 어떻게 쓰는지만 적는다 (원칙 III)

## 스펙 번호

번호를 먼저 예약하고 스펙을 만든다. 예약·겹침 검사 규칙은 `docs/spec-numbers.md`(psw-dev-kit `git` 템플릿)를 따른다.

- 예약 줄은 그 기능의 도메인 표(관리자 백오피스 또는 사용자 쪽)에 넣는다
- 스펙이 생기면 표의 스펙 칸을 폴더 이름으로 바꾸면서 상태를 `기획 중`으로 바꾼다

## 관리자 백오피스

psw-dev-kit admin 프리셋 전체(code, login-history, menu, rbac, user-admin)로 세운다. 프리셋 밖 헬퍼는 넣지 않고 필요한 기능의 스펙에서 정한다.

| 도메인 | 기능 | 출처 | 스펙 | 상태 |
|---|---|---|---|---|
| 시스템 | 관리 메뉴 구성과 접근 제한, 관리 셸·사용자 셸 | 키트 menu | `001-admin-menus` | 구현됨 |
| 회원 | 첫 관리자, 관리자 계정(최고 관리자·운영자)과 회원 | 키트 user-admin, 골격 부트스트랩 | `002-admin-users` | 구현됨 |
| 시스템 | 권한 관리 (운영자 역할, 최고 관리자 역할) | 키트 rbac | `003-admin-roles` | 구현됨 |
| 시스템 | 공통코드 | 키트 code | `004-admin-codes` | 구현됨 |
| 시스템 | 접속 이력 | 키트 login-history | `005-admin-login-history` | 구현됨 |
| 시스템 | 개인정보 파기 이력 (정리기의 파기 이력 저장과 관리 화면 목록, `docs/privacy.md`) | moa | `013-purge-log` | 구현됨 |
| 공지 | 공지사항 (관리 화면과 사용자 목록·상세) | moa | `006-notices` | 구현됨 |
| 알림 | 알림 (실시간 전달, 개인 알림함, 브라우저 알림) | moa, 키트 websocket | `007-notifications` | 구현됨. 개인 알림을 보내는 기능은 각 기능이 `NotificationApplication.notify`로 붙는다. 알림을 보내는 기능은 FR-012 규칙을 따른다 |
| 마케팅 | 배너·팝업 관리 (관리 화면과 사용자 쪽 노출) | moa | `016-banner-popup` | 구현됨 (담당: haily). 사용자 화면 노출은 자리가 정해진 뒤 |
| 고객센터 | FAQ와 1:1 문의 (관리 화면과 사용자 목록·작성, 답변 알림) | moa | `017-customer-center` | 구현됨 (담당: haily). 사용자 셸의 메뉴 자리는 사용자 쪽 담당과 맞춘다 |
| 회원 | 탈퇴 계정 복구 | moa | `018-member-withdrawal` | 구현됨: 018 US2(30일 안에 다시 로그인해 복구)에 들어갔다 |
| 회원 | 회원 제재·해제 | moa | - | 미정 |
| 신고 | 신고 처리 | moa | - | 미정 |
| 게임 | 게임·모드·티어 관리 | moa | - | 다른 담당, 추후 |

## 사용자 쪽

팀원 담당이다. 기능이 정해지면 이 표에 더한다.

| 도메인 | 기능 | 출처 | 스펙 | 상태 |
|---|---|---|---|---|
| 모임 | 파티(임시 모임)와 모집 페이지 | moa (게임 목록은 키트 code) | `008-party` | 스펙 작성 중 |
| 회원 | 마이페이지 (프로필: 닉네임, 아바타, 소개, 게임 정보) | moa | `009-mypage` | 기획 중 |
| 회원 | 소셜 로그인 (구글, 디스코드) | moa | `010-social-login` | 일부 구현됨: 구글 가입·로그인·안내, 관리자 기록. 디스코드와 계정 연결·해제(US5)는 구현 전 |
| 회원 | 이용약관·개인정보처리방침 공개 페이지 (전문, 버전·시행일, 예전 버전·시행 예정 안내, 로그인 화면과 사이드바 아래 링크) | moa (문안 구조는 010 약관) | `012-terms-privacy` | 기획 중 (담당: haily) |
| 회원 | 회원 탈퇴 (계정 관리 탭, 30일 복구, 파기) | moa | `018-member-withdrawal` | 구현됨 (담당: jeonggi4007) |
| 회원 | 기본 회원가입·로그인 (아이디·비밀번호, 이메일 인증, 비밀번호 재설정, 로그인 실패 잠금) | moa | `019` | 예약 (담당: jeonggi4007) |
| 회원 | 회원 프로필 보기, 친구, 팔로우 | moa | `014-friends-follow` | 스펙 작성 중 (담당: hyeonchang) |
| 모임 | 크루(반영구 모임), 크루원 모집 | moa | - | 008 다음 |
| 모임 | 크루 내전, 크루 간 경기 매칭 | moa | - | 크루 다음 |
| 피드 | 게임 플레이 숏폼 (올리기·압축, 탐색 격자, 세로 뷰어, 좋아요·조회수) | moa | `015-game-shortform` | 스펙 작성 중 (담당: hyeonchang) |

## 공통 화면

관리 셸과 사용자 셸이 함께 쓰는 화면 동작이다. 키트 web-next 골격의 공용 부품을 moa가 바꾸는 것을 여기에 둔다.

| 도메인 | 기능 | 출처 | 스펙 | 상태 |
|---|---|---|---|---|
| 화면 | 업무 목록의 쪽 이동·빈 결과 (쪽 크기, 아래 줄 배치, 표 높이), 기간 빠른 단추 | 키트 web-next 골격 | `011-list-screen` | 구현됨 |

## 맞춰야 할 경계

관리자 백오피스와 사용자 쪽이 함께 정해야 하는 것이다. 정해지면 관련 기능의 스펙에 적고 이 목록에서 지운다.

| 항목 | 관련 기능 | 비고 |
|---|---|---|
| 회원 탈퇴 상태와 유예 기간 | 탈퇴 계정 복구 | 예전 정책: 유예 기간 안의 탈퇴 계정만 복구, 본인 확인은 관리자가 직접. 유예 30일 뒤 파기는 `docs/privacy.md` "탈퇴 회원 파기"를 따른다: 글·댓글·파티·메시지는 남기고 작성자만 "탈퇴한 회원"이 된다(2026-11-21) |
| 관리자·운영자 계정의 회원 활동 금지 | 회원 활동 기능 (게시물, 파티, 메시지) | 관리자와 운영자 계정은 관리와 조회만 하고 회원 활동은 하지 않는다(MUST). 막는 방법은 회원 활동을 만드는 기능의 스펙이 정한다. 관리자·운영자 계정은 시스템 역할이 `ADMIN`인 계정이다(2026-11-21, `002-admin-users` FR-003·FR-005). 회원(`USER`)은 역할을 받을 수 없으므로 `009-mypage` FR-016·`010-social-login` FR-007의 "`ADMIN`이거나 업무 역할을 가진 계정"은 `ADMIN` 계정과 같다. 두 스펙의 문구는 담당이 맞춘다. `008-party`(FR-012)도 이 제한을 따라 서버에서 막는다(2026-11-22, 2026-11-14의 "두지 않는다"를 뒤집음). 판단은 `009-mypage`의 `MemberActivityPolicy`를 함께 쓴다 |
| 회원 정보 모델 | `002-admin-users` FR-004 | 키트 `tb_user`는 아이디·이름 기준이다. 회원 가입 방식(이메일, 소셜, 닉네임)에 따라 관리자 목록에 보일 항목이 달라진다 |
| 사용자 셸의 메뉴와 모양 | `001-admin-menus` FR-005 | 화면은 관리 셸과 사용자 셸로 나뉜다(2026-11-15). 사용자 셸은 지금 홈·공지 메뉴만 둔 임시 구성이다. 사용자 메뉴는 메뉴 관리에서 대상 "사용자"로, 등록된 연결 화면을 골라 다룬다(`001-admin-menus` FR-007·FR-008). 사용자 쪽 화면을 만드는 기능은 그 스펙에 프로그램을 적는다. 사용자 쪽 기능(게시물, 파티, 메신저 등)의 메뉴와 셸 모양은 사용자 쪽 담당이 정해 그 기능의 스펙에 적는다 |
| 추가로 쓸 키트 헬퍼 | 키트 적용 | 백오피스 기반은 admin 프리셋만 쓴다. 사용자 쪽에 필요한 헬퍼(oauth, websocket, file 등)는 키트 적용 전에 알려 준다. `006-notices`가 rich-text를, 알림(007)이 websocket을 적용한다. 파티(`008-party`)도 그 websocket을 함께 쓴다 |

# Quickstart: 공통코드 (admin-codes)

기대 결과의 기준은 [contracts/admin-codes.md](./contracts/admin-codes.md)다.

## 자동 검증

인수 테스트와 e2e는 PR CI가 돌린다(CLAUDE.md "로컬 검사"). 로컬에서 돌릴 때만 Docker가 떠 있어야 한다. `backend/`에서 실행한다 (Windows는 `.\gradlew.bat`).

```bash
./gradlew dbTest --tests "*Code*AcceptanceTest"
```

기대: `US1-AC1`~`US1-AC9`가 통과한다. `US1-AC10`은 e2e(`frontend/e2e/code.spec.ts`)가 본다.

## 화면 확인

local 프로필은 `db/localdata`의 SQL로 시험 그룹 둘(`LOCAL_GAME_GENRE` 게임 장르 (시험), `LOCAL_REPORT_REASON` 신고 사유 (시험))을 넣는다. 넓은 폭(1024px 이상)에서 본다.

1. `backend/`에서 `./gradlew bootRun`, `frontend/`에서 `npm run dev`
2. 시험 계정 `admin`으로 로그인해 공통코드를 연다: 왼쪽에 트리, 오른쪽에 "왼쪽에서 그룹이나 항목을 고르면 여기서 고쳐요" 안내가 보인다. 머리 설명이 FR-007 문구다. 삭제 단추는 어디에도 없다
3. 트리 맨 아래 "그룹 추가"를 누른다: 오른쪽 패널에서 그룹 코드 칸에 `event-type 1`을 치면 `EVENT_TYPE_1`로 바뀐다. 이름 "이벤트 분류"를 적고 저장하면 트리 맨 뒤에 생긴다. 같은 그룹 코드로 다시 만들면 "이미 있는 그룹 코드예요"가 보인다
4. 이벤트 분류의 "항목 추가"로 이름만 적고 둘 만든다: 코드 `001`, `002`로 생기고 사용 칸에 초록 점이 보인다
5. 이벤트 분류 그룹 행을 체크한다: 두 항목이 골라지고 일괄 처리 줄이 "2개 선택"이 된다. 트리는 위아래로 움직이지 않는다. 항목 하나를 풀면 그룹 체크가 "일부 선택"(−)이 된다
6. "사용 안 함"을 누른다: 골라진 항목이 회색 점(사용 안 함)이 된다. 다른 그룹의 항목을 함께 고르면 "한 그룹씩 처리해요"가 보인다
7. 손잡이를 끌거나 키보드(스페이스, 화살표, 스페이스)로 같은 그룹 안 순서를 바꾼다: 새로 고쳐도 그 순서다
8. 그룹 행을 누른다: 패널에서 이름·설명·사용을 고칠 수 있고, 그룹 코드는 바꿀 수 없다. 그룹 삭제 단추가 없다
9. 그룹을 "사용 안 함"으로 저장한다: 트리에서 그룹 이름이 흐리게 보이고 항목은 그대로 있다
10. 패널에서 이름을 고치다가 저장하지 않고 다른 행을 누른다: "저장하지 않고 나갈까요?"가 보인다
11. 창 높이를 줄인다: 트리와 패널이 각자 안에서 스크롤되고 일괄 처리 줄과 저장 줄은 보인다
12. 창 너비를 1024px보다 좁게 줄인다: 트리만 보이고 행을 누르면 오른쪽 드로어가 열린다

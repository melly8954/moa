# Quickstart: 공통코드 (admin-codes)

기대 결과의 기준은 [contracts/admin-codes.md](./contracts/admin-codes.md)다.

## 자동 검증

인수 테스트와 e2e는 PR CI가 돌린다(CLAUDE.md "로컬 검사"). 로컬에서 돌릴 때만 Docker가 떠 있어야 한다. `backend/`에서 실행한다 (Windows는 `.\gradlew.bat`).

```bash
./gradlew dbTest --tests "*Code*AcceptanceTest"
```

기대: `US1-AC1`~`US1-AC9`가 통과한다. `US1-AC10`은 e2e(`frontend/e2e/code.spec.ts`)가 본다.

## 화면 확인

local 프로필은 `db/localdata`의 SQL로 시험 그룹 둘(`LOCAL_GAME_GENRE` 게임 장르 (시험), `LOCAL_REPORT_REASON` 신고 사유 (시험))과 그 항목(게임 장르: `FPS`·`RPG`·`MOBA`, 신고 사유: `ABUSE`·`SPAM`)을 넣는다. 넓은 폭(1024px 이상)에서 본다.

1. `backend/`에서 `./gradlew bootRun`, `frontend/`에서 `npm run dev`
2. 시험 계정 `admin`으로 로그인해 코드 관리를 연다: 왼쪽에 그룹 목록(항목 수), 오른쪽에 첫 그룹의 머리와 항목 표가 보인다. 삭제 단추는 어디에도 없다
3. "그룹 추가"를 누른다: 드로어에서 그룹 코드 칸에 `event-type 1`을 치면 `EVENT_TYPE_1`로 바뀐다. 이름 "이벤트 분류"를 적고 저장하면 목록 맨 뒤에 생기고 골라진다. 같은 그룹 코드로 다시 만들면 "이미 있는 그룹 코드예요"가 보인다
4. 추가 줄에 코드 `open`(→ `OPEN`), 이름 "오픈"을 적고 엔터: 표 맨 뒤에 생긴다. 코드를 비우고 엔터를 누르면 "코드를 입력해 주세요", 같은 코드면 "이미 있는 코드예요"가 보인다
5. 항목 이름을 눌러 고치고 엔터: 저장된다. 다시 눌러 고치다 Esc: 고치기 전으로 돌아간다. 줄의 사용 스위치를 끄면 바로 회색이 된다
6. 항목 둘을 체크하고 "사용 안 함": 둘 다 꺼진다. 표는 위아래로 움직이지 않는다. 다른 그룹을 고르면 체크가 풀린다
7. 손잡이를 끌거나 키보드(스페이스, 화살표, 스페이스)로 항목 순서와 왼쪽 그룹 순서를 바꾼다: 새로 고쳐도 그 순서다
8. "그룹 설정": 드로어에서 이름·설명·사용을 고칠 수 있고, 그룹 코드는 바꿀 수 없다. 고치다 닫으면 "저장하지 않고 나갈까요?"가 보인다
9. 그룹을 "사용 안 함"으로 저장한다: 왼쪽 목록에서 이름이 흐리게 "사용 안 함"과 함께 보이고 항목은 그대로 있다
10. 사용 안 함 항목 줄의 삭제를 누르고 확인한다: 표에서 빠진다. 사용 중인 항목 줄에는 삭제 단추가 없다. 빈 그룹을 고르면 추가 줄 코드 칸에 "… 코드 (영문 대문자·숫자·_)"가 보인다
11. 창 높이를 줄인다: 목록과 표가 각자 안에서 스크롤되고 그룹 머리·일괄 처리 줄·추가 줄은 보인다
12. 창 너비를 1024px보다 좁게 줄인다: 그룹 목록이 위, 그룹 상세가 아래로 쌓인다

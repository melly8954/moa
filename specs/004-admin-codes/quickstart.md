# Quickstart: 공통코드 (admin-codes)

기대 결과의 기준은 [contracts/admin-codes.md](./contracts/admin-codes.md)다.

## 자동 검증

인수 테스트와 e2e는 PR CI가 돌린다(CLAUDE.md "로컬 검사"). 로컬에서 돌릴 때만 Docker가 떠 있어야 한다. `backend/`에서 실행한다 (Windows는 `.\gradlew.bat`).

```bash
./gradlew dbTest --tests "*Code*AcceptanceTest"
```

기대: `US1-AC1`~`US1-AC10`이 통과한다.

## 화면 확인

local 프로필은 `db/localdata`의 SQL로 시험 그룹 둘을 넣는다: 시스템 그룹 `LOCAL_GAME_GENRE`(게임 장르 (시험)), 일반 그룹 `LOCAL_REPORT_REASON`(신고 사유 (시험)).

1. `backend/`에서 `./gradlew bootRun`, `frontend/`에서 `npm run dev`
2. 시험 계정 `admin`으로 로그인해 공통코드를 연다: 그룹 행 둘(이름·그룹 코드·쓰는 곳)이 보이고 게임 장르에 잠금 표시가 있다. 머리에 "그룹 추가"가 있고, 머리 설명이 FR-007 문구다
3. "그룹 추가"를 눌러 그룹 코드 `EVENT_TYPE`, 이름 "이벤트 분류"를 적고 저장한다: 트리 맨 뒤에 생긴다. 다시 `EVENT_TYPE`나 `LOCAL_GAME_GENRE`로 만들면 "이미 있는 그룹 코드예요"가 보인다
4. 이벤트 분류 이름을 누른다: 드로어에서 이름·설명·쓰는 곳을 고칠 수 있고, 그룹 코드는 바꿀 수 없다
5. 이벤트 분류의 "항목 추가"를 눌러 이름만 적고 저장한다: 그룹 맨 뒤에 코드 `001`로 생긴다. 하나 더 만들면 `002`다
6. 항목 이름을 누른다: 드로어에서 이름과 사용을 고치고, 코드는 바꿀 수 없다
7. 항목 둘을 체크해 "사용 안 함"을 누른다: 둘 다 사용 안 함이 된다. 다른 그룹의 항목을 함께 고르면 "한 그룹씩 처리해요"가 보인다
8. 손잡이를 끌거나 키보드(스페이스, 화살표, 스페이스)로 같은 그룹 안 순서를 바꾼다: 새로 고쳐도 그 순서다. 다른 그룹으로는 옮겨지지 않는다
9. 그룹 행을 눌러 접고 편다
10. 게임 장르 이름을 누른다: 드로어에 "그룹 삭제"가 없고 "기능이 쓰는 그룹이라 지울 수 없어요"가 보인다
11. 이벤트 분류 드로어에서 "그룹 삭제"를 누른다: 확인 창에 "항목 2개도 함께 지워요"가 보이고, 확인하면 트리에서 빠진다

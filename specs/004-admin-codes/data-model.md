# Data Model: 공통코드 (admin-codes)

> 2026-11-21: 지금 스키마는 `V1__schema.sql`, 처음 데이터는 `V2__seed.sql`에 합쳐져 있다 (`docs/db.md`). 아래 마이그레이션 파일 이름은 합치기 전 기록이다.

키트 `tb_code`(`V1_4__codes.sql`)가 기준이다. 그룹은 `tb_code_group` 표에 둔다 (spec.md FR-004, research.md R11).
`tb_code_group`는 2026-11-15에 지웠다가(`V2_7`) 2026-11-18에 다시 만들었고(`V2_8`), 2026-11-20에 `used_by`·`system`을 빼고 `enabled`를 더한다(`V2_9__code_groups_enabled.sql`, 번호는 구현할 때 다시 본다).

## 스펙의 개념과 표의 대응

| 스펙 | 표 | 비고 |
|---|---|---|
| 코드 그룹 | `tb_code_group` (그룹 코드, 이름, 설명, 사용 여부 `enabled`) | 지우지 않는다(FR-008). 소프트 삭제 열은 키트 표에 남지만 쓰지 않는다. 지금 moa가 쓰는 그룹은 없다 (spec.md FR-001 표) |
| 코드 | `tb_code` (그룹, 코드, 이름, 순서, 사용 여부) | 지우지 않는다(FR-008). 코드를 비우면 자동 순번 (FR-006) |

## 바뀌는 열 (`tb_code_group`)

| 열 | 바뀜 | 뜻 |
|---|---|---|
| `enabled` | 더함 `BOOLEAN NOT NULL DEFAULT TRUE` | 꺼지면 그 그룹의 화면용 목록이 빈 목록이다 |
| `used_by` | 뺌 | 쓰는 곳. 설명으로 합쳤다 |
| `system` | 뺌 | 시스템 그룹. 지우지 않으므로 구분이 필요 없다 |
| `sort_order` | 더함 `INT NOT NULL DEFAULT 0` (2026-11-21, `V5__code_group_sort_order.sql`) | 그룹 순서. 기존 그룹은 만든 순서로 채우고, 새 그룹은 맨 뒤(최대 + 1). 트리는 순서, 같으면 만든 순서 |

## 처음 구성

코드 그룹이 없다. 그룹을 쓰는 기능이 생기면 그 기능의 스펙이 그룹과 초기 코드를 정하고, 마이그레이션으로 넣고, spec.md FR-001 표에 한 줄 더한다 (FR-002).
local 프로필만 `db/localdata`의 SQL로 시험 그룹 둘(`LOCAL_GAME_GENRE`, `LOCAL_REPORT_REASON`)과 그 항목(뜻 있는 코드)을 넣는다 (quickstart "화면 확인").

## 검증 규칙

- 그룹 코드: `[A-Z][A-Z0-9_]{0,49}`. 그룹끼리 겹치면 안 된다. 만든 뒤 바꾸지 않는다
- 코드: 영문 대문자·숫자·밑줄, 필수(자동 순번 없음, 2026-11-21). 그룹 안에서 겹치면 안 된다. 만든 뒤 바꾸지 않는다
- 그룹 이름은 필수다. 설명은 비어도 된다
- 그룹은 지우지 않는다. 사용 여부로 끈다. 코드는 사용 안 함일 때만 지운다(소프트 삭제, `deleted_at`·`deleted_by`, 2026-11-21)

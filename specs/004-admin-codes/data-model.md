# Data Model: 공통코드 (admin-codes)

키트 `codes`(`V1_4__codes.sql`)가 기준이다. 그룹은 `code_groups` 표에 둔다 (spec.md FR-004, research.md R9).
키트 `code_groups`는 2026-11-15에 moa에서 지웠다가(`V2_7__code_groups_from_code.sql`) 2026-11-18에 열 둘을 더해 다시 만든다(`V2_8__code_groups_on_screen.sql`, 번호는 구현할 때 다시 본다).

## 스펙의 개념과 표의 대응

| 스펙 | 표 | 비고 |
|---|---|---|
| 코드 그룹 | `code_groups` (그룹 코드, 이름, 설명, 쓰는 곳 `used_by`, 시스템 여부 `system`) | 키트 열에 `used_by`·`system`을 더한다. 소프트 삭제. 지금 moa가 쓰는 그룹은 없다 (spec.md FR-001 표) |
| 코드 | `codes` (그룹, 코드, 이름, 순서, 사용 여부) | 소프트 삭제. 코드를 비우면 자동 순번 (FR-006) |

## 더하는 열

| 열 | 형식 | 뜻 |
|---|---|---|
| `used_by` | `VARCHAR(200) NULL` | 이 그룹을 쓰는 곳 (예: 파티 모집의 티어). 관리자가 만든 그룹은 비어 있어도 된다 |
| `system` | `BOOLEAN NOT NULL DEFAULT FALSE` | 기능이 코드에서 읽는 그룹. 마이그레이션으로만 켠다. 켜져 있으면 지울 수 없다 (FR-008) |

## 처음 구성

코드 그룹이 없다. 그룹을 쓰는 기능이 생기면 그 기능의 스펙이 그룹과 초기 코드를 정하고, 마이그레이션으로 그룹을 시스템 그룹으로 넣고, spec.md FR-001 표에 한 줄 더한다 (FR-002).
local 프로필만 `db/localdata`의 SQL로 시험 그룹 둘(시스템 그룹 `LOCAL_GAME_GENRE`, 일반 그룹 `LOCAL_REPORT_REASON`)을 넣는다 (quickstart "화면 확인").

## 검증 규칙

- 그룹 코드: `[A-Z][A-Z0-9_]{0,49}`. 지우지 않은 그룹끼리 겹치면 안 된다. 만든 뒤 바꾸지 않는다
- 코드: 영문 대문자·숫자·밑줄. 그룹 안에서 겹치면 안 된다. 만든 뒤 바꾸지 않는다
- 그룹 이름은 필수다. 설명·쓰는 곳은 비어도 된다
- 시스템 그룹은 지울 수 없다. 그룹을 지우면 그 항목도 함께 지운다

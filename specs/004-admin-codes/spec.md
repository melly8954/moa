# Feature Specification: 공통코드 (admin-codes)

**Feature Branch**: `feat/004-admin-codes`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "관리 화면에서 바꾸는 값(분류, 상태 이름 등)을 공통코드로 두고 관리자가 공통코드에서 바꾼다. moa가 쓰는 코드 그룹을 이 스펙에 모은다."

**출처**: psw-dev-kit springboot code 헬퍼. 태그 `springboot/v0.3.1`, 화면은 `web-next/v0.3.0`.
키트 동작(코드 만들기·바꾸기, 화면용 목록, 코드 형식)은 키트 문서와 키트 수용 테스트가 기준이다 (원칙 III). 키트의 코드 지우기는 moa에서 쓰지 않는다(FR-008).
moa는 관리 화면을 왼쪽 그룹 목록 · 오른쪽 그룹 상세(항목 표) 두 칸으로 두고(2026-11-21), 그룹도 관리자가 화면에서 다루며, 그룹은 지우지 않고 사용 여부로 끄고 항목은 사용 안 함인 것만 지운다(2026-11-20, 2026-11-21). 아래 Assumptions.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자는 그룹을 고르고 그 그룹의 항목을 표에서 다룬다 (Priority: P3)

관리자는 공통코드 화면에서 코드 그룹(예: 반품 사유)을 더하고 고치고 켜고 끄며, 그룹마다 항목(예: 단순 변심, 상품 불량)을 더하고, 고치고, 켜고 끄고, 순서를 바꾼다. 그룹은 지우지 않고, 사용 안 함으로 끈 항목만 지운다.
기능이 쓰는 그룹(예: 파티의 롤 티어)은 개발자가 그 기능을 만들 때 마이그레이션으로 넣는다. 들어간 뒤에는 관리자가 만든 그룹과 똑같이 다룬다.
화면은 왼쪽에 그룹 목록, 오른쪽에 고른 그룹의 정보와 그 그룹의 항목 표다.

**Why this priority**: 지금은 moa가 쓰는 코드 그룹이 없다. 다른 기능이 코드 그룹을 쓰기 시작하면 중요해진다.

**Independent Test**: 그룹 둘(하나는 항목이 있다)로 공통코드를 열어 그룹을 더하고 끄며, 항목을 더하고, 끄고, 순서를 바꾼다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 그룹이 둘 있고 하나에 항목이 있다, **When** 관리자가 코드 관리를 연다, **Then** 왼쪽에 그룹 목록(줄마다 끌기 손잡이, 이름, 그룹 코드, 항목 수)이 순서대로 보이고 첫 그룹이 골라져 있다. 오른쪽에 그 그룹의 머리(이름, 그룹 코드, 설명, 사용, "그룹 설정")와 항목 표(끌기 손잡이·고르기·코드·이름·사용, 맨 아래 추가 줄)가 쪽 나눔 없이 보인다. 표 위 일괄 처리 줄은 고른 것이 없어도 같은 자리·높이에 있다
2. **US1-AC2** **Given** 같은 상태다, **When** 관리자가 추가 줄에 코드와 이름을 적고 엔터(또는 "추가")를 누른다, **Then** 항목이 그 그룹 맨 뒤에 그 코드로 생기고 추가 줄이 비워진다. 코드를 비우면 "코드를 입력해 주세요", 그룹 안에 이미 있는 코드면 "이미 있는 코드예요"가 코드 칸 아래에 보이고 만들지 않는다
3. **US1-AC3** **Given** 같은 상태다, **When** 관리자가 항목의 이름을 눌러 고치고 엔터를 누르거나 칸을 벗어난다, **Then** 그 이름으로 저장된다. Esc를 누르면 고치기 전으로 돌아간다. 코드는 고칠 수 없다. 줄의 사용 스위치는 누르면 바로 저장된다
4. **US1-AC4** **Given** 같은 상태다, **When** 관리자가 항목 둘을 체크하고 "사용 안 함"을 누른다, **Then** 둘이 함께 꺼지고 그 그룹의 화면용 목록(선택 상자에 쓰는 목록)에서 빠진다. 체크해도 표는 위아래로 움직이지 않는다. 다른 그룹을 고르면 체크가 풀린다
5. **US1-AC5** **Given** 같은 상태다, **When** 관리자가 항목을 끌어 표 안에서 순서를 바꾸거나, 왼쪽 목록에서 그룹을 끌어 그룹 순서를 바꾼다(또는 키보드로 같은 일을 한다), **Then** 저장되고 목록·표와 화면용 목록도 그 순서다
6. **US1-AC6** **Given** 그룹이 하나도 없다, **When** 관리자가 코드 관리를 연다, **Then** "그룹이 없어요. 그룹 추가로 첫 그룹을 만들어요"라는 안내와 "그룹 추가"가 보인다
7. **US1-AC7** **Given** 그룹이 둘 있다, **When** 관리자가 "그룹 추가"를 눌러 드로어에서 그룹 코드와 이름을 적고 저장한다, **Then** 목록 맨 뒤에 사용 중인 그룹으로 생기고 그 그룹이 골라진다. 그룹 코드 칸은 치는 동안 대문자로 바뀌고 `-`·빈칸은 `_`로 바뀌며 그 밖의 글자는 들어가지 않는다. 이미 있는 그룹 코드를 적으면 "이미 있는 그룹 코드예요"로 막힌다
8. **US1-AC8** **Given** 같은 상태다, **When** 관리자가 그룹 머리의 "그룹 설정"을 누른다, **Then** 드로어에서 이름·설명·사용 여부를 고칠 수 있고, 그룹 코드는 보기만 한다. 그룹 삭제 단추는 없다
9. **US1-AC9** **Given** 항목이 있는 그룹이 있다, **When** 관리자가 그 그룹을 "사용 안 함"으로 바꾼다, **Then** 그 그룹의 화면용 목록은 빈 목록이고, 왼쪽 목록에서 그룹 이름이 흐리게 "사용 안 함"과 함께 보이며, 항목은 그대로 남는다. 다시 켜면 켜져 있던 항목이 다시 보인다
10. **US1-AC10** **Given** 그룹 드로어에서 무언가를 고치는 중이다, **When** 저장하지 않고 드로어를 닫으려 한다, **Then** "저장하지 않고 나갈까요?"를 묻고, 나가기를 고를 때만 닫힌다. 항목 이름은 엔터나 칸을 벗어날 때 저장되므로 그룹을 바꿀 때 묻지 않는다
11. **US1-AC11** **Given** 사용 안 함 항목과 사용 중인 항목이 있다, **When** 관리자가 사용 안 함 항목 줄의 삭제를 눌러 확인한다, **Then** 그 항목이 표에서 빠지고, 같은 코드로 다시 만들 수 있다. 사용 중인 항목 줄에는 삭제 단추가 없고, API로 지우려 하면 409 `B001`이다

---

### Edge Cases

- 다른 기능이 쓰는 항목이나 그룹을 관리자가 사용 안 함으로 바꾸면: 그 기능의 선택 상자에서 빠진다. 이미 저장된 값은 그대로 남고 이름도 찾을 수 있다. 이미 저장된 값의 처리는 그 기능의 스펙이 정한다
- 잘못 만든 항목은 사용 안 함으로 끈 뒤 지운다. 지우기는 소프트 삭제라 DB에 줄이 남는다(`deleted_at`). 코드를 저장하는 기능이 저장된 값의 이름을 보일 때는 지운 항목까지 찾아야 한다(그 기능의 스펙이 정한다). 그룹은 지우지 않고 사용 안 함으로 끈다
- 항목 코드는 만들 때 반드시 적는다(대문자·숫자·밑줄, 치는 동안 걸러진다). 다른 데이터에 저장되는 값이라 뜻이 보이게 적는다(예: `FPS`, `ABUSE`). 만든 뒤에는 바꾸지 않는다
- 그룹 코드는 만들 때만 적는다(영문 대문자로 시작, 대문자·숫자·밑줄 50자 이하. 맨 앞의 숫자·밑줄은 들어가지 않는다). 만든 뒤에는 바꾸지 않는다. 항목과 기능 코드가 그룹 코드로 그룹을 찾기 때문이다
- 관리자가 만든 그룹은 그 그룹 코드를 읽는 기능이 생겨야 어느 화면의 선택 상자에 나온다. 그 전에는 공통코드 화면에만 보인다
- 기능이 읽는 그룹 코드가 DB에 없으면(시드 누락·오타): 그 기능의 화면용 목록이 "없음"(R001)으로 응답한다. 시작할 때 검사하지 않으므로, 기능을 만들 때 마이그레이션과 기능 코드의 그룹 코드를 함께 확인한다 (FR-002)
- 일괄 처리(사용·사용 안 함)는 고른 그룹 안의 항목끼리 한다. 하나라도 틀리면 아무것도 바꾸지 않는다. 그룹은 "그룹 설정"에서 하나씩 끈다
- 넓은 폭에서 그룹 목록이나 항목 표가 길면 그 칸 안에서 스크롤하고 페이지는 스크롤하지 않는다. 그룹 머리, 일괄 처리 줄과 추가 줄은 늘 보인다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: moa가 쓰는 코드 그룹은 아래 표에 모은다(MUST). 처음 배포할 때의 초기 코드는 그 그룹을 쓰는 기능의 스펙이 정한다

  | 코드 그룹 | 쓰는 기능 | 초기 코드 |
  |---|---|---|
  | `GAME` | `008-party` | `008-party` spec.md FR-002 표 |
  | `LOL_MODE`, `LOL_POSITION`, `LOL_TIER` | `008-party` | 같은 표 |
  | `OVERWATCH_MODE`, `OVERWATCH_POSITION`, `OVERWATCH_TIER` | `008-party` | 같은 표 |
  | `VALORANT_MODE`, `VALORANT_POSITION`, `VALORANT_TIER` | `008-party` | 같은 표 |
  | `PUBG_MODE`, `PUBG_TIER` | `008-party` | 같은 표 |
  | `SUPPORT_CATEGORY` | `017-customer-center` | `017-customer-center` spec.md FR-003 |

- **FR-002**: 기능이 코드 그룹을 새로 쓰면 그 기능의 스펙에 그룹(코드, 이름, 설명)과 초기 코드를 적고, 마이그레이션으로 그룹과 초기 코드를 넣고, FR-001 표에 한 줄 더한다(MUST). 관리자가 이미 만든 그룹을 쓰게 되면 마이그레이션으로 넣지 않고 그 그룹 코드를 그대로 읽으며 FR-001 표에만 더한다
- **FR-003**: 공통코드는 캐시 없이 쓴다. 백오피스 기반은 프리셋 밖 헬퍼(redis)를 쓰지 않기 때문이다
- **FR-004**: 관리자는 공통코드 화면에서 코드 그룹을 더하고, 이름·설명·사용 여부·순서를 고칠 수 있어야 한다(MUST). 그룹은 그룹 코드, 이름, 설명, 사용 여부, 순서를 가지고 모두 DB에 둔다. 그룹 코드는 만들 때만 정한다
- **FR-005**: 코드 관리 화면은 넓은 폭에서 왼쪽 그룹 목록과 오른쪽 그룹 상세의 두 칸이다(MUST). 그룹 목록은 좁게(약 1/3), 그룹 상세는 넓게 두고, 둘 다 화면 남은 높이를 채우며 각 칸 안에서 스크롤한다 (2026-11-21)
  - 그룹 목록: 순서대로 보인다(새 그룹은 맨 뒤). 줄마다 끌기 손잡이, 이름, 그룹 코드(작게), 항목 수를 보인다. 꺼진 그룹은 이름을 흐리게 하고 "사용 안 함"을 붙인다. 줄을 누르면 그 그룹을 고르고(오른쪽이 바뀐다) 고른 줄은 강조한다. 처음에는 첫 그룹을 고른다. 목록 위에 "그룹 추가"를 둔다
  - 그룹 상세 머리: 고른 그룹의 이름, 그룹 코드, 설명, 사용 여부와 "그룹 설정" 단추. 그룹 추가와 그룹 설정은 드로어(`001-admin-menus` FR-012)에서 한다. 드로어의 "사용" 토글은 이름 칸 바로 아래 오른쪽에 둔다(메뉴 관리와 같다)
  - 항목 표는 구성 목록이다(원칙 "목록"). 그룹마다 항목은 200개를 넘지 않는다. 열은 끌기 손잡이, 고르기, 코드, 이름, 사용이다. 쪽 나눔 없이 보인다
    - 이름은 눌러 표 안에서 고친다. 엔터나 칸을 벗어나면 저장하고, Esc는 고치기 전으로 돌린다. 코드는 고치지 않는다
    - 사용은 줄의 스위치로 바로 바꾼다. 꺼진 항목은 회색이다
    - 표 맨 아래 추가 줄에서 코드와 이름을 적고 엔터나 "추가"로 그 그룹 맨 뒤에 만든다. 오류는 그 칸 아래에 보인다
    - 추가 줄의 예시 글자는 그룹마다 다르다: 항목이 있으면 그룹 이름과 첫 항목("게임 장르 코드 (예: FPS)", "이름 (예: FPS)"), 항목이 없으면 그룹 이름과 적는 규칙("이벤트 분류 코드 (영문 대문자·숫자·_)")이다. 항목이 없는 표의 안내 줄은 뜻이 보이는 코드의 예를 든다("예: 게임 장르라면 FPS, RPG") (2026-11-21)
    - 사용 안 함 항목 줄 끝에는 삭제 단추를 두고, 누르면 확인을 받아 지운다. 사용 중인 항목에는 삭제 단추가 없다 (FR-008)
    - 일괄 처리 줄은 표 위에 늘 같은 자리·높이로 둔다. 고른 것이 없으면 안내와 꺼진 단추를, 고르면 고른 수와 사용·사용 안 함 단추를 보인다. 고른 그룹 안의 항목만 처리한다. 다른 그룹을 고르면 체크가 풀린다
    - 항목 순서는 표 안에서, 그룹 순서는 왼쪽 목록에서 끌기 손잡이로 바꾼다. 같은 일을 키보드로도 할 수 있어야 한다. 항목은 다른 그룹으로 옮기지 않는다(삭제·옮기기는 없다, FR-008)
  - 1024px보다 좁으면 그룹 목록이 위, 그룹 상세가 아래로 쌓인다
- **FR-006**: 항목 코드는 만들 때 반드시 적는다(MUST). 자동 순번은 없다(2026-11-21). 그룹 안에서 겹치면 만들지 않는다
- **FR-007**: 공통코드 머리 설명은 `001-admin-menus` FR-011에 따라 "선택 상자에 쓰는 값(분류, 사유 등)을 그룹마다 정해요. 사용 안 함으로 끄고, 꺼진 항목만 지울 수 있어요."로 한다(2026-11-21). 메뉴 이름은 "공통코드"다
- **FR-008**: 그룹은 지우지 않는다(MUST). 사용 안 함으로 끈다. 항목은 사용 안 함일 때만 지운다(MUST, 2026-11-21). 지우기는 확인을 받고 소프트 삭제이며, 사용 중인 항목을 지우려 하면 409 `B001`이다. 꺼진 항목은 화면용 목록에서 빠지고, 꺼진 그룹의 화면용 목록은 빈 목록이다. 관리 화면에는 꺼진 것도 모두 보이고 지운 항목은 보이지 않는다
- **FR-009**: 그룹 코드와 항목 코드 입력 칸은 치는 동안 대문자로 바꾸고, `-`와 빈칸은 `_`로 바꾸며, 대문자·숫자·밑줄 밖의 글자는 받지 않는다(MUST). 그룹 코드는 맨 앞의 숫자·밑줄도 받지 않는다. 둘 다 50자까지다

### Key Entities *(include if feature involves data)*

- **코드 그룹**: 같은 종류의 코드를 묶은 것 (예: 반품 사유). 영문 대문자·숫자·밑줄 그룹 코드, 이름, 설명, 사용 여부를 가진다. 관리자가 화면에서 다루고, 기능이 쓰는 그룹은 개발자가 마이그레이션으로 넣는다. 지우지 않는다
- **코드(항목)**: 그룹 안의 값 하나. 코드, 이름, 순서, 사용 여부를 가진다. 관리자가 다룬다. 사용 안 함일 때만 지운다(소프트 삭제)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 코드 값 하나를 바꾸면 개발자의 배포 없이 화면에 반영된다
- **SC-002**: 수용 시나리오(US1) 전부가 자동 테스트로 확인된다 (원칙 II)
- **SC-003**: 관리자는 그룹을 고른 뒤 한 표에서 그 그룹의 항목을 더하고, 이름·사용·순서를 고칠 수 있다
- **SC-004**: 관리자는 개발자 없이 새 코드 그룹을 만들 수 있고, 관리자의 어떤 조작으로도 그룹이나 사용 중인 항목이 갑자기 사라져 다른 화면이 깨지지 않는다(항목은 먼저 꺼야 지울 수 있다)

## Assumptions

- 관리자 화면(프론트)은 프론트 키트(web-next admin 프리셋)가 만드는 admin 화면을 쓴다
- 코드 로직이 값에 따라 갈리는 상태값은 공통코드가 아니라 각 기능 안에 둔다 (키트 안내: 언제 공통코드, 언제 enum)
- 화면은 메뉴 관리와 같은 트리 표로 바꾼다 (2026-11-15 결정, FR-005~FR-007, US1. 2026-11-20에 트리는 그대로 두고 드로어 대신 두 칸으로 바뀜, 아래)
  - 배경: 그룹 코드·이름·설명을 모두 손으로 입력하는 창밖에 없었다
  - 화면 시안 넷(목록 + 드로어 폼, 표 안 바로 편집, 칩 입력, 메뉴 관리와 같은 트리) 중 메뉴 관리와 조작이 같은 트리를 골랐다. 관리 화면을 같은 틀로 맞추는 방향(`001-admin-menus` "관리 화면 정리")과 맞기 때문이다
  - 버린 안: 쓰는 기능이 생길 때 다시 만들기(사용자 결정으로 지금 함께 바꾼다), 여러 줄 붙여넣기(항목이 수십 개씩 들어올 때 다시 본다)
  - 키트 code 헬퍼를 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 그룹도 관리자가 화면에서 더하고 고치고 지우며, 기능이 쓰는 그룹은 마이그레이션으로 넣은 시스템 그룹으로 잠근다 (2026-11-18 사용자 결정. 2026-11-20에 시스템 그룹과 삭제를 없애는 것으로 바뀜, 아래)
  - 배경: 처음 목표가 그룹과 항목을 모두 관리자가 화면에서 다루는 것이었다(그룹웨어·SaaS 관리 화면의 공통코드처럼). 2026-11-15에는 "그룹은 그것을 읽는 기능 코드가 있어야 쓸모가 있다"며 그룹을 코드 등록(`CodeGroupSource`)으로만 두고 `tb_code_group` 표를 지웠는데, 이 결정이 목표와 어긋나 되돌린다
  - 기능이 읽는 그룹을 관리자가 지우면 그 기능의 선택 상자가 깨지므로 시스템 그룹으로 잠근다. 그룹 코드는 모든 그룹에서 만든 뒤 바꾸지 않는다
  - 버린 안: 코드 등록 유지 + DB 표(시스템 그룹은 `CodeGroupSource`로 등록해 시작할 때 검사하고, 관리자 그룹만 DB에 두기). 그룹 코드 오타·누락을 서버 시작 때 잡지만, 그룹이 두 곳에 나뉜다. 그룹을 모두 DB 한곳에 두는 쪽을 골랐다
  - 키트 code 헬퍼는 그룹 만들기만 있고 고치기·지우기·시스템 표시는 없다. moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 공통코드를 흔한 방식으로 바꾼다: 시스템·일반 그룹 구분을 없애고, 그룹과 항목을 지우지 않고 사용 여부로만 끈다. 쓰는 곳은 설명으로 합친다 (2026-11-20 사용자 결정, FR-002·FR-004·FR-007·FR-008, US1-AC8·AC9)
  - 배경: 시스템·일반 그룹 구분은 업계에서 흔한 방식이 아니고, 일반 그룹은 개발자가 화면에 연결하기 전까지 어디에도 쓰이지 않아 구분의 쓸모가 "지울 수 있는가" 하나뿐이었다. 그룹웨어·SI 공통코드는 보통 그룹(분류)과 항목(상세 코드)을 모두 화면에서 다루고, 지우는 대신 사용 여부로 끈다. 지우지 않으면 화면이 깨지거나 예전 데이터의 이름이 사라지지 않는다
  - "쓰는 곳"은 관리자가 마음대로 적을 수 있어 실제와 어긋나도 알 수 없었다. 설명 하나로 합친다
  - 버린 안: 시스템 그룹만 잠그고 일반 그룹은 지우기(2026-11-18 안. 개발자가 시스템 표시를 빠뜨리면 지워져 화면이 깨지고, 관리자가 잠금의 뜻을 알기 어렵다), 그룹 체크로 그룹을 일괄 삭제하기(항목 고르기와 헷갈리고 되돌릴 수 없다)
  - 2026-11-18에 더한 `system` 열과 시스템 그룹 삭제 막기(B001), 그룹·항목 삭제 API를 걷어낸다. 키트 code 헬퍼는 항목 삭제가 있으므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 화면을 좌 트리 · 우 상세 두 칸으로 바꾼다 (2026-11-20 사용자 결정, FR-005·FR-009, US1-AC1·AC4·AC7·AC10)
  - 배경: 드로어는 트리를 가려 고르고 고치기를 오갈 때 불편했다. 체크하면 일괄 처리 줄이 표 위에 새로 생겨 목록이 아래로 밀렸다. 그룹 추가가 화면 오른쪽 위에 따로 떨어져 있었다. 그룹 코드는 저장할 때만 검사해 잘못 친 것을 늦게 알았다
  - 다른 관리 화면(역할·사용자)은 지금처럼 목록 + 드로어로 둔다. 같은 두 칸으로 맞출지는 나중에 따로 정한다. 메뉴 관리는 같은 날 두 칸으로 맞췄다 (`001-admin-menus` FR-010·FR-012)
  - 상태 색: 사용 초록, 사용 안 함 회색(2026-11-21, 빨강은 문제 표시에만 쓴다). 테마에 `success` 색을 더하고 공통 상태 표시(`StatusText`)의 positive를 초록으로 바꾼다. 다른 관리 화면의 상태 점도 같이 바뀐다
  - 버린 안: 3단(대분류·중분류·소분류) 칸과 표 안 바로 편집(moa는 2단이고, 표 안 편집은 입력 검사·저장하지 않은 변경 묻기·키보드 사용이 어렵다), 반반 대신 패널 너비 고정(사용자가 반반을 골랐다)
- 트리 행 전체를 눌러 상세를 열고, "사용 안 함"을 회색으로 바꾼다 (2026-11-21 사용자 결정, FR-005, US1-AC3·AC8)
  - 배경: 메뉴 관리(`001-admin-menus` FR-010)와 같은 날 같은 방식으로 맞춘다. 이름만 눌리는 것이 불편했고, 사용 안 함 색이 메뉴(회색)와 공통코드(빨강)에서 달랐다
  - 체크박스·접기 단추·끌기 손잡이는 제 일만 하고 행을 열지 않는다. 키보드는 이름 단추로 연다
  - 사용 안 함은 일부러 끈 정상 상태라 회색이다. 빨강은 문제 표시에만 쓴다
- 코드 관리를 메뉴 관리와 같은 조작으로 맞춘다 (2026-11-21 사용자 결정, FR-004·FR-005, US1-AC1·AC2·AC4~AC8)
  - 배경: 같은 두 칸 틀인데 그룹 체크의 뜻(그룹 자체 / 그 그룹 항목 전부), 일괄 처리 범위(아무 메뉴 / 한 그룹 항목만), 상위 줄 순서(끌기 / 만든 순서), 새로 만들기(트리 위 단추 하나 / 트리 안 추가 줄)가 메뉴 관리와 달라 헷갈렸다
  - 그룹 행 체크는 그 그룹 자체를 고르고, 그룹과 항목을 섞어 여러 그룹을 한꺼번에 사용·사용 안 함으로 바꾼다
  - 그룹에 순서(`sort_order`)를 더하고 그룹 행도 끌어서 순서를 바꾼다. 기존 그룹은 만든 순서로 순서를 채운다
  - 새로 만들기는 트리 위 "추가" 하나와 패널의 "소속 그룹" 칸(없음이면 그룹)으로 한다. 메뉴 관리의 "상위 메뉴" 칸과 같다
  - 삭제와 다른 그룹으로 옮기기는 두지 않는다. 지우지 않고(FR-008) 항목 코드의 뜻이 그룹에 달려 있기 때문이다
  - 접기 단추는 둔다. 그룹마다 항목이 많을 수 있다(200개까지)
  - 버린 안: 그룹 체크로 그 그룹 항목 전부 고르기를 남기기(메뉴와 뜻이 달라진다)
- 코드 관리를 그룹 목록 + 항목 표(마스터-디테일)로 바꾸고, 항목 코드를 직접 적게 한다 (2026-11-21 사용자 결정, FR-005·FR-006, US1. 같은 날의 "메뉴 관리와 같은 조작"을 갈음한다)
  - 배경: 메뉴는 상위 메뉴 아래 자리를 옮기는 계층이지만, 공통코드는 그룹(값 목록)과 그 값들이다. 항목은 다른 그룹으로 옮기지 않고, 코드 값이 다른 데이터에 저장되어 바꿀 수 없다. 트리로 두니 접기 단추와 행 누르기(상세 열기)가 섞이고, 그룹·항목을 섞은 일괄 처리처럼 쓸 일이 적은 조작이 생겼다. 업계 공통코드 화면은 그룹 목록 → 고른 그룹의 항목 표가 흔하다
  - 항목은 칸이 적어(코드·이름·순서·사용) 표 안에서 고친다. 2026-11-20에 버린 "표 안 바로 편집"의 걱정(입력 검사, 저장하지 않은 변경 묻기, 키보드)은 이름만 표 안에서 고치고(엔터·벗어나면 저장, Esc 취소), 사용은 스위치로 바로 저장하고, 코드는 추가 줄에서만 적어 줄인다
  - 그룹 추가·설정은 칸이 많고 드물게 하므로 드로어로 한다
  - 항목 코드 자동 순번(`001`, `002`, …)을 없앤다. 다른 데이터에 저장되는 값이라 뜻이 보이는 코드가 읽기 쉽다. 만들기 API는 코드가 없으면 400 `V001`이다
  - 그룹·항목을 섞은 일괄 사용 여부 API(`PUT /api/v1/admin/code-groups/enabled`)와 트리 위 "추가"·"소속 그룹" 칸을 걷어낸다. 일괄 처리는 한 그룹 안 항목만(`PUT /api/v1/admin/code-groups/{g}/codes/enabled`)이다. 그룹 순서(`sort_order`, 끌기)는 남긴다
  - 버린 안: 지금 트리를 두고 접기만 고치기(그룹과 항목은 계층이 아니라 고르기와 고치기가 계속 섞인다), 코드를 비우면 자동 순번 유지(뜻 없는 값이 데이터에 남는다)
- 사용 안 함 항목만 지우고, 추가 줄 예시 글자를 그룹마다 다르게 (2026-11-21 사용자 결정, FR-005·FR-008, US1-AC11)
  - 배경: 오타로 만든 항목이 사용 안 함으로 목록에 계속 남았다. 추가 줄의 "예: FPS"는 신고 사유 같은 다른 그룹에서도 같아 맞지 않았다
  - 켜진 항목을 바로 지우면 쓰던 선택 상자에서 값이 갑자기 빠지므로, 먼저 끄게 한다. 지우기는 소프트 삭제라 줄이 남아, 나중에 코드를 저장하는 기능이 예전 값의 이름을 찾을 수 있다
  - 빈 그룹은 보여 줄 예시 코드가 없어 적는 규칙을 보이고, 안내 줄에서 뜻 있는 코드의 예를 든다
  - 버린 안: 지금처럼 삭제 없음(잘못 만든 항목이 계속 남는다), 언제든 삭제(쓰던 선택 상자에서 값이 갑자기 빠진다). 그룹 삭제는 다루지 않는다

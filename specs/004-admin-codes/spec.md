# Feature Specification: 공통코드 (admin-codes)

**Feature Branch**: `feat/004-admin-codes`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "관리 화면에서 바꾸는 값(분류, 상태 이름 등)을 공통코드로 두고 관리자가 공통코드에서 바꾼다. moa가 쓰는 코드 그룹을 이 스펙에 모은다."

**출처**: psw-dev-kit springboot code 헬퍼. 태그 `springboot/v0.3.1`, 화면은 `web-next/v0.3.0`.
키트 동작(코드 만들기·바꾸기·지우기, 화면용 목록, 코드 형식)은 키트 문서와 키트 수용 테스트가 기준이다 (원칙 III).
moa는 관리 화면을 메뉴 관리와 같은 트리 표로 바꾸고(2026-11-15), 그룹도 관리자가 화면에서 더하고 고치고 지우게 하되 기능이 쓰는 그룹은 시스템 그룹으로 잠근다(2026-11-18). 아래 Assumptions.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자는 그룹과 항목을 트리 표에서 다룬다 (Priority: P3)

관리자는 공통코드 화면에서 코드 그룹(예: 이벤트 분류)을 더하고 고치고 지우며, 그룹마다 항목(예: 출석, 퀴즈)을 더하고, 고치고, 켜고 끄고, 순서를 바꾼다.
기능이 코드에서 읽는 그룹(예: 파티의 롤 티어)은 개발자가 마이그레이션으로 넣은 시스템 그룹이다. 관리자는 그 이름·설명과 항목을 다루지만 그룹을 지울 수는 없다.
화면은 메뉴 관리와 같은 틀이다: 그룹 아래 항목이 들여쓰기된 트리 표, 체크박스 일괄 처리, 끌어서 순서, 이름을 누르면 드로어.

**Why this priority**: 지금은 moa가 쓰는 코드 그룹이 없다. 다른 기능이 코드 그룹을 쓰기 시작하면 중요해진다. 화면 틀은 관리 화면 정리(`001-admin-menus` FR-010·FR-011)와 함께 맞춘다.

**Independent Test**: 시스템 그룹 하나와 일반 그룹 하나로 공통코드를 열어 그룹을 더하고 지우며, 항목을 더하고, 끄고, 순서를 바꾼다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 시스템 그룹 하나와 일반 그룹 하나가 있다, **When** 관리자가 공통코드를 연다, **Then** 그룹 행(이름·그룹 코드·쓰는 곳, 시스템 그룹은 잠금 표시) 아래 그 그룹의 항목이 들여쓰기된 트리 표가 쪽 나눔 없이 보이고, 머리에 "그룹 추가" 단추가 있다
2. **US1-AC2** **Given** 같은 상태다, **When** 관리자가 한 그룹의 "항목 추가"를 눌러 드로어에서 이름만 적고 저장한다, **Then** 항목이 그 그룹 맨 뒤에 생기고 코드는 그룹 안에서 겹치지 않는 순번(예: `001`)으로 자동으로 정해진다
3. **US1-AC3** **Given** 같은 상태다, **When** 관리자가 항목 이름을 누른다, **Then** 오른쪽 드로어에서 이름과 사용 여부를 고칠 수 있고, 코드는 보기만 한다
4. **US1-AC4** **Given** 같은 상태다, **When** 관리자가 항목 둘을 체크하고 "사용 안 함"을 누른다, **Then** 둘 다 꺼지고 그 그룹의 화면용 목록(선택 상자에 쓰는 목록)에서 빠진다
5. **US1-AC5** **Given** 같은 상태다, **When** 관리자가 항목을 끌어 같은 그룹 안에서 순서를 바꾼다(또는 키보드로 같은 일을 한다), **Then** 저장되고 화면용 목록도 그 순서다. 다른 그룹 아래로는 끌어 놓을 수 없다
6. **US1-AC6** **Given** 그룹이 하나도 없다, **When** 관리자가 공통코드를 연다, **Then** "그룹이 없어요. 그룹 추가로 첫 그룹을 만들어요"라는 안내와 "그룹 추가" 단추가 보인다
7. **US1-AC7** **Given** 같은 상태다(그룹 둘), **When** 관리자가 "그룹 추가"를 눌러 드로어에서 그룹 코드(`EVENT_TYPE`)와 이름을 적고 저장한다, **Then** 일반 그룹으로 트리 맨 뒤에 생긴다. 이미 있는 그룹 코드(시스템 그룹 포함)를 적으면 "이미 있는 그룹 코드예요"로 막힌다
8. **US1-AC8** **Given** 같은 상태다, **When** 관리자가 그룹 이름을 누른다, **Then** 오른쪽 드로어에서 이름·설명·쓰는 곳을 고칠 수 있고, 그룹 코드는 보기만 한다. 시스템 그룹도 같다
9. **US1-AC9** **Given** 항목이 둘 있는 일반 그룹이 있다, **When** 관리자가 그 그룹 드로어에서 "그룹 삭제"를 누르고 확인한다(확인 창에 "항목 2개도 함께 지워요"), **Then** 그룹과 항목이 함께 지워져 트리에서 빠진다
10. **US1-AC10** **Given** 시스템 그룹이 있다, **When** 관리자가 그 그룹 드로어를 연다, **Then** "그룹 삭제" 단추가 없고 "기능이 쓰는 그룹이라 지울 수 없어요"라는 안내가 보인다. API로 지우려 해도 막힌다

---

### Edge Cases

- 다른 기능이 쓰는 코드를 관리자가 사용 안 함으로 바꾸면: 그 기능의 화면 선택 목록에서 빠진다 (키트 동작). 이미 저장된 값의 처리는 그 기능의 스펙이 정한다
- 항목을 지우면: 소프트 삭제한다 (키트 동작). 지운 항목의 코드는 다시 자동 순번으로 쓰지 않는다
- 관리자가 코드를 직접 정하고 싶으면: 드로어에서 만들 때만 코드를 적을 수 있다(영문 대문자·숫자·밑줄). 비우면 자동이다. 만든 뒤에는 바꾸지 않는다
- 일괄 처리(사용·사용 안 함·삭제)는 하나라도 틀리면 아무것도 바꾸지 않는다
- 그룹 코드는 만들 때만 적는다(영문 대문자로 시작, 대문자·숫자·밑줄 50자 이하). 만든 뒤에는 바꾸지 않는다. 항목이 그룹 코드로 그룹을 가리키고, 기능 코드도 그룹 코드로 읽기 때문이다
- 관리자가 만든 그룹은 그 그룹 코드를 읽는 기능이 생겨야 어느 화면의 선택 상자에 나온다. 그 전에는 공통코드 화면에만 보인다
- 시스템 여부는 화면에서 켜거나 끌 수 없다. 개발자가 마이그레이션으로만 정한다 (FR-008)
- 그룹을 지우면: 그룹과 항목을 함께 소프트 삭제한다. 같은 그룹 코드로 다시 만들 수 있고, 그때 항목 자동 순번은 지운 항목의 순번 다음부터다 (FR-006)
- 기능이 읽는 그룹 코드가 DB에 없으면(시드 누락·오타): 그 기능의 화면용 목록이 "없음"(R001)으로 응답한다. 시작할 때 검사하지 않으므로, 기능을 만들 때 마이그레이션과 기능 코드의 그룹 코드를 함께 확인한다 (FR-002)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: moa가 쓰는 코드 그룹은 아래 표에 모은다(MUST). 처음 배포할 때의 초기 코드는 그 그룹을 쓰는 기능의 스펙이 정한다

  | 코드 그룹 | 쓰는 기능 | 초기 코드 |
  |---|---|---|
  | `GAME` | `008-party` | `008-party` spec.md FR-002 표 |
  | `LOL_MODE`, `LOL_POSITION`, `LOL_TIER` | `008-party` | 같은 표 |
  | `OVERWATCH_MODE`, `OVERWATCH_POSITION`, `OVERWATCH_TIER` | `008-party` | 같은 표 |
  | `VALORANT_MODE`, `VALORANT_POSITION`, `VALORANT_TIER` | `008-party` | 같은 표 |
  | `PUBG_MODE`, `PUBG_TIER` | `008-party` | 같은 표 |

- **FR-002**: 기능이 코드 그룹을 새로 쓰면 그 기능의 스펙에 그룹(코드, 이름, 설명, 쓰는 곳)과 초기 코드를 적고, 마이그레이션으로 그룹을 시스템 그룹(FR-008)으로 넣고, FR-001 표에 한 줄 더한다(MUST)
- **FR-003**: 공통코드는 캐시 없이 쓴다. 백오피스 기반은 프리셋 밖 헬퍼(redis)를 쓰지 않기 때문이다
- **FR-004**: 관리자는 공통코드 화면에서 코드 그룹을 더하고, 고치고, 지울 수 있어야 한다(MUST). 그룹은 그룹 코드, 이름, 설명, 쓰는 곳을 가지고 모두 DB에 둔다. 그룹 코드는 만들 때만 정하고, 시스템 그룹은 지울 수 없다 (FR-008)
- **FR-005**: 공통코드 화면은 그룹 > 항목의 트리 표 하나다(MUST). 메뉴 관리(`001-admin-menus` FR-010)와 같은 틀이다
  - 구성 목록이다(원칙 "목록"). 그룹마다 항목은 200개를 넘지 않는다. 전체를 쪽 나눔 없이 보이고 화면 안에서 스크롤한다. 그룹 행은 접고 펼 수 있다
  - 그룹과 항목은 이름을 눌러 오른쪽 드로어에서 고친다. 새 그룹은 머리의 "그룹 추가"로, 새 항목은 그룹 아래 "항목 추가"로 같은 드로어에서 만든다. 행마다 단추를 두지 않는다
  - 그룹은 만든 순서로 보인다. 그룹 삭제는 그룹 드로어에서 하고, 함께 지워질 항목 수를 보여 확인을 받는다
  - 체크박스로 여러 항목을 골라 사용·사용 안 함·삭제를 한꺼번에 한다. 삭제는 확인을 받는다. 그룹 행은 체크할 수 없다
  - 순서는 그룹 안에서 끌기 손잡이로 바꾼다. 같은 일을 키보드로도 할 수 있어야 한다. 다른 그룹으로는 옮기지 않는다
- **FR-006**: 항목 코드를 비우고 만들면 그룹 안에서 겹치지 않는 세 자리 순번(`001`, `002`, …, 999를 넘으면 자릿수를 늘린다)으로 정한다(MUST). 지운 항목의 순번은 다시 쓰지 않는다
- **FR-007**: 공통코드 머리 설명은 `001-admin-menus` FR-011에 따라 "선택 상자에 쓰는 값(분류, 사유 등)을 그룹마다 정해요. 잠금 표시가 있는 그룹은 기능이 쓰고 있어 지울 수 없어요."로 한다. 메뉴 이름은 "공통코드"다
- **FR-008**: 기능이 코드에서 그룹 코드로 읽는 그룹은 시스템 그룹이어야 한다(MUST). 시스템 여부는 개발자가 마이그레이션으로만 정하고 화면과 API로는 바꾸지 않는다. 시스템 그룹은 지울 수 없고(API는 `B001`), 이름·설명·쓰는 곳과 항목은 관리자가 다룬다

### Key Entities *(include if feature involves data)*

- **코드 그룹**: 같은 종류의 코드를 묶은 것 (예: 신고 사유). 영문 대문자·숫자·밑줄 그룹 코드를 가진다. 이름, 설명, 쓰는 곳, 시스템 여부를 가진다. 관리자가 화면에서 다루고, 시스템 그룹은 개발자가 마이그레이션으로 넣는다
- **코드(항목)**: 그룹 안의 값 하나. 코드, 이름, 순서, 사용 여부를 가진다. 관리자가 다룬다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 코드 값 하나를 바꾸면 개발자의 배포 없이 화면에 반영된다
- **SC-002**: 수용 시나리오(US1) 전부가 자동 테스트로 확인된다 (원칙 II)
- **SC-003**: 관리자는 코드 값을 정하지 않고 이름만 적어 항목을 더할 수 있다
- **SC-004**: 관리자는 개발자 없이 새 코드 그룹을 만들 수 있고, 기능이 쓰는 그룹은 화면에서 지워지지 않는다

## Assumptions

- 관리자 화면(프론트)은 프론트 키트(web-next admin 프리셋)가 만드는 admin 화면을 쓴다
- 코드 로직이 값에 따라 갈리는 상태값은 공통코드가 아니라 각 기능 안에 둔다 (키트 안내: 언제 공통코드, 언제 enum)
- 화면은 메뉴 관리와 같은 트리 표로 바꾼다 (2026-11-15 결정, FR-005~FR-007, US1)
  - 배경: 그룹 코드·이름·설명을 모두 손으로 입력하는 창밖에 없었다
  - 화면 시안 넷(목록 + 드로어 폼, 표 안 바로 편집, 칩 입력, 메뉴 관리와 같은 트리) 중 메뉴 관리와 조작이 같은 트리를 골랐다. 관리 화면을 같은 틀로 맞추는 방향(`001-admin-menus` "관리 화면 정리")과 맞기 때문이다
  - 버린 안: 쓰는 기능이 생길 때 다시 만들기(사용자 결정으로 지금 함께 바꾼다), 여러 줄 붙여넣기(항목이 수십 개씩 들어올 때 다시 본다)
  - 키트 code 헬퍼를 고치므로 moa에서 먼저 하고 키트로 옮긴다 (원칙 III)
- 그룹도 관리자가 화면에서 더하고 고치고 지우며, 기능이 쓰는 그룹은 마이그레이션으로 넣은 시스템 그룹으로 잠근다 (2026-11-18 사용자 결정, FR-002·FR-004·FR-008, US1-AC1·AC6~AC10)
  - 배경: 처음 목표가 그룹과 항목을 모두 관리자가 화면에서 다루는 것이었다(그룹웨어·SaaS 관리 화면의 공통코드처럼). 2026-11-15에는 "그룹은 그것을 읽는 기능 코드가 있어야 쓸모가 있다"며 그룹을 코드 등록(`CodeGroupSource`)으로만 두고 `code_groups` 표를 지웠는데, 이 결정이 목표와 어긋나 되돌린다
  - 기능이 읽는 그룹을 관리자가 지우면 그 기능의 선택 상자가 깨지므로 시스템 그룹으로 잠근다. 그룹 코드는 모든 그룹에서 만든 뒤 바꾸지 않는다
  - 버린 안: 코드 등록 유지 + DB 표(시스템 그룹은 `CodeGroupSource`로 등록해 시작할 때 검사하고, 관리자 그룹만 DB에 두기). 그룹 코드 오타·누락을 서버 시작 때 잡지만, 그룹이 두 곳에 나뉜다. 그룹을 모두 DB 한곳에 두는 쪽을 골랐다
  - 키트 code 헬퍼는 그룹 만들기만 있고 고치기·지우기·시스템 표시는 없다. moa에서 먼저 하고 키트로 옮긴다 (원칙 III)

# Quickstart: 업무 목록의 쪽 이동·빈 결과

기대 결과의 기준은 [contracts/list-pager.md](./contracts/list-pager.md)다.

## 자동 검증

`frontend/`에서 실행한다.

```bash
npm run check
```

화면 검사는 로컬에서 돌리지 않고 PR CI(`frontend-ci` e2e)로 본다. 대상은 `e2e/list.spec.ts`와, 영향이 없는지 볼 `login-history`·`user-admin`·`notices` spec이다.

## 손으로 확인

`npm run dev`를 띄우고, 관리 화면은 백엔드도 함께 띄운다 (local 프로필, 시험 계정 `admin`).

1. **`/dev/list`** (예시 87건, 백엔드 필요 없음)
   - 처음 열면 10줄이 보이고 쪽 크기는 "10개씩"이다. 아래 줄은 건수 | 쪽 이동 | 쪽 크기 순서이고, 쪽 이동이 가운데에 있다 (US1-AC1, US3-AC1)
   - 6쪽에서 «를 누르면 1쪽, »를 누르면 9쪽이다. 양 끝에서 버튼이 비활성이 된다 (US1-AC2·AC3)
   - 9쪽(7건)에서 쪽 이동 줄의 위치가 1쪽과 같다 (US2-AC2)
   - 결과가 없는 이름으로 조회하면 표 높이가 그대로이고 "조건 초기화"가 보인다. 누르면 87건으로 돌아간다 (US2-AC1·AC5)
   - 주소를 `?page=99`로 열면 9쪽이 열린다. 뒤로 가기를 해도 `page=99`로 돌아가지 않는다 (US3-AC3)
   - 이름에 `error`를 넣고 조회하면 오류 안내가 같은 표 높이 안에 보이고 건수는 숨는다 (US2-AC3)
   - 행 선택 칸이 있는 표라서 선택이 있어도 같은 규칙인지 본다
   - 브라우저 폭을 좁히면 쪽 이동이 위 줄, 건수·쪽 크기가 아래 줄로 나뉜다 (US1-AC5)
2. **`/admin/login-histories`**: 조건 없이 결과가 없는 상태에서는 "조건 초기화"가 없다 (US2-AC6). 결과가 한 쪽이면 이동 버튼이 모두 비활성이다 (US1-AC4)
3. **`/admin/users`, `/admin/notices`**: 화면 코드를 고치지 않았는데도 10건씩, 새 아래 줄과 표 높이가 적용된다 (FR-009)
4. **`/admin/login-histories`, `/admin/purge-logs`** 기간 조건 (US4)
   - 날짜 칸 앞에 오늘·7일·이번 달·3개월·1년 단추가 있고, 단추 줄과 날짜 칸 높이가 같다. 달력 창 안에는 빠른 선택이 없다 (US4-AC1)
   - 7일을 누르면 오늘까지 7일이 채워지고 7일이 골라진 모양이며 바로 조회된다 (US4-AC2)
   - 시작일을 직접 바꾸면 단추 표시가 풀린다 (US4-AC4). 폭을 좁히면 단추 줄이 날짜 칸 위로 간다 (US4-AC5)
5. **`/admin/login-histories`** 바로 조회 (US5)
   - 검색 영역에 조회 단추가 없고 초기화만 있다 (US5-AC1)
   - 결과 "실패"를 누르면 바로 실패만 보이고 주소에 `success=false`가 붙는다 (US5-AC2)
   - 아이디에 글자를 치고 잠시 멈추면 조회된다. 엔터를 누르면 바로 조회된다 (US5-AC4). 뒤로 가기를 하면 글자마다가 아니라 그 전 조건으로 돌아간다 (US5-AC5)
